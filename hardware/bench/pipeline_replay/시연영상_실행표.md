## 0. 무엇이 진짜인가 (촬영 전에 반드시 알 것)

영상에 나가는 화살표 네 개 중 **세 개는 실물이고 하나는 아직 아니다.** 여기를
헷갈린 채 찍으면 나중에 질문 하나에 무너진다.

| 구간 | 상태 | 영상에서 어떻게 말할 것인가 |
|---|---|---|
| 센서 → 라즈베리파이 | ✅ **진짜** | INA226·DS18B20 ×2·MLX90614 ×2 를 1초 주기로 실측 |
| 파이 → Kafka | ✅ **진짜** | 파이가 직접 `battery-data` 토픽에 produce 한다 |
| Kafka → PostgreSQL | ✅ **진짜** | 컨슈머가 적재. 누적 176,533건이 이미 들어 있다 |
| PostgreSQL → 화면 | ✅ **진짜** (`live_view.py`) | **읽기 전용 라이브 뷰.** SELECT 만 한다 |
| PostgreSQL → **팀 React 대시보드** | ❌ **아직 아니다** | `backend/src/store/postgres.ts` 미구현. `DATA_MODE=postgres` 는 의도된 `503` fail-closed다 |

> **팀 대시보드(`localhost:3005`)를 영상에 넣으려면 "UI 최종본, 데이터 연동 진행 중"
> 이라고 말하고 넘어간다.** 지금 그 화면의 숫자는 `store/memory.ts` 의 데모 픽스처다.
> 실연결은 두 스키마(`runs`/`battery_logs` ↔ `telemetry_metric`/`batteries`)를 잇는
> 별도 작업이고, 오늘 일정과 맞지 않는다.

### ⚠️ 전압 2.5V 는 측정값이 아니다

전력 경로에 아무것도 안 물려 있으면 INA226 아래 노드가 떠서 **2.5V 부근**을 가리킨다
(CLAUDE.md 2026-08-27 「떠 있는 노드」). 라이브 뷰에도 그 설명을 적어 뒀다.

**그래서 이번 영상의 라이브 신호는 「온도」다.** 부하가 없어도 진짜로 움직이는 값은
온도뿐이다 — **IR 센서 앞에 손을 대면 주황선이 즉시 올라간다.** 이게 시연의 핵심 장면이다.

전압·전류까지 실측값으로 찍고 싶으면 실제 방전이 필요하다 → 맨 아래 「선택: 짧은 방전」.

### ⚠️ IP 두 개를 반드시 맞출 것

```
PC (Kafka 브로커)   <LAN_IP>      ← 집 WiFi 기준
라즈베리파이         <LAN_IP>
```

**PC 의 IP 가 바뀌면 두 곳을 고쳐야 한다** — `compose.yaml` 의

핫스팟으로 옮기면 **둘 다 바뀐다** — 아래 「1-b 동방」의 `switch_network.ps1` 이 그걸 자동으로 해준다.

### ⛔ PC 쪽 스크립트도 `localhost` 대신 `<LAN_IP>` 을 쓴다

광고 주소를 LAN IP 로 바꾼 뒤로, `--broker localhost:9092` 로 부르면 컨슈머가
부트스트랩 연결을 닫고 재접속하다가 **Python 3.14 셀렉터 버그로 죽는다**
(`ValueError: Invalid file descriptor: -1`). 부트스트랩을 광고 주소와 같게 주면 안 난다.

```
❌  python consumer_v2.py --broker localhost:9092 ...
✅  python consumer_v2.py --broker <LAN_IP>:9092 ...
```

## 1-b. 동방(핫스팟)에서 찍는다면

**인터넷은 필요 없다.** 파이·PC·Kafka·DB 가 전부 같은 망 안에서만 통신하므로
핫스팟이면 충분하다. 다만 **IP 가 전부 바뀌므로** 옮긴 뒤 이것 하나만 돌리면 된다:

```bash
cd "C:\Users\<USER>\Desktop\라즈베리파이5테스트\pipeline_replay"
powershell -ExecutionPolicy Bypass -File .\switch_network.ps1
```

### ⚠️ IP 가 바뀌면 SSH 호스트키를 새로 받아야 한다

파이의 IP 가 바뀌면 `ssh` 가 `Host key verification failed` 를 낸다 —
새 주소라서 알려진 호스트 목록에 없기 때문이다. 한 번만 이렇게 붙으면 등록된다:

```bash
ssh -o StrictHostKeyChecking=accept-new <USER>@<파이IP>
```

`accept-new` 는 **처음 보는 키만 받고, 바뀌었으면 여전히 거부한다** —
`StrictHostKeyChecking=no` 보다 안전하다.

이 스크립트가 ① PC 의 새 IP 를 찾고 ② `compose.yaml` 광고 주소를 고치고
③ Kafka 를 재기동하고 ④ 파이를 찾아 ⑤ **붙여 넣을 명령 세 줄을 출력**한다.
출력된 명령을 그대로 쓰면 STEP 2~4 가 된다.

### ✅ 파이 WiFi — 확인 완료

**파이는 헤드리스다.** 동방 망에 못 붙으면 화면도 키보드도 없어 되살릴 방법이 없다.
다행히 **핫스팟 `Amsterdam16` 이 이미 등록돼 있고 자동접속이 켜져 있다**
(2026-09-04 확인):

| SSID | 자동접속 | 우선순위 | 동작 |
|---|---|---|---|
| `iptime_samsung7` | yes | **10** | 집. 잡히면 이걸 먼저 쓴다 |
| `Amsterdam16` | yes | 0 | **집이 안 잡히면 자동으로 여기로 넘어간다** |

우선순위가 이렇게 잡혀 있는 것이 정확히 원하는 동작이다 — 집에서는 집 WiFi,
동방에서는 핫스팟. **손댈 것이 없다.**

> **그래도 나가기 전에 한 번 시험해 두면 마음이 편하다.** 핫스팟을 켠 뒤 파이에서
> 집 연결을 잠깐 내리면 `Amsterdam16` 으로 넘어가는지 볼 수 있다 (`sudo` 필요):
>
> ```bash
> sudo nmcli connection down netplan-wlan0-iptime_samsung7
> ```
>
> PC 도 핫스팟에 붙인 뒤 `Resolve-DnsName <HOST>` 로 찾아지면 성공이다.
> 되돌리려면 `sudo nmcli connection up netplan-wlan0-iptime_samsung7`,
> 최악의 경우 파이를 재부팅하면 자동으로 집 WiFi 로 돌아온다.

### 핫스팟 쪽 설정 두 가지

| 항목 | 이유 |
|---|---|
| **기기 간 연결 허용** (AP isolation 끄기) | 켜져 있으면 PC 와 파이가 같은 핫스팟에 붙어도 서로 못 본다. 삼성폰은 「모바일 핫스팟 → 고급」 |
| **절전으로 핫스팟이 꺼지지 않게** | 접속 기기가 없으면 자동으로 꺼지는 설정이 있다. 촬영 중 끊기면 파이가 사라진다 |

> **방화벽은 이미 통과한다.** `Docker Desktop Backend` 인바운드 규칙이 **Public**
> 프로필에 걸려 있고, 집 WiFi 도 이미 Public 으로 분류돼 있는데 파이가 정상 접속했다.
> 핫스팟도 Public 이라 동일하게 동작한다.

> **mDNS 도 된다.** 파이의 `avahi-daemon` 이 active 라 핫스팟에서도
> `<HOST>` 로 찾을 수 있다 — `switch_network.ps1` 이 이걸 먼저 시도한다.

### STEP 5 — 🔥 핵심 장면: 손으로 온도를 만든다

**MLX90614 센서 앞 2~3cm 에 손바닥을 댄다.** 5~10초면 충분하다.

세 창에서 동시에 일어나는 일:

| 창 | 보이는 것 |
|---|---|
| 파이 터미널 | `IR 27.55/27.73` → `IR 33.2/28.1` 로 튄다 |
| 컨슈머 터미널 | 적재 건수가 계속 올라간다 |
| 라이브 뷰 | **주황선만 솟고 회색(실온)은 그대로다.** 두 선이 벌어지는 폭이 곰 자체 발열이다 |

손을 떼면 다시 내려온다. **이 한 장면이 "센서에서 화면까지 진짜로 이어져 있다" 를
가장 짧게 증명한다.**

> 타일 아래 `0x5A 33.20℃ · 0x5B 28.10℃ → max 를 채택` 문구를 짚어주면
> **`temperature = max(5a,5b)` 규칙**(계약 §2)까지 한 컷에 설명된다.
> 한쪽 IR 은 run 마다 겨냥이 빗나가 실온을 읽기 때문에 평균을 쓰면 신호가 죽는다.

`backend/.env` 가 없으면 스크립트가 안내를 띄우고 멈춘다 — `.env.example` 을 복사하고

## 4. 선택: 짧은 방전으로 전압·전류까지 실측하기

온도만으로 부족하고 **5V · −0.5A · 2.5W 같은 진짜 전기값**을 찍고 싶다면 실제 부하가
필요하다. CC 0.5A 로 3분이면 충분하다.

⛔ **그 전에 2026-08-27 소손 이후 복구 점검을 통과해야 한다.** 건너뛰지 말 것:

1. 확장보드 `5V0`↔`GND` · `3V3`↔`GND` 저항으로 단락 확인
2. `python3 ~/i2cstress.py 30` — 6채널 실패 0
3. 릴레이 4채널 딸깍 확인 (LED 만으로는 판정 불가 — 코일이 당기는지 봐야 한다)
4. **팩 뽑은 채** `COM`↔`NO` 도통 (OFF 열림 / ON 삑)
5. `tempguard.py` 무장 후에만 통전

```bash
nohup python3 -u ~/tempguard.py --ir-stop 60 --ds-stop 50 --rise 10 --window 60 --rise-gate 40 --log ~/guard.log </dev/null > ~/guard.out 2>&1 &
```

그리고 **BW150 출력을 먼저 켜고 → 팩을 깨우고 → 마지막에 CH3 를 닫는다**
(핵심 발견 12 — 순서를 어기면 무부하 30~40초에 팩이 잠든다).

> 이건 오늘 일정 밖이면 그냥 넘어가도 된다. 온도 시연만으로도 파이프라인은 충분히 증명된다.

## 5. 문제가 생기면

| 증상 | 원인 | 조치 |
|---|---|---|
| 컨슈머가 `Invalid file descriptor: -1` 로 즉사 | `--broker localhost:9092` 를 썼다 | `<LAN_IP>:9092` 로 바꾼다 |
| 파이가 Kafka 에 못 붙는다 | PC IP 가 바뀌었다 / 방화벽 | `ipconfig` 확인 → `compose.yaml` 광고 주소 수정 → `docker compose up -d` |
| 화면 숫자가 안 오른다 | `--batch` 가 기본 500 이다 | `--batch 1` 로 재시작 |
| 파이 표본이 전부 막힌다 | `runs` 행이 없다 | 컨슈머에 `--live-run LIVE_DEMO` |
| DS 가 `<< NO READ` | 배선 흔들림 (`t=85000` = 전원 미도달) | 듀폰선 재체결 |
| 파이를 못 찾는다 | IP 변경 | `Resolve-DnsName <HOST>` 또는 `방전분석_공용/find_pi.ps1` |

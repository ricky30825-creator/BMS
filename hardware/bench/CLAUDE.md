## 라즈베리파이 접속

```bash
ssh <USER>@<IP>
```

- 호스트명 `<HOST>`, 사용자 `<USER>`, Debian 13 (Trixie) **Lite**
- ⚠️ **본체는 Raspberry Pi 4 Model B Rev 1.5다** (2026-08-20 교체). Pi 5는 고장 — 아래 참조
- **SSH 공개키 등록 완료** — `BatchMode=yes`로 비밀번호 없이 접속 가능
- **`sudo`는 비밀번호 필요** → 시스템 설정 변경은 사용자에게 명령어를 전달할 것
- **`<HOST>`(mDNS)로 찾는 게 가장 빠르다** — `avahi-daemon`이 깔려 있다
  ```powershell
  Resolve-DnsName <HOST>
  ```
- 집 WiFi `iptime_samsung7`(2.4GHz) 등록됨. 유선도 DHCP 자동
- IP 이력: `<LAN_IP>` → `<LAN_IP>` → `<LAN_IP>`(핫스팟) → **`<LAN_IP>`(집 WiFi)**
- mDNS가 안 되면 서브넷을 ping 스윕하고 MAC이 **`d8:3a:dd`**(라즈베리파이 OUI)인 호스트를 찾는다
- **`방전분석_공용/find_pi.ps1`이 이 순서를 자동으로 한다** (mDNS → ARP OUI → 핑 스윕 → SSH 확인).
  찾으면 `deploy_pi.ps1 -IP <주소>`로 로거·점검 스크립트 6개를 한 번에 배포한다
- ⚠️ **파이는 `iptime_samsung7`(집)과 핫스팟만 안다.** PC가 다른 WiFi(예: 학교·카페)에 붙어 있으면
  스윕해도 안 나온다 — 파이가 그 망에 없는 것이다. `netsh wlan show interfaces`로 PC 쪽 SSID부터 확인할 것

### ⚠️ Pi 5 고장 (2026-08-20)

전원을 넣으면 **빨간 LED에서 멈추고 초록으로 넘어가지 않는다.** 아래를 전부 배제했다:

| 시도 | 결과 |
|---|---|
| SD 카드 2장 (서로 다른 것) | 둘 다 빨강 |
| 확장보드 리본·USB·랜선 전부 제거 | 빨강 |
| 27W 정품 전원 | 빨강 |
| 그 SD 카드를 Pi 4에 | **정상 부팅** |

→ **부트로더 EEPROM 손상**이 유력. 복구 방법: Imager의 `Misc utility images` → `Bootloader (Pi 5 family)` → `SD Card Boot`을 여분 SD에 굽고 Pi 5에 넣어 부팅. 초록이 빠르게 깜빡이면 성공.
리본을 뽑다가 **GPIO 핀 일부가 휘었으니** 되살릴 때 인접 핀 단락부터 확인할 것.

### Lite 이미지라 없는 것

- `i2c-tools`·`smbus2` **미설치**. 넣으려면 `sudo apt install -y i2c-tools python3-smbus2`
- **점검 스크립트는 순수 Python(ctypes+fcntl)이라 아무것도 없이 돈다** — 이 방식을 유지할 것
- 가이드의 STEP 18·19·27-1 스크립트만 `smbus2`가 필요하다

### 이미 설정된 것

`/boot/firmware/config.txt` 하단:
```
dtparam=i2c_arm=on
dtoverlay=w1-gpio,gpiopin=4
gpio=5,6,13,19=op,dh      # 릴레이 안전 — 부팅 시 출력·High 고정
```

- `i2c-tools` **설치됨** (4.4-2). 단 `/usr/sbin/`에 있고 SSH 비로그인 셸의 PATH에 없으므로
  **전체 경로로 부른다**: `/usr/sbin/i2cdetect`
- **`sudo` 불필요** — `<USER>`가 `i2c`·`gpio`·`spi` 그룹에 들어 있다. `smbus2 0.4.3`도 설치됨
- 순수 Python(ctypes+fcntl) I2C 접근도 그대로 된다 — 스캔 방식을 바꿔가며 확인할 때 유용
- 파이에 있는 스크립트: `~/thermal_log.py`, `~/thermal_log_alarm.py`, `~/watch_temp.py`

## 센서 구성 (ID를 반드시 지킬 것)

| 채널 | ID / 주소 | 역할 |
|---|---|---|
| DS18B20 | **`28-0625650a2c2c`** | **셀·케이스 표면** — 경보와 온도 판정의 기준 (2026-08-26 정정) |
| DS18B20 | **`28-062565206490`** | **실온** — 공기 중, 배터리에서 10cm 이상 (2026-08-26 정정) |
| MLX90614 | `0x5B` | 비접촉 대상온도 — 모드 2에서 **USB 출력 포트쪽** |
| MLX90614 | `0x5A` | 비접촉 대상온도 — 모드 2에서 **케이스 중앙** (2026-08-19 연결 완료) |
| INA226 | `0x40` | 전압·전류 — **R010 투입 완료·진품 확인** (MFG `0x5449` / DIE `0x2260`) |
| ADS1115 | `0x48` | 압력(FSR) — 이번 주 미사용 |

**2026-08-19 실측 확인**: 6채널 전부 정상. MLX 두 개 모두 `Config = 0xB7F4`(`IIR=100`·`FIR=111`)로
**STEP 19가 이미 적용된 상태**이며 두 값이 동일하다 — 다시 쓸 필요 없다(EEPROM은 수명이 있다).
방사율은 두 개 다 `1.000`(공장값)이라 **검정테이프 0.95 프로토콜과 어긋난다**. 두 센서가 같은 값이라
상호 비교에는 지장이 없고, 절대값이 필요해지면 그때 정한다.

> ⚠️ **2026-08-26 — 두 DS18B20의 배치가 문서와 반대였다.** 9개 run 전부에서 **부하를 끊었을 때
> 식는 쪽이 `28-0625650a2c2c`**였다(r3 −7.90 / r6 −7.79 / c1 −1.27 ℃). 식는 쪽이 케이스에 붙은
> 것이므로 `2c2c`가 표면, `6490`이 공중이다. 예외가 한 건도 없었다 = 처음부터 그랬다.
>
> **프로브는 그대로 두고 스크립트 상수를 맞바꿨다** — 과거 9 run 과 배치 일관성을 지키기 위해서다.
> 고친 파일: `thermal_log_alarm.py` · `thermal_log_bulk.py` · `tempguard.py` · `preflight.py` ·
> `sensorwatch.py` · `build_run_report.py`.
>
> **CSV 열 의미가 이 시점에서 바뀐다.** `c6` 이전 파일은 `ds18b20_c`=공중 / `ds_ambient_c`=표면,
> `c6` 이후는 문서대로다. **과거 run 의 `delta_c`는 부호가 반대**이니 그대로 읽지 말 것.
> (`delta_c`는 이미 실온 드리프트 때문에 폐기한 지표라 분석 영향은 없다. 문제는 **경보**였다 —
> 중단온도 판정을 공중에 뜬 프로브로 하고 있었으니 표면 발열을 못 봤다. IR 기반 `tempguard`가
> 실제 보호를 맡고 있었던 것이 다행이다.)

`thermal_log_alarm.py` 상단의 `CELL_ID` / `AMBIENT_ID` 상수가 위 ID를 참조한다. 센서를 물리적으로
바꿔 달면 그 두 줄만 고치면 된다.

### DS18B20 읽기 원리

커널의 1-Wire 드라이버가 센서를 파일로 노출한다. 라이브러리 불필요.

```
cat /sys/bus/w1/devices/28-XXXXXXXXXXXX/w1_slave
→ 96 01 4b 46 7f ff 0c 10 a0 : crc=a0 YES     ← CRC 결과
  96 01 4b 46 7f ff 0c 10 a0 t=25375          ← 온도 × 1000
```

- 폴더명이 `28-`로 시작해야 DS18B20 (패밀리 코드 0x28). `00-`은 노이즈로 읽힌 유령 장치
- **`t=85000`(85.0℃)은 실제 온도가 아니라 전원투입 초기값** = 변환 실패 = VCC가 안 들어옴
  - 이 증상이 하루에 세 번 재발했다. 배선이 흔들리면 바로 나타난다

### MLX90614 읽기 원리

- 레지스터 `0x07`=TOBJ1(대상), `0x06`=TA(주변). 변환식 `raw × 0.02 − 273.15`
- 최상위 비트(`0x8000`)가 서면 에러
- **단순 I2C 스캔에는 안 잡힌다** — 레지스터를 쓴 뒤 repeated START로 읽어야 응답. 실제 읽기로 판정할 것
- **`i2cdetect`는 기본 모드로 MLX를 절대 못 본다.** `0x50~0x5F` 구간에서 EEPROM 보호를 위해
  "맨 읽기(read byte)"를 쓰는데 MLX가 그걸 NACK하기 때문이다. **`-q`(quick write)를 붙여야 보인다**:
  ```bash
  /usr/sbin/i2cdetect -y -q 1     # 40 48 5a 5b 가 보여야 정상
  ```
  가이드 STEP 17의 "`5a`가 보여야 한다"는 이 환경에서 **기본 모드로는 성립하지 않는다**
- 주소를 잃어버렸으면 **`0x00`으로 접근**하면 MLX가 자기 주소와 무관하게 응답한다.
  `0x00`조차 무응답이면 주소 문제가 아니라 **전원 또는 배선 문제**로 확정된다

## 스크립트

### 파이에서 실행

```bash
# 경보판 로거 (권장) — 간격(초) 파일 중단온도(℃)
python3 ~/thermal_log_alarm.py 1 ~/PB20000_r1_2A_temp.csv 60
```

- 3단 경보: 주의(중단온도−5℃) / 중단온도 도달 / 급상승(1분 5℃)
- 시작 시 화면에 센서 2개가 `OK`로 잡혔는지 표시된다 — **매번 확인하고 시작할 것**
- CSV 열: `timestamp, elapsed_s, ds18b20_c(셀), ds_ambient_c, delta_c, mlx5a_*, mlx5b_*`
- `delta_c`(셀−실온)가 핵심 — run마다 실온이 달라도 직접 비교가 된다

> ⚠️ **`delta_c`는 실온이 안정할 때만 자체 발열을 뜻한다** (2026-08-21 확인). run **도중에** 실온이
> 움직이면 배터리가 열용량 때문에 늦게 따라가서, 발열이 그대로여도 `delta_c`가 줄거나 음수가 된다.
>
> | 시각 | 셀 | 실온 | `delta_c` |
> |---|---|---|---|
> | 00:00 | 28.75℃ | 27.94℃ | **+0.81** |
> | 08:34 | 30.06℃ | 30.19℃ | **−0.13** |
>
> 방이 2.25℃ 오르는 동안 배터리는 1.31℃만 올랐다. 부하는 5W로 **내내 동일**했다.
> **`delta_c`가 음수라고 발열이 멈춘 게 아니다** — 실제로 이렇게 오독한 적이 있다.
> 여름 13시간 run은 밤낮 온도차를 반드시 겪으므로 항상 이 함정이 있다.
>
> **대안**: ① **냉각 꼬리 진폭** — 부하 차단 직전 60초 − 꼬리 말미 5분. 기준선을 안 쓰므로
> 실온 드리프트가 상쇄된다. **현재 1차 발열 지표다**(핵심 발견 9). ② 실온 변화율이 작은 구간만 비교.
> ③ **에어컨으로 실온 고정** — 8 run 중 4개가 실온 5℃ 이상 요동했고 r6은 13.7℃였다.
>
> ⚠️ 여기 적혀 있던 `R_th = delta_c ÷ P ≈ 0.16 ℃/W`는 **폐기**했다. `R_th`는 실온과 무관한
> 고유값이 아니었고(핵심 발견 9), `delta_c` 기반 산출은 이 경고문 자신이 말하는 함정에 걸린다.
>
> 로거의 경보는 `delta_c`가 아니라 **절대온도와 상승률**로 판단하므로 안전 설계에는 영향이 없다.

백그라운드로 돌리면 SSH가 끊겨도 살아남지만 **경보음이 파일로 가서 안 들린다**.
`tail -f ~/logger.out`로 보면 화면과 비프가 모두 전달된다.

## 장비

**전자부하 ATORCH BW150/CL24** — 최대 25A / 150W / 1~200V
- 모드 **10개**: `CC / CV / CR / CP / BRT / PT / CT / CDC / CDCDC / CDxN` (설명서 §5, 2026-08-26 확인)
  - **`CV`는 배터리 측정 불가** — 설명서 명시 (*"Constant Voltage mode cannot test the battery"*)
  - **`CDC` / `CDCDC` / `CDxN`은 충전 제어 모듈 별매.** `CDxN`은 **1~99회 충방전 자동 반복**이라
    열화 데이터에는 이게 왕도다 — 지금 계획의 run 은 전부 1회 방전이라 열화 축이 없다
  - `CT`(배선 내부저항·최대전류 7개 값)와 `BRT`(셀 내부저항)는 **4선식 지그가 왔으니 이제 의미가 있다**
- 입력 단자 4구 = **4선식(켈빈) 지원** (`A+ V+ V− A−`)
  - **바깥 `A+`/`A−`가 전류 단자**이고 가이드의 `BW150 부하 +`·`부하 −`는 이것을 뜻한다.
    안쪽 `V+`/`V−`는 전압 감지용
  - ✅ **확정 (2026-08-20, `배터리부하 설명서.pdf` p.5)** — `V+`/`V−`는 **내부적으로 이어져 있지 않다.**
    이 부하가 4선식을 지원한다는 것 자체가 증거다(내부에서 묶여 있으면 4선식이 불가능하다).
    - **2선식**: `A+`↔`V+`, `A−`↔`V−`를 점퍼로 이어야 한다. 안 이으면 전류는 흐르는데
      **전압 표시가 엉망**이 된다 — 이전 시험에서 3V 이하로 찍힌 원인
    - **4선식(권장)**: `A+`/`A−`는 전류(0.75SQ), `V+`→`SOURCE_P`·`V−`→전력 GND 스플라이스로
      **배터리 쪽에서** 감지한다. 감지선은 전류가 안 흘러 얇은 선이면 된다.
      매뉴얼도 *"voltage measurement is not affected by the voltage drop of the wire … recommended"*로 권장
    - ⚠️ **어느 가이드에도 이 내용은 없다**(3개 문서 grep 0건). 4선식으로 가면 원안 이탈이니 인계표에 적을 것
  - `8V<V<36V`라고 인쇄된 단자는 **부하 입력이 아니다.** 5V를 물리면 사양 밖 동작
- **USB/Type-C 입력 포트에 측정 대상을 꽂으면 안 된다** — 전류가 부하 내부로만 흘러
  INA226·CH3·CH4가 경로에서 빠진다. 반드시 나사 단자를 쓴다
- ✅ **ETS 온도프로브 있다** (2026-08-26 정정) — 장비 화면에 `ETS:030.4℃`가 뜨고
  `Run Stop` 조건에 `>100℃`가 걸려 있다. 설명서 기본 동봉품 목록에도 있다.
  구판의 "ETS 없음 → 장비 자동 온도차단 못 씀"은 **틀렸다**
- 다만 **100℃는 너무 높다** — 실측 최고 표면이 48.8℃였다. 실질 보호는 `tempguard.py`(IR 60℃)가 맡는다
- 설명서 p14에 **「Four major alarm functions」**이 있으나 이미지라 내용 미확인 — `Setup`에서 볼 것
- PC 소프트웨어 샘플링은 **1초 고정**. 0.1초는 INA로만 가능
- CSV 헤더 3줄은 배너, 4번째 줄이 컬럼명. 날짜 형식 `YYYY-MM-DD_HH:MM:SS`

**충전기**: 18650은 TC1 (5V/2A), 보조배터리는 5V/2.4A

**4선식 지그**: ATORCH 20A 배터리 테스트 스탠드 주문, **8/20~25 도착 예정**

### 2. 내부저항 분해 (2026-08-15 실측, 1A 부하)

```
무부하 OCV      4.02V
셀 단자 @1A     3.87V     → 셀+보호회로  0.15 Ω  (정상 범위)
부하 표시 @1A   3.82V     → 홀더+배선    0.05 Ω  (0.246Ω에서 개선)
```

- 정전류에서 `저항 = 전압차 ÷ 전류`로 바로 계산된다
- 임시 접점은 **드리프트한다**. 하루 사이 0.246 → 0.11 → 0.05Ω로 오갔다
- 3C(7.65A)에서 외부 0.246Ω이면 홀더가 **14.4W**를 열로 뿜는다(플라스틱 변형 위험 + 온도 측정 오염).
  0.05Ω이면 2.9W로 안전. **1.5C 이상과 모든 BRT는 지그 도착 후에만**

### 3. INA226 션트값이 측정 범위를 결정한다

INA226의 션트 전압 측정 한계는 **±81.92mV**(하드웨어 사양).

| 션트 | 측정 가능 최대 전류 |
|---|---|
| `R100` (0.1Ω) | **0.82A** — 1A도 초과. 사용 불가 |
| `R010` (0.01Ω) | **8.19A** — 이번 주 전 구간 커버 ✅ |

기존 모듈은 R100이라 못 썼고, **R010을 새로 구입했다**. 도착하면 **각인부터 확인**할 것.
`sensors.py`의 `SHUNT_OHMS = 0.01`로 설정.

### 4. 전압 강하와 발열은 같은 현상

부하를 걸면 전압이 떨어지는 것은 내부저항에서 `I×R`만큼 깎이기 때문이고, 그 전력 `I²R`이 곧 열이다.
부하를 끊으면 그 성분이 즉시 사라져 전압이 회복된다(스프링백). 8/9에 3초 끊긴 구간에서
3.310V → 3.558V로 튄 것이 그 현상이며, 여기서 내부저항을 계산할 수 있다.

**0.1초 샘플링이 필요한 이유**가 이것 — 부하 인가 직후의 밀리초 강하가 R0(옴), 이어지는 수 초가
R1(분극)이다. 1초로는 둘이 뭉쳐 나온다. PSSENL 논문 "short-term rest"가 다루는 신호이기도 하다.

### 5. 플라스틱 케이스는 단열재다

보조배터리(케이스 위 측정)는 2A/10W로 35분에 **+0.44℃**, 맨 18650(셀 표면)은 1A/3.7W로 48분에
**+3.81℃**였다. 전력이 1/3인데 상승률은 6.4배. 케이스 위 측정은 신호가 크게 눌린다.

### 6. 보조배터리 라벨 mAh는 셀 기준이지 USB 출력 기준이 아니다

`3.7V 10000mAh 37Wh`는 **셀 쪽 값**이다. 5V USB 출력에서 재면 부스트 변환을 거치므로 훨씬 적게 나온다.

```
37Wh ÷ 5V = 7.4Ah  (이론)
부스트 효율 85~90% → 약 6.3~6.7Ah
```

> ✅ **2026-08-21 PB-20000 실측으로 확정.** 1A 완전방전 10:55:47에 **54.21Wh / 10,928mAh @5V**.
> **에너지로 비교하면 라벨(74.0Wh)의 73.0%**, mAh끼리 비교하면 54.6%다. **반드시 Wh로 비교할 것** —
> mAh 비교는 3.7V(셀)와 5V(출력)를 섞는 것이라 무의미하다. 데이터·리포트는
> 바탕화면 `PB20000_r1_1A_20260821/`.

**5V 기준 실측 용량 ≈ 라벨 mAh × 0.65.** 이걸 모르고 "10000인데 6500밖에 안 나왔다 = 열화"로
판정하면 틀린다. **핵심 발견 1번(18650 1393mAh)과 같은 종류의 함정** — 기준을 어디서 재느냐가 값을 바꾼다.

2A 기준 예상 run 시간: PB-5000 약 1.6h / PB-10000 약 3.3h / PB-20000 약 6.5h.
**2A로 3종 한 바퀴가 11시간**이라 일정 배치에 직접 영향을 준다.

### 7. 출력 전류를 통일해도 셀 스트레스는 모델마다 다르다

PB-10000의 형식 표기 `1INR22/71-2`는 IEC 규격으로 **1직렬 / 2병렬 / 21700 셀**을 뜻한다
(`3.7V × 10Ah = 37Wh`가 5000mAh 셀 두 개와 맞는다).

| 모델 | 셀 구성 | 2A 출력 시 셀당 C-rate |
|---|---|---|
| PB-5000 | 1셀(추정) | 약 0.6C |
| PB-10000 | 21700 ×2 병렬 | 약 0.3C |

**출력 전류가 같아도 셀이 받는 부하는 2배 차이**다. 「크기 비교」에서 이걸 구분하지 않으면
발열 차이가 용량 때문인지 병렬 수 때문인지 섞인다. **나머지 두 모델의 형식 표기도 찍어 둘 것.**

### 8. 기록 공백을 평균 전류로 메우면 에너지가 조작된다

`analyze_run2.py`는 기록 공백을 평균 전류로 채운다. **그게 맞을 때와 틀릴 때가 있고,
공백 경계의 전압을 보면 즉시 갈린다.**

| run | 공백 | 직전 마지막 | 직후 첫 | 판정 |
|---|---|---|---|---|
| r1 | 593s | `5.0225V −0.988A` | `5.0225V −0.986A` | **로거만 재시작** → 보정이 맞다 |
| r3b | 6699s | **`0.0438V −0.0004A`** | `4.8463V −0.991A` | **방전 중단** → 보정하면 틀린다 |

r3b는 보정 때문에 **7.176 → 16.136 Wh (2.2배)** 로 부풀려져 있었다.
메운 8.959 Wh가 실제로 측정한 7.176 Wh보다 컸다. 전달률도 38.8%가 87.2%로 둔갑해
**3종 중 최고 성능처럼 보였다.**

- 정정 후 r3(7.702 Wh)와 편차 **7.1%** — 그제서야 재현성이 드러났다
- `compare_runs.py`는 공백 사이 원본에 `V<1` 행이 있는지 보고 **자동 판정**한다.
  사람이 `--no-gap-fill`을 기억해야 하는 구조를 없앴다
- **핵심 발견 1·6과 같은 종류의 함정** — 어디서 재느냐가 아니라 **무엇을 채우느냐**가 값을 바꾼다

### 9. IR `obj−amb`도 기준선 함정이 있다 — 냉각 꼬리로 재라

`delta_c`가 실온 드리프트에 오염되듯(위 경고 참조), **MLX의 `obj−amb`에는 정착 과도가 있다.**
로거를 켜면 MLX 내부 주변온도 센서(`TA`)가 아직 차가워서 차분이 크게 나왔다가 **약 1시간에
걸쳐 내려앉는다.** run 1 실측:

| 경과 | obj | amb(TA) | `obj−amb` |
|---|---|---|---|
| 0.0h | 26.93 | **24.53** | **+2.398** ← 이게 기준선으로 잡혔다 |
| 1.0h | 29.42 | 28.54 | +0.886 |
| 3.0h | 30.31 | 29.06 | +1.254 |
| 10.0h | 30.04 | 28.86 | +1.179 |

부하는 내내 5W로 동일했는데 기준선을 `+2.398`로 잡으면 발열이 **−1.4℃**로 나온다.

> **대안 — 냉각 꼬리 진폭.** 부하 차단 직전 60초 − 꼬리 말미 5분.
> 센서 정착도 실온 드리프트도 부하 차단과 무관하게 이어지므로 상쇄되고,
> **부하가 만든 열만 남는다. 기준선을 아예 안 쓴다.**
> 조건은 **꼬리 20분 이상** (τ가 10~19분이라 그보다 짧으면 과소평가).
> **run 1은 꼬리가 2분뿐이라 발열 값을 못 낸다.**

**그리고 `R_th`는 전류와 무관하지 않았다.** 발열 ∝ 전력ⁿ:

| 팩 | 비교 | 전력 배수 | 발열 배수 | 지수 n |
|---|---|---|---|---|
| PB-20000 | r4→r9 (9.83→14.43W) | ×1.47 | ×1.65 | **1.30** |
| PB-10000 | r2→r5 (4.87→9.23W) | ×1.90 | ×5.06 | **2.53** |

**n≈2가 물리적으로 자연스럽다** — 출력이 5V 고정이면 전력은 전류에 비례하고 저항 손실은 `I²R`이라
열은 전력의 제곱으로 간다. 다만 **표본이 팩당 두 점**이고 고전력 run일수록 실온 요동이 컸다.
**CC에서는 전류와 전력이 분리되지 않는다 — 이게 CP를 하는 이유다.**

### 11. CP 붕괴는 고갈이 아니라 「포트 정격 초과 + 양의 되먹임」이다

CP run 에서 팩이 몇 분 만에 무너지는 일이 반복됐는데, **고갈이 아니었다.** 붕괴 후 팩에
**80~90% 가 남아 있었다.**

```
① 전류가 포트 정격에 닿는다
② 팩이 전류 제한에 들어가며 출력 전압을 낮춘다
③ CP 부하는 P=V·I 를 지키려 전류를 더 요구한다  (I = P/V)
④ 더 깊은 제한 → 전압 더 하락 → ② 로
⑤ 되먹임이 발산해 수직 붕괴
```

**실측으로 확정 (2026-08-26, PB-10000 같은 팩·같은 충전):**

| run | 전력 | 시작 전류 | 최대 전류 | 정격 2.4A 대비 | 결과 |
|---|---|---|---|---|---|
| c2 | 10.20 W | 2.19 A | **2.658 A** | **111%** | 36분 붕괴 · **6.10 Wh** |
| c6 | 9.215 W | 1.92 A | **2.338 A** | **97%** | **3.07h 완주 · 28.27 Wh** |

**전력을 10% 낮췄더니 에너지가 4.6배 나왔다.** 한 번 충전으로 오늘 총 34.37 Wh —
r5(CC 2A)의 29.823 Wh보다 많다. **팩은 멀쩡하다.**

> **CC 에서는 안 일어난다.** 전류가 고정이라 되먹임이 없다. r5·r6 가 완주한 이유다.
> **CP 고유의 실패 모드**이며, 이상탐지 라벨로 값어치가 크다.

**팩별 CP 상한 = 포트 정격 전류 ÷ 말기 최저 전압**

| 팩 | 포트 정격 | CP 상한 | 검증 |
|---|---|---|---|
| PB-20000 | **3.83 A** (c8 실측) | **10~14 W 사이** | 10 W 완주 ✅ / 14 W 붕괴 ❌ |
| PB-10000 | C타입 2.4 A | **9~10 W 사이** | 9 W 완주 ✅ / 10 W 붕괴 ❌ |
| PB-5000 | C타입 2.1 A | **8~10 W 사이** | 8 W 완주 ✅ / 10 W 붕괴 ❌ |

**세 팩 모두 「시작 전류가 정격의 85% 이하면 완주, 100% 이상이면 붕괴」로 갈린다.**
c7 이 말미에 정격의 114%(2.40 A)까지 갔는데도 완주한 것을 보면, 정격 초과 자체가 즉시
붕괴는 아니고 **되먹임이 발산할 만큼 깊이 들어가야** 무너진다.

**붕괴 파형이 팩 건강도를 가른다:**

| 형태 | 예 | 뜻 |
|---|---|---|
| 끝까지 평탄하다 **한 샘플에 절벽** | c1 (4.92V → 0.05V, 0.1초) · c6 | 정상 종료 |
| 수십~수백 초에 걸쳐 **가속하는 무릎** | c2 (23초) · c3 (150초) | 되먹임 발산 |

### 13. 18650 전류축 3점 — 발열은 초선형이지만 제곱이 아니다 (2026-08-31)

**같은 날 1A / 2A / 3A 세 run 을 돌렸다.** 4선식 지그·Babysitter 우회·`max()` 핫스팟이
모두 갖춰진 첫 데이터셋이다.

| run | 셀 | 전류 | 전력 | 용량 | 라벨대비 | **꼬리 진폭** | τ | `R0` |
|---|---|---|---|---|---|---|---|---|
| b1 | BAT01 | 0.9898 A | 3.637 W | 2362 mAh | 92.6% | **+3.112 ℃** | 12.5분 | 0.1243 Ω |
| b2 | BAT02 | 1.9801 A | 7.042 W | 2247 mAh | 88.1% | **+5.785 ℃** | 9.2분 | — |
| b3 | BAT03 | 2.9692 A | 9.994 W | 1824 mAh | 71.5% | **+12.872 ℃** | 8.8분 | 0.1539 Ω |

> b3 는 시작 OCV 4.178 V 로 거의 완충이었으나 셀 저항이 높아 컷오프에 일찍 닿았다.
> 용량 71.5% 는 열화가 아니라 **1.26C 의 고율 + 그 셀의 높은 저항** 때문이다.

**꼬리 진폭은 지수 피팅으로 구한다 (2026-08-31 신설 방법):**

```
T(t) = T_inf + A·exp(−t/τ)   를 꼬리에 맞추고 A 를 쓴다
```

고정 창(25분)으로 자르던 기존 방식은 **절단 편향이 run 마다 달랐다**(핵심 발견 10).
지수 피팅은 **완전 감쇠까지 외삽**하므로 꼬리 길이에 무관하다. rms 0.02~0.14 ℃ 로 잘 맞는다.
위 표는 공통 27분 창으로 맞춘 값이며, BAT01 을 전체 3.81시간으로 피팅해도 3.053 ℃ 로
**2% 차이뿐**이라 창 선택에 견고하다.

**⛔ 단일 지수로 요약되지 않는다:**

| 구간 | 전류비 | 진폭비 | 국소 지수 |
|---|---|---|---|
| 1A → 2A | ×2.00 | ×1.86 | **0.89** |
| 2A → 3A | ×1.50 | ×2.23 | **1.98** |
| 1A → 3A | ×3.00 | ×4.14 | 1.29 |

**국소 지수가 0.89 에서 1.98 로 두 배 뛴다.** 두 점(1A·2A)만 봤을 때는 「n≈1, `R_th` 상수」로
보였고 실제로 그렇게 결론 낼 뻔했다 — **3A 가 그것을 깼다.**

> 핵심 발견 8·10 과 같은 패턴이다. **두 점이 맞아 보인다고 법칙이 아니다.**

**아직 섞여 있는 교란:**

| 교란 | 크기 |
|---|---|
| **셀이 셋 다 다르다** | `R0` 0.1243 → 0.1539 Ω (**24% 차**). 열 = `I²R` 이므로 직접 영향 |
| **τ 가 run 마다 다르다** | 12.5 / 9.2 / 8.8분 → 냉각 조건이 동일하지 않았다 |
| IR 겨냥 | 셀 교체마다 재설정 |

`I²R` 로 보면 b1 0.12 W → b3 1.36 W 로 **11.2배**인데 진폭은 4.1배뿐이다. 즉 **온도가 오를수록
냉각이 좋아지는**(자연대류) 효과가 겹쳐 있고, τ 가 계속 줄어드는 것이 그 방증이다.

> **다음 단계**: BAT01 을 재충전해 **같은 셀로 1A·3A** 를 돌린다. 셀 간 편차가 빠지면
> 지수가 처음으로 깨끗하게 나온다. 현재로서 정직한 결론은
> **「초선형이지만 제곱은 아니다」** 까지다.

### 「부하 전 두 IR 값 일치」는 겨냥 검증이 아니다 (2026-08-31)

b2 시작 시 `0x5A` 27.75 / `0x5B` 27.37 로 붙어 있어 겨냥이 맞은 줄 알았는데,

## 도구 사용 시 주의 (PowerShell + SSH)

- ⚠️ **Git Bash로는 `ssh`가 안 된다.** 한글 홈 경로(`C:\Users\<USER>\.ssh`)를 못 읽어 키를 못 찾고
  `Permission denied (publickey)`가 난다. **파이 접속은 PowerShell로만** 한다
- **`Get-Content ... -Raw | ssh`로 셸 스크립트를 보내면 BOM이 붙어 `bash`가 깨진다**
  (`﻿echo: command not found`). **Python으로 보내면 문제없다** — 원격 실행 스크립트는 Python으로 쓴다
- **PowerShell이 따옴표를 먹는다.** 원격 명령은 **작은따옴표로 전체를 감쌀 것**
  ```powershell
  ssh -o BatchMode=yes <USER>@IP 'echo test | sudo tee -a file'
  ```
- **`$(...)`를 PowerShell이 자기 것으로 해석한다** — 작은따옴표 안에 두면 해결
- **복잡한 스크립트는 파일로 만들어 stdin으로** — 따옴표 지옥을 근본적으로 피한다
  ```powershell
  Get-Content script.py -Raw | ssh <USER>@IP "python3 -"
  ```
  다만 **파이프로 보내는 스크립트에 한글을 쓰면 인코딩이 깨진다.** ASCII로 작성할 것.
  파일 배포는 `scp`가 안전하다
- **`pkill -f thermal_log`는 SSH 세션 자신을 죽인다** (명령줄에 같은 문자열이 있어서).
  대신 `pgrep -f [t]hermal_log | xargs -r kill` 또는 PID 지정
- 장시간 명령은 `run_in_background: true`로

### 방전 계획 (2026-08-21 재설계)

**원래 안이었던 `3종 × SOC 100/50/20 = 9 run`은 폐기했다.** 두 가지 이유다:

1. **보조배터리는 SOC가 출력단에서 안 보인다.** run 1이 증명했다 — 10.9시간 내내 5.02V로
   평탄하다가 수직 낙하했다. 부스트 컨버터가 셀 전압을 가린다. **SOC 50%에서 시작해도
   출력 전압은 똑같이 5.02V**라, 관측 가능한 차이는 지속 시간과 발열뿐이다.
2. **SOC 축은 이미 각 run 안에 있다.** 완전방전 run 하나가 SOC 100→0 전 구간을 담는다.
   "SOC 50에서 시작"한 run은 그 run의 후반 절반과 사실상 같은 데이터인데,
   **50%를 버리는 예비방전이 곧 run 시간**이라 소요만 배가 된다(LED는 25% 단위라 눈으로는 못 맞춘다).

> **SOC 실험이 필요하면 18650(모드 1)에서 한다.** 맨 셀은 단자 전압이 SOC를 직접 반영하므로
> 정보량이 비교가 안 된다. 지그 도착(8/20~25) 후의 과제다.

### INA226 모듈 단자 대응 (2026-08-20 확정)

보유 모듈은 실크스크린이 `VIN`/`GND`/`GND`/`VOUT`이라 **가이드의 `IN+`/`IN−`와 이름이 정반대로 매칭된다.**
뒷면에 `INPUT`/`OUTPUT`이 R010 션트를 사이에 두고 찍혀 있다.

✅ **2026-08-20 0.1A 시운전으로 부호 확정** — `VIN` 쪽에 전원을 물리면 **방전이 양수(+0.098A)로 나온다.**
따라서 **실크스크린과 반대로 물려야 한다**:

| 가이드 | 이 모듈 | 연결 |
|---|---|---|
| `IN−` = `SOURCE_P` | **`VOUT`** (= 뒷면 `OUTPUT`) | 모드 2: USB-A `VBUS` / 모드 1: 셀 홀더 `+` — **한 가닥만** |
| `IN+` | **`VIN`** (= 뒷면 `INPUT`) | CH3 `COM` (STEP 14) |
| — | `GND` ×2 | **비운다** — 음극은 `PB_N`→스플라이스로 간다 |

> 시운전 실측: `voltage_v=5.075V`, `current_a=+0.098A`, **`mismatch_a=0.0000`**.
> 교차검증이 완전히 일치하므로 **R010 션트값과 `CAL=0x0A00`이 모두 정확**하다.

- **큰 구멍 2개와 작은 구멍 4개는 같은 네트**다(큰 쪽은 굵은 선용). 단자대를 단 작은 쪽을 쓴다
- 헤더는 `VCC GND SDA SCL ALER` 5핀뿐 — **`VBUS` 핀이 없다.** 보드가 내부에서 묶어놨으므로
  **STEP 23-1의 "VBUS → IN−" 배선은 할 게 없다**(2A에서 션트 강하 20mV, 5V 대비 0.4%라 무시 가능)
- ~~`VIN`이 칩의 `IN+`인지 `IN−`인지 판정 필요~~ → **닫힘.** 위 표대로 `VOUT`이 `SOURCE_P`다

### 릴레이 보드 단자 배열 (2026-08-20 확정)

**네 채널 모두 `NC – COM – NO`** (왼쪽 → 오른쪽). 도통으로 확정했다:
무전원에서 `왼쪽↔가운데` 도통, 통전에서 `가운데↔오른쪽` 도통 → 공통인 가운데가 `COM`.

| 채널 | `COM` (가운데) | 쓰는 접점 |
|---|---|---|
| CH1 | ZY12PDN `+` | **`NO`**(오른쪽) → Babysitter `VIN` |
| CH2 | Babysitter `SYS+` | **`NO`**(오른쪽) → BW150 `A+` |
| CH3 | INA226 (`IN+` 쪽 단자) | **`NO`**(오른쪽) → CH4 `COM` |
| CH4 | CH3 `NO`에서 | **`NC`**(왼쪽) → Babysitter `BAT+` / **`NO`**(오른쪽) → BW150 `A+` |

> ⚠️ **CH3를 `NC`에 물리면 안 된다.** 그러면 릴레이가 꺼졌을 때 오히려 회로가 닫혀 **마스터 차단이 뒤집힌다.**
> 2026-08-20에 실제로 이 오배선이 있었고, 그 탓에 CH3를 "켰을 때" 경로가 끊겨 **0A**가 나왔다.
> **검증법**: 무전원에서 `INA226 IN+ 쪽 단자 ↔ Babysitter BAT+`가 **열려 있어야** 한다(STEP 22 「마스터 차단」).

### 릴레이가 안 움직일 때 (2026-08-20 실측)

딸깍 소리도 LED도 없으면 **전원부터 잰다.** 검은 탐침은 릴레이 보드 `GND`에:

| 측정 | 정상 | 비고 |
|---|---|---|
| 릴레이 `VCC` ↔ `GND` | 약 3.1V | 실제로 **2.8V**가 나왔고 원인은 **점퍼 접촉 불량**이었다 |
| 릴레이 `JD-VCC` ↔ `GND` | 약 4.9V | 확장보드 `5V0`에서 온다 |

릴레이가 꺼져 있으면 `VCC` 전류가 거의 0이다. **전류가 0인데 0.3V가 떨어지면 접촉이 거의 끊긴 것**이다 —
점퍼를 양쪽 다 다시 꽂고, 안 되면 브레드보드 구멍을 바꾸고, 그래도 안 되면 점퍼선을 교체한다.

### ⛔ 릴레이 보드 CH2·CH3·CH4 사망 (2026-08-27) — 교체 필요

**LED는 4채널 모두 켜지는데 딸깍(코일)은 CH1 하나뿐이다.** 보드 전원은 정상이었다
(`VCC 3.2V` / `JD-VCC 5.0V`, 무부하). 입력 옵토는 살아 있고 **그 뒤 코일 드라이브가 죽었다.**

> **진단법 — 같은 선을 다른 `IN` 핀에 꽂아 본다.** 전압 측정보다 확실하다.
> 변수(GPIO·점퍼선·확장보드)를 전부 고정한 채 **핀만 바꾸므로** 채널 고장이 바로 갈린다.
>
> | GPIO13 선을 꽂은 곳 | LED | 딸깍 | 판정 |
> |---|---|---|---|
> | `IN1` | ✅ | **✅** | 채널 정상 |
> | `IN3` (꾹 눌러 재체결) | ✅ | **❌** | **채널 고장 확정** |
>
> **「LED 켜짐」은 신호 도달만 증명한다.** 코일이 당기는지와 별개다 — 이걸 혼동해 한참 헤맸다.

**모드 2는 CH3(마스터)+CH4(모드선택) 두 채널을 쓰므로 지금 구성으로는 run 을 못 돌린다.**

| 선택지 | 내용 | 비고 |
|---|---|---|
| **보드 교체** (정석) | 4채널 5V 릴레이 보드, 옵토커플러 절연, `JD-VCC` 분리형 | 흔하고 싸다 |
| CH1 마스터 승격 (임시) | 전력선을 릴레이1 나사단자로 이설 + CH4 우회 직결 | **`tempguard.py`·`preflight.py`의 GPIO13을 5로 고쳐야 한다** |

⚠️ **임시안을 쓰면 안전장치가 엉뚱한 채널을 연다.** `tempguard.py`의 자동 차단은 GPIO13을 여는데,
마스터가 CH1이면 IR 60℃에서 차단이 걸려도 **부하가 안 끊긴다.** 상수를 같이 안 고치면 임시안을 쓰지 말 것.

### 🔥 GND 배선 2가닥 소손 (2026-08-27) — 원인 미확정, 재통전 전 판정 필수

**눈으로 확인된 소손은 두 곳뿐이다.** 이 둘이 **한 갈래로 이어진 경로**라는 것이 핵심 단서다.

| 탄 곳 | 그 선의 정상 전류 | 판정 |
|---|---|---|
| MLX `0x5B` 모듈의 `GND` 선 | **약 1.5 mA** | 수백 mA~A 가 흘렀다 |
| 확장보드 `GND` → 브레드보드 GND 레일 점퍼 **(2개 중 1개)** | 센서 합계 수십 mA | 같은 경로 |

> ⚠️ **확장보드 GND 점퍼는 2개였고 그중 하나만 탔다.** 둘이 진짜 병렬이었다면 비슷하게
> 더웠어야 한다. 한 쪽만 탔다는 것은 **두 점퍼가 서로 다른 구간을 맡고 있었고,
> 탄 쪽이 고장 전류의 경로였다**는 뜻이다.

**소손 경로가 MLX 가지에서 끝난다는 점이 중요하다.** 부하 귀환이 신호 GND 로 우회했다면
**주 경로**가 타야지 MLX 한 채널의 가지가 탈 이유가 없다. 그래서 유력한 가설은 이쪽이다:

| 가설 | 경로 | 정합성 |
|---|---|---|
| **① MLX `0x5B` 모듈 내부 단락 (`VCC`↔`GND`)** | 전원 → MLX → **그 모듈 GND 선** → 레일 → **그 점퍼** → 파이 | **탄 두 곳과 정확히 일치** |
| ② 부하 귀환이 신호 GND 로 우회 | `A−` 헐거움 → 전력 GND 대신 신호 GND 로 귀환 | 첫 발연과 같은 뿌리지만, 왜 MLX 가지가 타는지 설명 못 함 |
| ③ GND 가 데이지체인이라 MLX 선이 남의 전류를 나름 | 모듈 → 모듈 → 레일 순으로 이어져 있었다면 | 배선 실물 확인 필요 |

**갈라내는 방법은 저항 한 번이다 — 전원 다 뺀 상태에서:**

| 측정 | 판정 |
|---|---|
| **MLX `0x5B` 모듈 `VCC`↔`GND`** vs **`0x5A` 모듈 같은 지점** | `0x5B` 만 0~수 Ω → **가설 ① 확정, 모듈 폐기** |
| 확장보드 `3V3`↔`GND` · `5V0`↔`GND` | 0 Ω 이면 레일 단락 — 확장보드·파이도 의심 |

> **같은 부품 두 개를 나란히 재는 것이 이 프로젝트의 검증법이다.** 정상값을 몰라도 비교로
> 판정된다 — 릴레이 채널 고장을 `IN1`/`IN3` 에 같은 선을 꽂아 가려낸 것과 같은 원리.

**재통전 전 공통 조치 (어느 가설이든 해야 한다):**

1. **열 받은 듀폰선은 전부 교체.** 피복이 멀쩡해 보여도 안이 상한다
2. **탄 브레드보드 행·레일은 쓰지 않는다.** 내부 클립이 탄화되면 눈에 안 보이는 접촉저항이 남는다
3. **GND 를 데이지체인 하지 않는다.** 각 모듈 `GND` 는 레일에서 **각각** 뽑는다(스타).
   중간 한 가닥이 뒤쪽 전부의 전류를 짊어지는 구조를 없앤다
4. **BW150 `A−` 는 압착단자로 바꾸고 당겨서 확인한다.** 헐거운 나사 접점이 첫 발연의 원인이었고,
   **「BW150 이 100℃ 를 찍었다」는 것이 그 첫 증상**이었을 가능성이 높다
5. **통전은 단계별로**: ① 파이만 → ② 센서만 + `i2cstress.py 30` → ③ 릴레이 보드 + 딸깍 →
   ④ **팩 뽑은 채** `COM`↔`NO` 도통 → ⑤ 전력 경로, 낮에, 1A 부터

### ⛔ 4선식으로 바꿀 때 `A`↔`V` 점퍼를 반드시 제거한다 (2026-08-31)

**2선식용 점퍼(`A+`↔`V+`, `A−`↔`V−`)를 남긴 채 감지선을 셀에 물리면, 그 감지선이
INA226과 릴레이를 통째로 건너뛰는 두 번째 전력선이 된다.**

```
정상 : 셀+ → SOURCE_P → INA226 → CH3 → CH4 → BW150 A+
우회 : 셀+ → (얇은 감지선) → V+ → [점퍼] → A+        ← INA·CH3 를 건너뛴다
```

**실측 (18650 BAT01, 2026-08-31):**

| BW150 설정 | INA226 실측 | 비율 |
|---|---|---|
| 1.00 A | 0.8034 A | **80.3%** |
| 0.50 A | 0.4012 A | **80.2%** |
| **점퍼 제거 후 1.00 A** | **0.9908 A** | **99.1%** ✅ |

**진단 논리 — 이 순서로 좁혔다:**

1. 설정을 1.0 → 0.5 로 내리자 전류가 따라 내려왔다 → **부하는 규제 중이다.**
   회로 저항 때문에 못 흐르는 거라면 0.803 에 머물렀어야 한다
2. 두 번 다 정확히 설정값의 80% → **두 전류계가 같은 직렬 루프에서 25% 다른 값을 본다**
3. 같은 날 팩 시험에서는 같은 부하·같은 INA 가 **99.1% 일치**했다 → **부하 교정 문제가 아니다**
4. 그 사이 바뀐 것은 4선식 지그 배선뿐 → **우회 경로가 지그 배선과 함께 생겼다**

> ⚠️ **이건 측정 오차가 아니라 안전 문제다.** 우회 경로는 **CH3(마스터)도 건너뛴다.**
> 실제로 CH3 를 열었을 때 INA 는 0 A 를 읽었지만 우회 경로는 살아 있었다 —
> **`tempguard` 의 자동 차단이 그 상태에서는 무력하다.**
> 그리고 20% 우회는 1 A 에서 0.2 A 지만, 계획된 **3C(7.65 A)에서는 1.5 A** 다.
> 얇은 감지선에 그게 흐르면 2026-08-27 에 GND 가 탄 것과 같은 일이 난다.

**전압 차이가 먼저 보인다.** 4선식이 셀에서 감지하고 있으면 INA 와 BW150 의 전압이
거의 같아야 한다. `INA 4.099 V / BW150 3.88 V` 처럼 **0.2 V 이상 벌어지면 배선을 의심할 것.**

> `0.219 V ÷ 0.16 A ≈ 1.4 Ω` — 얇은 감지선다운 저항값이다. 굵은 전력선이면 이런 값이 안 나온다.

### ⛔ Babysitter 는 방전 경로의 병목이다 (2026-08-31)

가이드의 모드 1 방전 경로(`CH2+CH3`, CH4 는 NC)는 **Babysitter 의 `BAT→SYS` 를 지난다.**
여기서 **0.61 A 에서 걸린다** (BW150 은 1.0 A 를 요구하는데 0.613 A 만 흘렀고,
Babysitter 에 빨간 LED 가 들어와 있었다).

**해결 — CH4 를 ON(NO) 으로 두어 셀을 BW150 에 직결한다:**

```
셀 → SOURCE_P → INA226 → CH3 → CH4(NO) → BW150 A+     ← Babysitter 없음
릴레이: CH1 OFF · CH2 OFF · CH3 ON · CH4 ON
```

| | `CH2+CH3` (가이드 모드 1) | **`CH3+CH4` (직결)** |
|---|---|---|
| 최대 전류 | **0.61 A** | 션트 한계 8.19 A 까지 |
| 직렬 요소 | 셀 + 보호회로 + 지그 + **Babysitter** | 셀 + 보호회로 + 지그 |

> 가이드가 CH4 를 NC 로 고정한 것은 **Babysitter 로 충전까지** 하기 위한 배선이다.
> 순수 방전 시험에는 Babysitter 가 필요 없고 측정을 오염시킨다. **원안 이탈이므로 인계표에 기록.**
> 전환은 반드시 **부하 OFF 상태에서** 한다 (CH3 열고 → CH2 열고 → CH4 닫고 → CH3 닫기).

### ⚠️ `COM`↔`NO` 도통 측정은 회로 전체 고리를 잰다 (2026-08-27)

접점만 재는 줄 알았는데 **멀티미터가 접점을 우회하는 다리를 놓는다.** 시험 전류가
`NO → CH4 → Babysitter → INA → 션트 → SOURCE_P → 팩`을 한 바퀴 돌아온다.

- **단서: Babysitter에 불이 들어온다.** 그러면 고리가 닫힌 것이다
- 그 상태의 값은 접점 저항이 아니라 **회로 전체 저항**이라 능동소자 때문에 계속 흔들린다
  (「한 번 삑하고 불안정」이 정확히 그 모습)
- **부하 쪽에 2.1~2.5V가 뜨는 것도 탐침이 만든 것**이다. BW150 입력 콘덴서가 충전된다
- 이것 때문에 「부하선이 `NC`에 물렸다」고 오판했다. 실제로는 `NC`에 아무것도 안 물려 있었다

> **접점만 재려면 팩 USB를 뽑거나 `NO` 쪽 선을 떼고 잰다.** 고리를 끊어야 값을 믿을 수 있다.

### ⚠️ 떠 있는 노드의 전압은 아무것도 증명하지 못한다 (2026-08-27)

경로가 끊기면 그 아래 노드가 **5V의 절반쯤(2.1~2.5V)에 걸려 천천히 방전**한다.
`CH3 COM 2.5V / CH3 NO 2.5V`를 보고 「두 값이 같으니 접점 정상」으로 읽었는데 **둘 다 떠 있었다.**
INA `VIN`·`VOUT`도 같은 이유로 2.5V였고, 그걸 「션트 단선」으로 오판했다.

**끊긴 곳을 찾을 때는 전압이 아니라 도통·저항으로 잰다.** 단, 위의 고리 함정을 먼저 끊고서.

### 시작 전 확인 필요

1. ~~보조배터리 3종의 출력 정격~~ → **닫힘.** PB-5000 `5V 2.1A` 확인, 2A 통일 가능
2. ~~INA R010 션트 각인~~ → **닫힘.** 사용자 실물 확인 + DIE ID로 진품 확인
3. **USB 충전기 개수** — 충전이 이번 주 최대 병목. PB-10000·PB-5000이 **C타입 단일 포트**라
   C 충전기가 따로 필요하다
4. **CL24와 저전류 교차검증 + 부호 규약(방전=음수)** — CC 1A를 걸고 `V_shunt ≈ 10mV`(R010 전기적 재확인)와
   방전 시 부호가 음수인지 함께 확인한다. INA226은 지금 `CAL=0x0000`이라 `Current`/`Power` 레지스터가
   0을 뱉는다 — STEP 27-1 스크립트가 `CONFIG=0x4527` / `CAL=0x0A00`을 써 넣는다
5. **C타입 전원 인출 수단** — `5.1kΩ` 내장 sink 보드 또는 C→USB-A 젠더.
   **회로에 물리기 전에 단독으로 5V가 나오는지 먼저 잰다**
6. ~~두 MLX의 대상온도 편차~~ → **닫힘 (2026-08-20).** 공중에서는 `0x5A`가 +0.3~0.9℃ 높았으나
   배터리에 겨냥한 뒤 **−0.24~−0.48℃로 부호가 뒤집혔다.** 고정 편차라면 방향이 유지되어야 하므로
   **개체 편차가 아니라 겨냥 차이**로 확정. `temp_ir_surface = max()`가 실제로 더 뜨거운 구역을 고른다

**확장판에서 실제로 달라진 것:**

- **STEP 0 신설** — 확장보드 라벨을 실물로 검증한다 (전원 넣은 채로 하는 유일한 STEP)
- **STEP 8 TFT: 9핀 → `8핀`** — `SDO/MISO`는 안 꽂는다. 원본 제목이 틀렸다고 확장판이 명시
- **§3 배선 전 세팅: 9가지 → `10가지`** — ⑩ 확장보드·브레드보드 전제 확인이 추가
- **핀 지칭이 물리 핀번호 → 확장보드 BCM 라벨**(`SDA`, `GPIO5`, `5V0` …)
- **3.3V 레일 두 줄 → `3V3 레일` 한 줄**, 신호 GND는 `GND-A`+`GND-B`를 이어 한 네트
- **릴레이 `JD-VCC`는 확장보드 `5V0` 열에서** 뽑는다. **5V 레일은 만들지 않는다**
- **`SOURCE_P`를 브레드보드로 끌어오면 안 된다**(퓨즈 없는 회로에서 셀 단락) — 도통 확인 항목 추가
- 전력 4가닥 중 **브레드보드를 지나는 것이 하나도 없어야** 한다는 확인 추가

## 하드웨어

| | |
|---|---|
| 패널 | **ILI9488 3.5인치 480×320 SPI** (`3.5 TFT SPI 480X320 V1.0`) |
| 본체 | **Raspberry Pi 4 Model B Rev 1.5** — GPIO 는 `/dev/gpiochip0` |
| SPI | ✅ **활성** — `/dev/spidev0.0`, `/dev/spidev0.1` |
| 사용자 권한 | `<USER>` 가 `spi`·`gpio`·`i2c` 그룹에 있다. `sudo` 불필요 |

배선은 가이드 STEP 8 그대로 (14핀 중 **8핀만**):

```
TFT 1 VCC   -> 3V3            TFT 6 SDI(MOSI) -> GPIO10 / MOSI
TFT 2 GND   -> GND-B          TFT 7 SCK       -> GPIO11 / SCLK
TFT 3 CS    -> GPIO8 / CE0    TFT 8 LED       -> 3V3  (백라이트)
TFT 4 RESET -> GPIO24         TFT 9 SDO(MISO) -> 결선 안 함
TFT 5 DC/RS -> GPIO25         10~14 T_*       -> 결선 안 함 (터치 미사용)
```

`CS` 는 `CE0` 라 **커널 SPI 드라이버가 자동으로 잡는다.** 코드가 직접 제어하지 않는다.

## 파일

| 파일 | 내용 |
|---|---|
| `tft_ili9488.py` | ILI9488 드라이버. `/dev/spidev` + `/dev/gpiochip` 을 ctypes ioctl 로 직접 제어 |
| `bench_display.py` | 실시간 상태 화면 |
| `bench-display.service` | systemd 유닛 (2026-09-20 신설, 아직 미등록) |

셋 다 파이 홈(`~/`)에 배포돼 있다.

### 실행

```bash
python3 ~/tft_ili9488.py                        # 드라이버 자체 시험 — 컬러바 + 글자
python3 ~/bench_display.py --demo               # 센서 없이 레이아웃만
python3 ~/bench_display.py --name PB20K_15W     # run 이름 달고 실제 센서
python3 ~/bench_display.py --ds-interval 60     # 1-Wire 를 더 아끼고 싶을 때
```

**⚠️ Windows 에서 `deploy_pi.ps1` 이 실행 정책에 막힌다.** 그냥 `scp` 로 보내는 게 빠르다.
**⚠️ PowerShell 이 작은따옴표 안의 큰따옴표를 먹는다.** 원격에 스크립트를 보낼 때는

## 설계상 반드시 지켜야 하는 것

### 1. 쓰기 전용이다
MISO(9번)를 결선하지 않았으므로 **상태 레지스터를 되읽을 수 없다.**
초기화가 됐는지 코드로 확인할 방법이 없다. 화면이 안 나오면 배선·전원을 눈으로 봐야 한다.

### 2. 부분 갱신만 한다
ILI9488 은 SPI 에서 **픽셀당 3바이트(RGB666)** 를 요구한다. 480×320 전체가 **460KB** 라
매 주기 전체를 다시 그리면 계측이 밀린다. `_Field` 가 **문자열이 바뀐 칸만** 다시 그린다.

### 3. 의존성이 없다
Debian Lite 라 `spidev`·`Pillow` 가 없다. 5×7 비트맵 폰트를 코드에 넣고
SPI·GPIO 를 ioctl 로 직접 때린다. **라이브러리를 새로 깔지 말 것.**

### 4. 누적 mAh/Wh 는 참고값이다
1Hz 사다리꼴이고 화면을 재시작하면 0 으로 돌아간다. **분석에 쓰는 값이 아니다** —
분석은 `ina_log.py` 의 0.1초 적분으로 한다. 다만 **공백을 평균으로 메우지는 않는다**
(핵심 발견 8 의 함정). 결측·시간 점프 구간은 건너뛴다. 5가지 경우로 검증했다.

## 잡은 버그 (같은 실수를 반복하지 말 것)

### `GPIO_V2_LINE_FLAG_OUTPUT` 은 비트 3이다 (2026-09-04)

```c
USED(0) / ACTIVE_LOW(1) / INPUT(2) / OUTPUT(3)
```

처음에 `1 << 1` 로 썼더니 라인이 **입력으로 잡혀** `SET_VALUES` 가 `EPERM` 을 냈다.
`gpio` 그룹에 들어 있는데도 권한 오류가 나면 **플래그부터 의심할 것.**

### 글자는 한 번의 버스트로 보낸다 (2026-09-04)

첫 판은 켜진 픽셀마다 `fill_rect` 를 불러 `"4.123 V"` 한 줄에 ioctl 이 약 1,200 번
나갔다. 지금은 문자열 전체를 메모리에서 합성해 **윈도우 전송 1회**(1,008 바이트)로 보낸다.

### 🔴 칸을 넘는 글자는 조용히 잘렸다 (2026-09-20)

`_Field` 는 `w // (6*scale)` 글자만 쓴다. 값 칸이 **6글자**였는데 넣던 문자열이
7~8글자였다. **예외도 경고도 없이 단위가 통째로 사라진다.**

| 넣던 것 | 필요 | 칸 | 실제로 그려진 것 |
|---|---|---|---|
| `4.123 V` | 168px | 156px | `4.123` |
| `-0.991 A` | 192px | 156px | `-0.991` |
| `-14.43 W` | 192px | 146px | `-14.43` |

**구판 인계문서의 화면 그림은 실제로 저렇게 나온 적이 없다.** 지금은 단위를 라벨로
올렸다. **칸을 새로 만들 때는 `_fits(w, scale, text)` 로 먼저 재 볼 것.**

### 🔴 CAL=0 이면 전류가 0 으로 보인다 (2026-09-20) — 제일 위험했던 것

INA226 은 **전원이 나갔다 들어오면 `CAL` 이 `0x0000` 으로 돌아간다.** 그 상태에서는
**Current·Power 레지스터가 전류가 흘러도 0 을 뱉는다.** `bench_display` 는 읽기만 하고
`CAL` 을 안 쓴다 — 그걸 쓰는 건 `ina_log.py` 다.

**즉 재부팅 직후 화면만 먼저 띄우면 3A 가 흐르는 중에도 `+0.000 A` 가 떠 있었다.**
무부하와 구분이 안 되고, 하필 **핵심 발견 12(팩이 30~40초면 잠든다)와 증상이 같아서**
멀쩡한 하드웨어를 뜯어보게 된다. `RunMeter` 도 영영 시작을 안 한다.

**고친 방법 — 션트 전압 레지스터(0x01)는 `CAL` 과 무관하다.** 그래서

- `CAL == 0x0A00` 이면 Current 레지스터를 쓴다 (`ina_log.py` 가 기록하는 값과 일치시킨다)
- 아니면 **션트에서 직접 계산**하고 상태줄에 `INA CAL=0  shunt fallback` 을 띄운다

두 경로 다 실측 확인했고 서로 **0.1 mA 안에서 일치**한다.

## 실측 성능 (2026-09-20, 파이 4)

| 항목 | 1회 비용 |
|---|---|
| INA226 3 레지스터 | 2.01 ms |
| MLX90614 ×2 | 1.43 ms |
| `pinctrl` 릴레이 | 4.93 ms |
| **DS18B20 ×2** | **1598 ms** ← 여기에 다 썼다 |
| SPI 전 칸 다시 그리기 | 70 ms |

**1-Wire 변환이 센서당 800ms 라 DS 를 주 루프에서 읽으면 1Hz 가 원천적으로 안 된다.**
`--interval 1.0` 을 줘도 실제 주기는 **1705 ms** 였다. 주기를 늘려 캐시하는 것만으로도
안 됐다 — 갱신하는 그 한 주기가 여전히 1.6초 멎는다.

→ **`DsReader` 스레드로 뺐다.** 주 루프는 캐시만 본다.

```
최악 주기  1705 ms  →  63 ms     (설정 1000 ms 대비 94% 여유)
```

화면이 스스로 `주기 실측 — 최악 N ms` 를 30주기째에 한 번 찍는다. **밀리면 그렇게 말한다.**

### 로거를 방해하는가 — 안 한다 (150초 × 2회 실측)

| 로거 | 화면 없이 | 화면 켜고 |
|---|---|---|
| `ina_log` 0.1s | 1500 행 | **1500 행** |
| `mlx_fast_log` 0.1s | 1551 행 | **1500 행** (공칭치로 수렴) |
| `thermal_log_alarm` | 58 행 | **57 행** |

`thermal_log_alarm` 이 150초에 58행뿐인 것은 **화면 탓이 아니다** — 그 로거 자신이
DS 를 순차로 읽어 행당 2.6초가 걸린다(CLAUDE.md 에 있는 그 값). 화면은 1행 차이고
계수 오차 범위다. **`--ds-interval` 기본을 30초로 둔 이유**가 이것: 1-Wire 점유율이
`1.6/(T+1.6)` 이라 T=10 이면 14%, T=30 이면 5% 다.

### 4 — systemd 등록 (sudo 라 사용자가 직접)

`~/bench-display.service` 는 배포돼 있고 `systemd-analyze verify` 를 통과했다.

```bash
sudo cp ~/bench-display.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now bench-display
```

run 이름만 바꿀 때 (sudo 없이도 편집은 되지만 restart 에 sudo 가 필요하다):

```bash
echo 'RUN_NAME=PB20K_15W' > ~/bench_display.env
sudo systemctl restart bench-display
```

유닛은 `Nice=10` 이라 **계측과 CPU 를 다투면 화면이 양보한다.**

### 문제가 생기면

| 증상 | 확인할 것 |
|---|---|
| 까맣기만 하다 | TFT **8번 `LED`** 가 3V3 에 물렸는지 (백라이트 스위치다) |
| 아무것도 안 나온다 | `VCC`(1) · `GND`(2) · 로직 5선 |
| **전류가 계속 0.000** | 상태줄에 `INA CAL=0` 이 떴는지. 떴으면 `ina_log.py` 를 먼저 띄운다 |
| **셀·실온이 `--`** | 시작 후 1.6초는 정상(스레드가 첫 변환 중). 계속이면 1-Wire 배선 |
| 색이 깨지거나 줄무늬 | SPI 속도를 낮춘다 — `ILI9488(speed_hz=16000000)` |
| `EPERM` | GPIO 플래그 비트 (위 「잡은 버그」 참조) |
| `/dev/spidev0.0` 없음 | `sudo raspi-config nonint do_spi 0` 후 재부팅 |

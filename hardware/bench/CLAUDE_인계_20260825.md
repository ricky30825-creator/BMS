### 결과 요약

**전달률 매트릭스** (라벨 `mAh × 3.7V` 대비 5V 출력 Wh)

```
              1A       2A       3A
PB-20000    73.0%    71.0%    66.7%
PB-10000    83.3%    80.6%      —      (신품)
PB-5000     41.6%    34.2%      —      (2년 사용)
```

**확인된 것 세 가지**

1. **전류가 오르면 전달률이 떨어진다** — 3종 모두 재현. 부스트 도통손실 `I²R`
2. **하락이 가속된다** — PB-20000: 1→2A `−2.0%p`, 2→3A `−4.3%p`. 3점을 찍어야 보인다
3. **열화된 팩이 고전류에서 더 무너진다** — 건강한 팩 2~3%p vs 2년 팩 **7.4%p**

**미해결 — 초선형 발열**

```
PB-20000   전력 1.00× → 1.98× → 2.91×
           온도 1.00× → 5.2×  → 10.2×      지수 약 2.2
```

전력 2배에 온도 5배. **세 팩·두 구간에서 일관되게 재현**됐다. 물리적으로는 반대여야 한다
(온도가 오르면 대류·복사가 세져 열저항이 줄어야 하고, 실제로 τ는 그 방향이다).
**설명을 붙이지 못했으므로 현상으로만 기록한다. 억지 해석을 만들지 말 것.**

**전류가 원인인지 전력이 원인인지 아직 구분 불가.** CC에서는 둘이 붙어 다닌다.
**CP 모드가 이를 분리할 유일한 방법** — `CP모드_방전계획_20260825.md` 참조.

### 표준 분석 3줄

```powershell
python analyze_run2.py <run디렉터리> --label-mah 20000 --base-ir <기준선> --base-ir-b <기준선> --base-dc <기준선> --name "PB-20000 2A"

python build_report2.py <run디렉터리> --label-mah 20000 --base-ir <기준선> --base-ir-b <기준선> --name "..." --sub "..."
```

**`--base-ir`는 필수에 가깝다.** 로거를 로드 ON 이후에 띄우면 파일에 무부하 구간이 없어서
기준선을 0으로 가정하게 되고, 자체 발열이 1℃대인 run에서는 그게 결과를 뒤집는다.
**`preflight.py`가 찍어주는 값을 그대로 넘긴다.**

기타 옵션: `--no-gap-fill` (공백 동안 전류가 흐르지 않았을 때)

## 4. run 실행 절차 — 실측으로 확립된 순서

이 순서를 지키면 이번 세션에서 겪은 실패가 대부분 안 난다.

```

② 센서 부착 → sensorwatch.py 40초   → "전부 정상" 나와야 함

⑤ ina_check.py 10        → 전류가 10초 내내 안정한지 확인

⑦ 종료 후 온도·IR 로거를 25분 더
⑧ pkill + 릴레이 차단 + scp 회수
```

## 5. 이번 세션에서 새로 발견한 함정

인계 문서에 없던 것들이다. **전부 실제로 시간을 잃고 얻은 것.**

### ① 센서를 안 붙이고 3시간을 돌렸다

`preflight.py`는 센서가 **응답하는지**만 본다. 무부하에서는 붙었든 안 붙었든 IR 차분이 0 근처라
구분이 안 된다. **`sensorwatch.py`를 반드시 돌릴 것** — 팩을 손으로 감싸면 붙은 채널만 반응한다.
MLX가 보는 면을 손으로 덮으면 손을 재게 되어 **거짓 통과**가 나오니, 옆이나 아래에서 감쌀 것.

### ② 기준선 동안 마스터를 끄면 INA 로거가 자멸한다

CH3가 열려 있으면 INA가 0V를 보고 `--stop-v 3.0`을 방전 종료로 오인한다.
**배터리를 경로에 붙인 채로 기준선을 잡거나, INA 로거는 로드 ON 직전에 띄운다.**

### ③ 잠든 팩은 CC 부하로 못 깨운다

전압이 0이면 CC 부하가 전류를 안 끌고, 팩은 전류가 없으니 계속 잔다. **버튼을 누르는 수밖에 없다.**
무부하 방치 10~30초면 잠든다.

### ④ 접점이 4일간 4번 끊겼다 — 판별법이 있다

| 증상 | 원인 |
|---|---|
| 20초에 걸쳐 전압이 흘러내린 뒤 붕괴 | **진짜 BMS 차단** — 데이터 유효 |
| 4.9V에서 한 샘플(0.1초) 만에 0 | **접점 단선** — 데이터 폐기 |
| 2.5V 같은 어중간한 값에서 부유 | **한쪽만 연결됨** 또는 팩 수면 |

`endshape.py`가 이걸 자동으로 판정한다. **나사에 맨 꼬임선을 물리면 반복된다 — 압착 단자로 재작업할 것.**

### ⑤ `ina_log.py`는 이어쓰기다

같은 파일명으로 다시 띄우면 **앞 데이터 뒤에 붙는다.** 재시작 전 `rm -f` 할 것.
로거를 두 번 띄우면 같은 파일에 두 프로세스가 써서 행이 뒤섞인다 —
**`pgrep -u <USER> -c -x python3`이 3인지 반드시 확인.**

### ⑥ 실온 프로브는 파이·BW150 양쪽에서 멀어야 한다

배터리에서 10cm는 지켰는데 파이 근처에 뒀다가 실온이 **13.7℃**까지 흔들린 run이 있다.
두 장비 다 상시 발열한다. 다행히 IR 차분은 영향이 없다.

### ⑦ 짧은 run은 열평형에 도달하지 않는다

8 run 중 5개가 미도달이었다. 특히 PB-5000 2A(41분)는 말미까지 `+5.68℃` 상승 중이었다.
`analyze_run2.py`가 자동 경고하고 **말미값 기준 `R_th`를 함께 낸다** — 짧은 run은 그쪽을 쓸 것.

### ⑧ MLX 겨냥이 바뀌면 `R_th` 비교가 끊긴다

팩을 갈아 끼울 때마다 다시 붙이므로 거리와 조준점이 달라진다. IR은 시야각 평균을 재므로
거리에 민감하다. **겨냥 지그가 크기 축을 막는 유일한 병목이다.**

## 6. 파이 접속 · 하드웨어

```powershell
ssh <USER>@<LAN_IP>        # mDNS: Resolve-DnsName <HOST>
```

**Pi 4 Model B** (Pi 5는 고장). `sudo`는 비밀번호 필요 → 사용자에게 명령어 전달.
정상 종료는 `sudo poweroff` — 그냥 뽑으면 SD 손상 이력이 있다.

**Git Bash로는 ssh가 안 된다** (한글 홈 경로). **PowerShell만 쓸 것.**
`Get-Content -Raw | ssh`는 BOM이 붙는다 → **`[System.IO.File]::ReadAllText($p) | ssh ... "python3 -"`**를 쓴다.
PowerShell이 괄호·따옴표를 먹으므로 원격 명령에 `(`, `)`, 중첩 따옴표를 넣지 말 것.

### 센서 (ID 고정)

| 채널 | 주소/ID | 역할 |
|---|---|---|
| DS18B20 | `28-062565206490` | 셀·케이스 표면 |
| DS18B20 | `28-0625650a2c2c` | 실온 |
| MLX90614 | `0x5A` | IR — **주력 채널** (대개 이쪽이 뜨겁다) |
| MLX90614 | `0x5B` | IR — 보조 (PB-5000은 이쪽이 더 뜨겁다) |
| INA226 | `0x40` | R010 션트, `CAL=0x0A00`. 방전 = **음수** |

**MLX는 repeated START(`I2C_RDWR`)로 읽어야 한다.** 별도 트랜잭션이면 전 레지스터가 `0xFFFF`로
나와 고장으로 오인하기 쉽다.

### 릴레이

```
pinctrl set 19 op dl    # CH4 → 모드 2 (보조배터리)
pinctrl set 13 op dl    # CH3 마스터 ON
pinctrl set 13 op dh    # 마스터 OFF  ← 긴급 차단
```

`hi` = 열림(안전), `lo` = 닫힘. 부팅 시 `config.txt`가 전부 `dh`로 올린다.

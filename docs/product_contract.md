# 셀가드 제품 계약서

이 문서는 셀가드 배터리 열폭주 관제 서비스가 **무엇을 하는지**만 기술한다. 어떻게 생겼는지는 기술하지 않는다. 어떤 시각 방향으로 다시 디자인하더라도 이 문서의 내용은 그대로 유지되어야 한다.

기준: `설계 산출물/셀가드 프로토타입_v3.html` (2026-07-22 확인).

## 0. 이 문서를 받은 실행자에게

### 막히면 멈추고 물어본다

다음 상황에서는 추측으로 채우지 말고 **작업을 멈추고 사용자에게 질문한다.**

- "고정"으로 적힌 항목인데 내용이 불충분해 그대로 옮길 수 없을 때
- 이 문서에 없는 정보나 동작을 추가해야 할 것 같을 때
- 부록 A의 목업 데이터에 없는 값이 필요할 때
- 하려는 디자인이 `**게이트**` 또는 `**불변**`과 충돌할 때

**묻지 말고 스스로 결정한다** — 아래 판정표의 "자유" 항목 전부.

**물을 때의 형식** — 무엇이 왜 막혔는지 한두 문장 + 선택지 + 잠정 추천. 답을 받기 전에 그 부분을 추측으로 채워 진행하지 않는다. 대신 답에 의존하지 않는 나머지 작업은 마저 끝내고 질문을 함께 올린다.

### 고정 / 자유 판정표

| | 항목 |
|---|---|
| **자유** | 색·간격·반경·그림자·타이포·모션 / 화면 개수와 경계 / 정보를 담는 그릇의 형태 / 목록 탐색 방식 / 이동 수단의 구조 |
| **고정** | 표시해야 할 데이터 항목 / 가능해야 할 동작 / 4단계 상태 등급과 임계 / 안전 게이트와 불변 조건 / 상태·예외 처리 / 반응형 3종(데스크톱·태블릿·모바일) 지원 |

아래 `## F로 시작하는 절`은 **기능 영역**이지 화면이 아니다. 한 영역이 새 디자인에서 화면 하나일 수도, 둘로 나뉠 수도, 다른 영역과 합쳐질 수도 있다.

### 도달 가능성

일반 사용자는 아래 9개 목적지에 도달할 수 있어야 한다 — 실시간 관제, 배터리 자산관리, 이상 탐지, 추세, 이벤트 이력, 알림 센터, 공지사항, 릴레이 제어, 설정. 관리자는 여기에 통합 관제, 유저 계정 관리, 배터리 운영 관리, 공지사항 관리, 감사 로그 5개가 더해진다.

**이동 수단의 구조는 자유다.** 몇 단계로 묶든, 어떤 형태로 제공하든 상관없다. 도달 가능하기만 하면 된다. 다만 T0 게이트가 걸린 상태에서는 배터리 자산관리를 제외한 8개가 잠겨야 한다.

**추적** — REQ-WEB-018

### 이상점수와 상태 등급

AI가 산출하는 Final Score는 0.0–1.0이며, 표시할 때는 100배한 정수를 쓴다.

| 등급 | Final Score | 표시값 |
|---|---|---|
| 정상 | 0.0–0.3 | 0–29 |
| 주의 | 0.3–0.6 | 30–59 |
| 경고 | 0.6–0.8 | 60–79 |
| 위험 | 0.8–1.0 | 80–100 |

원본 데이터를 그대로 보여주는 곳에서는 환산하지 않은 0.0–1.0 값을 쓴다. 100배한 정수는 사람이 읽는 표시에만 쓴다.

등급은 언제나 위 표로 계산한다. 어딘가에 미리 적어둔 등급 값을 그대로 보여주지 않는다. 계산 결과와 어긋난 등급이 남아 있으면 계산이 이긴다.

### 용어

| 용어 | 뜻 |
|---|---|
| Final Score | AE Score와 Informer Score를 가중합한 최종 이상점수 |
| AE Score | LSTM-AutoEncoder의 재구성 오차 기반 현재 이상점수 |
| Informer Score | Informer의 예측 오차 기반 미래 위험점수 |
| `device_id` | 측정 **장비**(라즈베리파이) 식별자 |
| `battery_id` | 측정 **대상**(셀·보조배터리) 식별자. 자산으로 등록해 재연결 시 이력을 잇는다 |
| 측정 모드 | 1 내장 배터리 / 2 외부 셀 / 3 보조배터리. 동시 활성 불가(인터락) |
| Kill-Switch | 위험 등급에서 전원을 물리적으로 차단하는 릴레이 제어 |
| Fail-Safe | 가스·압력·음향 임계 초과 시 AI 판정과 무관하게 즉시 차단하는 독립 안전계층 |
| 게이트 | 다음 단계로 넘어가기 전에 반드시 통과해야 하는 조건. 이를 건너뛰는 경로가 존재하면 안 된다 |
| 불변 | 어떤 경로로도 깨지면 안 되는 조건 |
| T0, T1 … | 과업 플로우의 번호다. 이 문서의 "과업 플로우" 절에 정의된다 |
| F1, F2 … | 기능 영역의 번호다. 이 문서의 "기능 영역" 절에 정의된다. F5는 결번이다 |

### 하지 말 것

- 4단계 등급의 임계값을 바꾸지 않는다
- 이상점수를 정수 아닌 형식으로 표시하지 않는다
- 이상점수 범례를 3구간(정상 0~39 / 주의 40~69 / 위험 70 이상)으로 쓰지 않는다 — v3의 버그이며 4등급이 정본이다
- 안전 게이트를 생략하지 않는다. 재인증·사유 입력 없는 차단 경로를 만들지 않는다
- 배터리 미연결 상태에서 잠긴 영역을 열어주지 않는다
- 관리자 전용 기능을 일반 사용자 영역에 노출하지 않는다
- 측정 모드 인터락(동시 활성 불가)을 무시하지 않는다
- 부록 A에 없는 수치를 지어내지 않는다

## 과업 플로우

화면 이동이 아니라 순서와 게이트를 고정한다. 각 단계를 어느 영역에서 수행하는지는 지정하지 않는다.

### T0. 진입 잠금

**게이트** — 일반 사용자는 측정 대상 배터리를 연결하기 전까지 T3(자산 등록·선택)을 제외한 모든 과업에 진입할 수 없다. 잠긴 대상은 선택해도 이동하지 않으며, 잠겨 있다는 사실과 푸는 방법이 보여야 한다.

로그인 직후 도착지는 배터리 자산관리(F6)다. 관리자는 이 게이트를 받지 않는다.

**불변** — 배터리가 연결되지 않은 상태에서 F4·F8·F9·F10·F11·F12·F13·F14에 도달하는 경로는 존재할 수 없다.

**추적** — REQ-WEB-073

### T1. 가입·로그인·계정 찾기

1. 로그인 절차를 시작한다
2. 이메일과 비밀번호로 로그인하거나, 관리자 계정으로 로그인하거나, Google 계정으로 로그인한다
3. 계정이 없으면 가입으로 넘어간다 — 이름, 이메일(중복 확인), 비밀번호, 전화번호를 입력하고 이용약관에 동의해 가입을 완료한다. 언제든 기존 계정 로그인으로 되돌아갈 수 있다
4. 이메일이나 비밀번호가 기억나지 않으면 계정 찾기로 넘어간다 — 가입한 이메일로 비밀번호 재설정 링크를 받거나, 이름과 전화번호로 본인 확인을 거쳐 마스킹된 이메일을 확인한다
5. 로그인한 뒤에는 언제든 로그아웃해 세션을 종료할 수 있다

**추적** — REQ-WEB-003, REQ-WEB-005, REQ-WEB-006, REQ-WEB-007, REQ-WEB-008, REQ-WEB-009, REQ-WEB-010, REQ-WEB-011, REQ-WEB-012, REQ-WEB-013, REQ-WEB-014

### T2. 측정 시작·종료

1. 저장된 배터리를 확인한다 — 측정 모드로 범위를 좁힐 수 있어야 한다
2. 대상을 선택한다
3. **게이트** — 한 번에 하나만 연결되며 기존 연결은 해제된다는 사실을 알리고 확인을 받는다
4. 측정 세션이 시작되고 실시간 관제 정보(F4)에 반영된다
5. 측정 세션을 사용자가 직접 끝내는 동작은 없다. 데이터 수신이 끊기거나, 다른 배터리를 연결하거나, 배터리가 운영 차단되면 서버가 세션을 끝내고, 그 사실이 전달되면 T0의 잠금 상태로 되돌아간다

3에서 확인 대신 취소하거나, 선택한 배터리의 상세·이력(F7)으로 먼저 갈 수 있어야 한다.

**실패 경로** — 디바이스가 오프라인이면 3에서 중단하고 사유를 알린다
**불변** — 게이트 3을 건너뛰고 세션을 시작하는 경로는 존재할 수 없다

**추적** — REQ-WEB-032, REQ-WEB-033, REQ-WEB-034, REQ-WEB-039

### T3. 배터리 자산 등록·수정

1. 새 배터리 등록을 시작한다
2. 배터리 이름, 측정 모드, 제조사(선택), 모델(선택), 직렬 셀 수(선택)를 입력한다
3. **게이트** — 배터리 종류(`chemistry`)는 필수 입력이다. 채우지 않으면 등록을 완료할 수 없다
4. 등록하면 `battery_id`가 발급되고 측정 모드가 자산에 고정된다
5. 이미 등록된 배터리는 정보를 불러와 이름·제조사·모델·직렬 셀 수·메모를 수정하고 저장할 수 있다. 측정 모드는 자산에 고정되어 등록 후에는 바뀌지 않으며, `battery_id`도 어떤 경로로도 바뀌지 않는다

**추적** — REQ-WEB-036, REQ-WEB-037, REQ-WEB-038

### T4. 이상 징후 확인 → 근거 확인

1. 현재 이상점수와 정상·주의·경고·위험 구간, 점수 추세를 확인한다
2. 더 자세한 확인이 필요하면 이상 탐지 확인으로 넘어간다
3. 활성 이상 이벤트 수, 오늘 발생한 이상 수, 최고 이상점수, 모델 동작 상태를 확인한다
4. 이상점수에 기여한 요인(V_drop, dT/dt, I_smooth 등)을 근거로 확인한다
5. 건강도(SOH, RUL, 누적 사이클, 내부 저항)와 만료 임박 여부를 함께 확인한다
6. 이상 이벤트 항목을 선택하거나 더 보기를 실행해 발생 시각·원인·조치를 포함한 상세를 확인한다

**추적** — REQ-WEB-021, REQ-WEB-022, REQ-WEB-042, REQ-WEB-043, REQ-WEB-044, REQ-WEB-045

### T5. 추세·이력 조회 및 내보내기

1. 저장된 배터리에서 상세·이력으로 넘어가 기본 정보, 현재 상태, 최근 측정값을 확인한다
2. 과거 측정 세션(세션 ID, 시간, 상태, 이상점수)을 확인한다
3. 추세를 살핀다 — 24시간·7일·30일 기간을 전환하고, 온도·전압 등 표시 지표를 바꾸고, 비교 추가로 다른 배터리·세션을 겹쳐 본다
4. 이벤트 이력에서 검색어로 좁히고, 상태 기준으로 필터링하고, 정렬 기준(최근 측정순·이상점수 높은순·SOC 낮은순 등)을 고르고, 페이지를 넘긴다
5. 이벤트 항목을 선택해 상세와 관련 센서값을 확인한다
6. 조회 결과를 CSV 또는 PDF로 내보내겠다는 확인을 거쳐 내보낸다

**추적** — REQ-WEB-040, REQ-WEB-041, REQ-WEB-035, REQ-WEB-046, REQ-WEB-047, REQ-WEB-048, REQ-WEB-049, REQ-WEB-050, REQ-WEB-051, REQ-WEB-052, REQ-WEB-053, REQ-WEB-054, REQ-WEB-055

### T6. 알림 수신 → 확인(Ack)

1. 새 알림이 오면 미확인 알림을 연다
2. 인앱·카카오 알림 이력, 발생 시간, 확인 상태를 확인한다
3. 개별 항목을 확인(Ack) 처리해 대응 확인 상태를 남기거나, 모두 확인으로 미확인 알림을 한 번에 처리한다
4. 전체 이력이 필요하면 알림 센터로 넘어간다

**추적** — REQ-WEB-016, REQ-WEB-056, REQ-WEB-057, REQ-WEB-058, REQ-WEB-027

### T7. 위험 제어 — 릴레이 차단·복구

1. 현재 회로 상태(정상 연결 / 차단됨)를 확인한다
2. 차단 또는 복구를 요청한다
3. **게이트** — 재인증하고 사유를 입력해야 실행된다. 둘 중 하나라도 없으면 실행하지 않는다
4. 실행 결과와 바뀐 회로 상태가 보인다

**불변** — 재인증과 사유 입력을 거치지 않는 차단·복구 경로는 존재할 수 없다

**추적** — REQ-WEB-023, REQ-WEB-061, REQ-WEB-062, REQ-WEB-063

### T8. 자동 차단(Fail-Safe) 수신 대응

1. 자동 차단이 발생하면 즉시 알림이 뜬다 — 차단 사유(예: 온도 임계 초과), 대상 배터리, 회로가 이미 차단된 상태임을 함께 확인한다
2. 확인을 눌러 알림을 닫는다. 이후 릴레이 제어(F12)에서 현재 회로 상태를 다시 확인할 수 있다

이 흐름은 승인 절차가 없다 — Fail-Safe는 AI 판정이나 사용자 승인과 무관하게 이미 실행된 차단을 통보만 한다.

**추적** — REQ-WEB-064

### T9. 설정 변경

1. 알림 수신 채널(카카오·이메일·SMS·웹푸시)의 수신 여부를 켜고 끄고, 위험·경고 즉시 발송·위험 등급만 발송·중복 발송 억제 같은 발송 조건을 확인한다
2. 계정 정보(이름·이메일·전화번호)를 확인하고 변경 사항을 저장하거나, 새 비밀번호를 입력해 비밀번호를 재설정한다
3. 테마(라이트·다크·시스템)를 선택한다
4. 디바이스 음성 안내의 전체 켜짐/꺼짐, 음량, 연결/측정·이상상태·Fail-Safe/릴레이·센서/디바이스 오류·네트워크/서버 상태 카테고리별 안내 여부를 설정한다
5. 언제든 화면 언어(한/영)를 전환할 수 있다

**추적** — REQ-WEB-065, REQ-WEB-066, REQ-WEB-067, REQ-WEB-068, REQ-WEB-070, REQ-WEB-072, REQ-WEB-015

### T10. 공지 확인

1. 최근 공지(카테고리, 제목, 요약, 게시일)를 확인한다
2. 전체 목록으로 넘어간다
3. 카테고리(전체·업데이트·점검 등)로 좁힌다
4. 항목을 선택해 공지 상세를 확인한다

**추적** — REQ-WEB-028, REQ-WEB-029, REQ-WEB-059, REQ-WEB-060

### T11. 관리자 진입·이탈

1. 관리자 계정으로 로그인해 관리자 진입점(전체 운영 현황 허브)에 도달한다
2. **게이트** — 관리자 권한이 없는 계정은 관리자 영역에 진입할 수 없다. 진입 시도는 감사 로그에 남는다
3. 관리자 대시보드·유저 계정 관리·배터리 운영 관리·공지사항 관리·감사 로그 사이를 오간다
4. 일반 사용자 영역으로 나가거나 로그아웃해 관리자 모드를 벗어난다

**추적** — REQ-WEB-101, REQ-WEB-102, REQ-WEB-103

### T12. 유저 계정 정지·해제·비밀번호 재설정

1. 이름 또는 이메일로 검색하고, 상태(전체·활성·정지)와 권한(전체·일반·관리자) 기준으로 유저 목록을 좁힌다
2. 유저를 선택해 기본 정보, 등록 배터리, 활동 로그를 확인한다
3. 이름·아이디·전화번호를 수정하고 저장하거나, 비밀번호 재설정 메일을 보낸다. 등록 배터리 수는 계산된 값이라 직접 고칠 수 없고, 권한은 웹에서 바꿀 수 없다
4. 정지 또는 해제를 요청한다
5. **게이트** — 사유를 입력해야 정지·해제가 실행된다. 사유 없이 정지·해제를 완료하는 경로는 없다
6. 변경 결과가 반영된다

**불변** — 유저 상태 변경과 정보 수정은 예외 없이 감사 로그에 기록된다

**추적** — REQ-WEB-110, REQ-WEB-111, REQ-WEB-112, REQ-WEB-113, REQ-WEB-114, REQ-WEB-115, REQ-WEB-116, REQ-WEB-117, REQ-WEB-118

### T13. 배터리 운영 상태 변경

3. 운영 상태(NORMAL·WATCH·BLOCKED)를 선택하고 관리자 메모를 입력한다
4. **게이트** — BLOCKED로 바꿀 때는 사유 입력이 필수다. 사유 없이 BLOCKED로 전환하는 경로는 없다

**불변** — 배터리 운영 상태와 관리자 메모 변경은 예외 없이 감사 로그에 기록된다

### T14. 공지 발행

3. **불변** — 감사 로그는 어떤 경로로도 수정하거나 삭제할 수 없다. 보존 안내만 제공된다

## 기능 영역

각 절은 화면이 아니라 기능의 묶음이다. 새 디자인은 이 묶음을 자유롭게 나누거나 합칠 수 있으나, 각 절의 정보와 동작은 어딘가에서 반드시 도달 가능해야 한다.

> F5는 결번이다. v3에 `devices` 화면이 구현돼 있으나 도달 경로가 없어 제외했다. 되살릴지는 별도 판단 사항이다.

### F1. 랜딩

**목적** — 서비스를 처음 만난 사람에게 무엇을 하는 서비스인지 알리고, 로그인 또는 가입으로 넘긴다.

**반드시 제공하는 정보**
- AI 열폭주 예측과 실시간 관제라는 핵심 가치
- 수집 대상 — 전압·전류·온도·SOC
- 제품 / 실시간 관제 / AI 이상탐지 / 문의 네 갈래의 소개
- 동작하는 관제 화면의 미리보기

**반드시 가능한 동작**
- 로그인 시작 → T1
- 가입 시작 → T1, F2
- 데모 확인
- 네 갈래 소개로 이동

**상태·예외**
- 로그인 정보가 틀렸을 때의 안내

**제약**
- 로그인 수단은 이메일과 Google 두 가지다. 관리자 진입 경로도 제공되어야 하며, 어디에 두는지는 자유다

**검수 체크리스트**
- [ ] 핵심 가치 4종이 모두 읽히는가
- [ ] 로그인·가입·데모 세 동작이 모두 가능한가
- [ ] 관리자 진입 경로가 있는가

**추적** — REQ-WEB-001, REQ-WEB-002, REQ-WEB-003, REQ-WEB-004, REQ-WEB-005, REQ-WEB-006, REQ-WEB-007, REQ-WEB-008

### F2. 회원가입

**목적** — 계정이 없는 사람이 이름·이메일·비밀번호·전화번호를 등록하고 이용약관에 동의해 새 계정을 만든다.

**반드시 제공하는 정보**
- 비밀번호 형식 요구사항(영문·숫자·특수문자 조합 8자 이상)과 입력 강도
- 이용약관·개인정보 처리방침 동의 요구
- 이미 계정이 있는 사람을 위한 로그인 복귀 경로

**반드시 가능한 동작**
- 이름, 이메일, 비밀번호, 전화번호 입력 → T1
- 이메일 중복 확인
- 이용약관 동의
- 가입 완료 → T1
- 기존 계정 로그인으로 돌아가기 → T1, F1

**상태·예외**
- 이메일이 이미 등록되어 있을 때의 안내
- 비밀번호가 형식 요구사항을 만족하지 못할 때의 안내
- 이용약관에 동의하지 않은 상태에서는 가입을 완료할 수 없다

**제약**
- 전화번호 입력은 필수다. v3 목업의 회원가입 정보 입력 조합에는 전화번호 입력이 시각적으로 없으나, 계정 찾기(F3)의 이메일 찾기가 이름·전화번호 대조로 본인을 확인하고 `docs/backend_contract.md`의 계정 데이터 모델과 REQ-WEB-009가 전화번호를 요구하므로 이를 따른다

**검수 체크리스트**
- [ ] 이름·이메일·비밀번호·전화번호 네 항목을 모두 입력받는가
- [ ] 이메일 중복 확인이 가능한가
- [ ] 이용약관 동의 없이는 가입을 완료할 수 없는가
- [ ] 로그인으로 돌아가는 경로가 있는가

**추적** — REQ-WEB-009, REQ-WEB-010

### F3. 계정 찾기

**목적** — 로그인 정보를 잊은 사람이 비밀번호를 재설정하거나 가입한 이메일을 확인해 로그인으로 되돌아간다.

**반드시 제공하는 정보**
- 비밀번호 재설정과 이메일 찾기 두 갈래
- 비밀번호 재설정 링크가 가입한 이메일로 발송된다는 안내
- 이메일 찾기는 이름·전화번호로 본인을 확인한다는 안내
- 확인된 이메일은 일부를 가린 형태로 제공된다

**반드시 가능한 동작**
- 로그인에서 계정 찾기로 이동 → T1, F1
- 비밀번호 재설정으로 전환하고 이메일을 입력해 재설정 링크 발송을 요청 → T1
- 이메일 찾기로 전환 → T1
- 이름과 전화번호로 본인 확인 후 마스킹된 이메일 확인 → T1
- 확인된 이메일로 로그인으로 돌아가기
- 언제든 로그인으로 돌아가기 → F1

**상태·예외**
- 입력한 이름·전화번호가 가입 정보와 일치하지 않을 때의 안내
- 재설정 링크 발송 완료 안내

**제약**
- 이메일 찾기 결과는 전체 이메일이 아니라 마스킹된 형태로만 제공한다

**검수 체크리스트**
- [ ] 비밀번호 재설정과 이메일 찾기 두 갈래가 모두 가능한가
- [ ] 이메일 찾기가 이름·전화번호 본인 확인을 거치는가
- [ ] 확인된 이메일이 마스킹되어 보이는가
- [ ] 로그인으로 돌아가는 경로가 있는가

**추적** — REQ-WEB-011, REQ-WEB-012, REQ-WEB-013

### F4. 실시간 관제

**목적** — 연결된 배터리 한 대의 현재 상태를 파악하고, 위험하면 즉시 차단으로 넘어간다.

**반드시 제공하는 정보**
- 연결된 배터리 식별자와 측정 세션 진행 여부
- 최종 이상점수(0–100 정수)와 4등급 판정, 그리고 4등급의 임계 구간
- 전압·전류·온도·SOC 현재값과 각각의 등급
- 네 지표의 최근 추이
- 위험도 구간별 배터리 분포
- 최근 이상 이벤트와 발생 시각
- 최근 공지
- 미확인 알림 건수와 이상 건수

**반드시 가능한 동작**
- 측정 대상 배터리 변경 → T2
- 릴레이 차단 진입 → T7
- 이상 근거 확인 → F8
- 알림 전체 확인 → F11
- 추세 전체 확인 → F9
- 공지 전체 확인 → F13
- 표시 지표를 전압·전류·온도·SOC 중에서 바꾸기

**상태·예외**
- 연결된 배터리 없음 — T0 게이트가 걸린 상태
- 디바이스 오프라인
- 데이터 수신 지연

**제약**
- 실시간 갱신 중 요소의 위치와 크기가 흔들리지 않아야 한다
- 이상점수와 4등급 판정은 항상 함께 읽혀야 한다. 점수만 단독으로 내보내지 않는다
- 4등급 임계 구간을 함께 보일 때는 4구간을 모두 보인다
- 상대 시간(예: "2일 전")은 저장된 문자열이 아니라 절대 시각으로부터 화면이 계산해서 보여준다. 서버는 상대 시간 문자열을 만들지 않는다

**검수 체크리스트**
- [ ] 정보 8종이 모두 도달 가능한가
- [ ] 동작 7종이 모두 가능한가
- [ ] 예외 3종의 표시가 정의돼 있는가
- [ ] 등급 구간이 4개로 표시되는가 (3구간은 v3 버그다)
- [ ] 시각이 상대 시간 문자열이 아니라 절대 시각 기준으로 계산되는가

**추적** — REQ-WEB-019, REQ-WEB-020, REQ-WEB-021, REQ-WEB-022, REQ-WEB-023, REQ-WEB-024, REQ-WEB-025, REQ-WEB-027, REQ-WEB-028, REQ-WEB-029, REQ-WEB-047

### F6. 배터리 자산관리

**목적** — 사용자가 소유한 배터리 자산을 등록·조회·수정하고, 측정할 대상을 선택해 연결한다.

**반드시 제공하는 정보**
- 저장된 배터리 목록과 총 개수
- 각 배터리의 식별자(라벨), 배터리 종류(chemistry), 직렬 셀 수, 제조사·모델(입력된 경우), 자산에 고정된 측정 모드
- 각 배터리의 현재 연결 여부
- 각 배터리의 최근 측정값(SOC, 이상점수, 마지막 측정 시각) — 아직 측정 이력이 없으면 그 사실이 드러나야 한다
- 측정 모드 기준으로 좁힌 목록 결과
- 정렬 기준(최근 측정순 · 이상점수 높은순 · SOC 낮은순)과 현재 선택된 기준
- 연결 확인 단계에서 선택한 배터리의 식별자·모델, "한 번에 하나만 연결되며 기존 연결은 해제된다"는 안내
- 신규 등록 입력 중 필수·선택 구분, 등록 완료 시 battery_id가 발급되고 측정 모드가 자산에 고정된다는 안내
- 정보 수정 단계에서 battery_id와 측정 모드는 바꿀 수 없다는 안내

**반드시 가능한 동작**
- 새 배터리 등록 → T3
- 저장된 배터리를 선택해 연결 확인으로 진입 → T2
- 측정 모드 기준으로 목록 좁히기
- 정렬 기준 바꾸기
- 배터리 정보(이름·제조사·모델·직렬 셀 수·메모) 수정 → T3
- 선택한 배터리의 상세·이력 확인 → F7
- 연결 확인에서 취소하거나, 확인 대신 상세·이력으로 먼저 이동 → F7

**상태·예외**
- 저장된 배터리가 하나도 없을 때
- 아직 한 번도 측정되지 않은 배터리의 최근 측정값 표시
- 연결하려는 배터리의 진단기가 오프라인일 때 — 연결을 중단하고 사유를 알린다
- 이미 다른 배터리가 연결되어 있어 연결하면 그 연결이 해제될 때

**제약**
- 이 영역은 배터리가 연결되지 않은 상태(T0 게이트)에서 일반 사용자에게 유일하게 열려 있는 곳이다. 나머지 8개 목적지는 모두 잠긴다
- 배터리 종류(chemistry)는 등록 시 필수 입력이다. 채우지 않으면 등록을 완료할 수 없다
- 측정 모드는 등록된 뒤 자산에 고정되며 어떤 경로로도 수정할 수 없다. 모드를 바꾸려면 새 자산을 등록한다
- battery_id는 발급된 뒤 어떤 경로로도 바뀌지 않는다

**검수 체크리스트**
- [ ] 목록·등록·수정·연결 네 동작이 모두 가능한가
- [ ] 배터리 종류를 채우지 않으면 등록이 막히는가
- [ ] 재연결 시 측정 모드 재선택 없이 이전 이력이 이어지는가
- [ ] 정렬·모드 좁히기가 모두 동작하는가
- [ ] 배터리 미연결 상태에서 이 영역만 열려 있는가

### F7. 배터리 상세·이력

**목적** — 등록된 배터리 한 대의 기본 정보, 현재 상태, 측정 이력을 확인한다.

**반드시 제공하는 정보**
- 배터리 식별자(battery_id), 라벨, 소유자, 배터리 종류, 직렬 셀 수, 제조사·모델(입력된 경우), 자산에 고정된 측정 모드
- 현재 전압·전류·온도·SOC와 현재 이상점수·등급
- 최근 30일 이상점수 추세
- 기간(24시간·7일·30일)별 전압·전류·온도·SOC 추세와, 다른 배터리·세션과 겹쳐 보는 비교
- 과거 측정 세션 목록 — 세션 식별자, 측정 기간, 세션 중 최고 이상점수와 등급, 세션 상태
- 이 화면에서 바로 측정을 시작하는 진입점

**반드시 가능한 동작**
- 배터리 자산관리 목록으로 돌아가기 → F6
- 이 배터리로 측정 시작(연결 확인으로 진입) → T2
- 추세 기간 전환과 비교 대상 추가 → T5
- 과거 세션 항목에서 해당 이벤트 이력으로 이동 → F10
- 이 배터리의 이상 근거·건강도 확인 → F8

**상태·예외**
- 아직 측정 이력이 없는 배터리
- 과거 측정 세션이 없는 배터리
- 진단기가 오프라인이라 이 화면에서 바로 측정을 시작할 수 없을 때

**제약**
- 셀 단위 데이터는 제공하지 않는다. 측정하는 온도는 접촉 온도와 IR 표면 온도 두 값뿐이며, 셀별 온도나 그 분포를 보여주는 정보는 범위 밖이다
- battery_id는 화면에 노출하되 어떤 경로로도 수정할 수 없다
- 측정 모드는 이 화면에서 바꿀 수 없다. 모드를 바꾸려면 배터리 자산관리(F6)에서 새 자산을 등록한다

**검수 체크리스트**
- [ ] 기본 정보·현재 상태·추세·과거 세션 네 정보 묶음이 모두 도달 가능한가
- [ ] 기간 3종(24시간/7일/30일) 전환이 가능한가
- [ ] 셀 단위 온도나 그 분포가 어디에도 노출되지 않는가
- [ ] 과거 세션에서 이벤트 이력으로 이동할 수 있는가

**추적** — REQ-WEB-040, REQ-WEB-041

### F8. 이상 탐지

**목적** — 연결된 배터리의 이상 탐지 결과를 종합적으로 확인하고, 점수에 기여한 근거와 배터리 건강도를 함께 판단 자료로 확인한다.

**반드시 제공하는 정보**
- 모델 동작 상태(정상 동작·저하·중단)
- 활성 이상 이벤트 수, 오늘 발생한 이상 수, 오늘 최고 이상점수와 발생 시각
- 위험도 구간별(정상·주의·경고·위험) 배터리 분포 — 이 계정이 소유한 배터리 기준, 4구간 모두 표시(0건인 구간도 표시)
- 이상점수에 기여한 요인과 기여도(dT/dt, I_smooth, V_drop, SOC_delta 등), 어느 배터리의 어느 시점 점수에 대한 근거인지
- 건강도 — SOH, RUL, 누적 사이클, 내부 저항, 만료 임박 여부. 산출된 값이 없으면 그 사실이 드러나야 한다
- 최근·활성 이상 이벤트 목록 — 배터리 식별자, 발생 시각, 이상점수
- 이상 이벤트 상세 — 발생 시각·원인·조치를 포함

**반드시 가능한 동작**
- 활성 이상 이벤트 항목을 선택하거나 더 보기를 실행해 상세 확인
- 전체 이벤트 이력으로 이동 → F10
- 실시간 관제로 돌아가기 → F4

**상태·예외**
- 모델 동작 상태가 저하되었거나 중단됐을 때
- 활성 이상 이벤트가 하나도 없을 때
- 건강도 산출값이 아직 없을 때

**제약**
- 위험도 구간은 4구간을 모두 표시한다. 0건인 구간도 빠뜨리지 않는다
- 기여 요인의 기여도는 서로 독립이며 합이 1이 되도록 정규화하지 않는다. 점수를 낮추는 방향의 기여는 표시하지 않는다
- 위험도 분포는 이 계정이 소유한 배터리만 집계한다

**검수 체크리스트**
- [ ] 모델 상태·활성 건수·오늘 발생 건수·오늘 최고점수 네 요약이 모두 도달 가능한가
- [ ] 위험도 분포가 4구간 모두 표시되는가(0건 포함)
- [ ] 기여 요인 근거를 확인할 수 있는가
- [ ] 건강도 산출값이 없을 때 그 사실이 드러나는가
- [ ] 활성 이상 이벤트 상세(발생 시각·원인·조치)를 확인할 수 있는가

**추적** — REQ-WEB-026, REQ-WEB-042, REQ-WEB-043, REQ-WEB-044, REQ-WEB-045

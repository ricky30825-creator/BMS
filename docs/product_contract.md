# 셀가드 제품 계약서

이 문서는 셀가드 배터리 열폭주 관제 서비스가 **무엇을 하는지**만 기술한다. 어떻게 생겼는지는 기술하지 않는다. 어떤 시각 방향으로 다시 디자인하더라도 이 문서의 내용은 그대로 유지되어야 한다.

기준: `설계 산출물/셀가드 프로토타입_v3.html` (2026-08-06 확인).

## 0. 이 문서를 받은 실행자에게

### 막히면 멈추고 물어본다

다음 상황에서는 추측으로 채우지 말고 **작업을 멈추고 사용자에게 질문한다.**

- "고정"으로 적힌 항목인데 내용이 불충분해 그대로 옮길 수 없을 때
- 이 문서에 없는 정보나 동작을 추가해야 할 것 같을 때
- 부록 A의 목업 데이터에 없는 값이 필요할 때
- 하려는 디자인이 `**게이트**` 또는 `**불변**`과 충돌할 때

**묻지 말고 스스로 결정한다** — 아래 판정표의 "자유" 항목 전부.

**물을 때의 형식** — 무엇이 왜 막혔는지 한두 문장 + 선택지 + 잠정 추천. 답을 받기 전에 그 부분을 추측으로 채워 진행하지 않는다. 대신 답에 의존하지 않는 나머지 작업은 마저 끝내고 질문을 함께 올린다.

아래 `## F로 시작하는 절`은 **기능 영역**이지 화면이 아니다. 한 영역이 새 디자인에서 화면 하나일 수도, 둘로 나뉠 수도, 다른 영역과 합쳐질 수도 있다.

### 도달 가능성

일반 사용자는 아래 10개 목적지에 도달할 수 있어야 한다 — 실시간 관제, 배터리 자산관리, 이상 탐지, 추세, 이벤트 이력, 알림 센터, 공지사항, 릴레이 제어, 설정, 보조배터리 진단. 관리자는 여기에 관리자 통합 관제, 유저 계정 관리, 배터리 운영 관리, 공지사항 관리, 감사 로그 5개 목적지가 더해진다 — 이벤트 추이(F20)는 별도 목적지가 아니라 관리자 통합 관제 안에서 도달하므로 이 수에 포함하지 않는다.

**이동 수단의 구조는 자유다.** 몇 단계로 묶든, 어떤 형태로 제공하든 상관없다. 도달 가능하기만 하면 된다. 다만 T0 게이트가 걸린 상태에서는 배터리 자산관리를 제외한 9개가 잠겨야 한다.

> REQ-WEB-018과 REQ-WEB-073은 v3 실측 기준이라 **9개 목적지 / 잠기는 8개**를 규정한다. 보조배터리 진단(F21)이 새로 더해져 **10개 / 잠기는 9개**가 됐다. 두 요구사항이 완화된 것이 아니라 대상이 하나 늘어난 것이다. 보조배터리 진단도 연결된 배터리를 전제하므로 T0 게이트를 똑같이 받는다.

**추적** — REQ-WEB-018

### 이상점수와 상태 등급

AI가 산출하는 Final Score는 0.0–1.0이며, 표시할 때는 100배한 정수를 쓴다.

| 등급 | Final Score | 표시값 |
|---|---|---|
| 정상 | 0.0–0.3 | 0–29 |
| 주의 | 0.3–0.6 | 30–59 |
| 경고 | 0.6–0.8 | 60–79 |
| 위험 | 0.8–1.0 | 80–100 |

원본 데이터를 그대로 보여주는 곳에서는 환산하지 않은 0.0–1.0 값을 쓴다. 100배한 정수는 사람이 읽는 표시에만 쓴다.

등급은 언제나 위 표로 계산한다. 어딘가에 미리 적어둔 등급 값을 그대로 보여주지 않는다. 계산 결과와 어긋난 등급이 남아 있으면 계산이 이긴다.

### 용어

| 용어 | 뜻 |
|---|---|
| Final Score | AE Score와 Informer Score를 가중합한 최종 이상점수 |
| AE Score | LSTM-AutoEncoder의 재구성 오차 기반 현재 이상점수 |
| Informer Score | Informer의 예측 오차 기반 미래 위험점수 |
| `device_id` | 측정 **장비**(라즈베리파이) 식별자 |
| 진단기 | `device_id`가 가리키는 측정 장비를 부르는 이 문서의 표기. "디바이스"와 같은 대상을 가리키며, "디바이스 음성 안내"·"디바이스 상태 화면"처럼 이미 굳어진 이름에서만 "디바이스"를 그대로 쓴다 |
| `battery_id` | 측정 **대상**(셀·보조배터리) 식별자. 자산으로 등록해 재연결 시 이력을 잇는다 |
| 측정 모드 | 1 외부 셀 / 2 보조배터리. 동시 활성 불가(인터락) |
| Kill-Switch | 위험 등급에서 전원을 물리적으로 차단하는 릴레이 제어 |
| Fail-Safe | 모드 1 압력 또는 모드 2 가스 임계 초과 시 AI 판정과 무관하게 즉시 차단하는 독립 안전계층. 음향은 도입하지 않는다 |
| 열화 등급 | 보조배터리의 수명 상태를 나타내는 등급(양호·주의·열화 의심·기준선 수집 중). **이상점수 4등급과 다른 축이다** — 열화는 수명, 이상점수는 열폭주 위험이다. 양쪽에 "주의"가 있으므로 어느 축인지 항상 함께 읽혀야 한다 (F21) |
| 기준선 | 한 보조배터리 자산의 첫 정밀 용량 테스트에서 뽑아낸 Wh. 이후 측정은 이 값 대비 상대값으로 읽는다 (F21) |
| 게이트 | 다음 단계로 넘어가기 전에 반드시 통과해야 하는 조건. 이를 건너뛰는 경로가 존재하면 안 된다 |
| 불변 | 어떤 경로로도 깨지면 안 되는 조건 |
| T0, T1 … | 과업 플로우의 번호다. 이 문서의 "과업 플로우" 절에 정의된다 |
| F1, F2 … | 기능 영역의 번호다. 이 문서의 "기능 영역" 절에 정의된다. F5는 결번이다 |

### 하지 말 것

- 4단계 등급의 임계값을 바꾸지 않는다
- 이상점수를 정수 아닌 형식으로 표시하지 않는다
- 이상점수 범례를 3구간(정상 0~39 / 주의 40~69 / 위험 70 이상)으로 쓰지 않는다 — v3의 버그이며 4등급이 정본이다
- 안전 게이트를 생략하지 않는다. 재인증·사유 입력 없는 차단 경로를 만들지 않는다
- 배터리 미연결 상태에서 잠긴 영역을 열어주지 않는다
- 관리자 전용 기능을 일반 사용자 영역에 노출하지 않는다
- 측정 모드 인터락(동시 활성 불가)을 무시하지 않는다
- 부록 A에 없는 수치를 지어내지 않는다 — 단 하나의 예외는 추세 파형이며, 조건은 부록 A의 "추세 파형은 예외다"에 있다
- 열화 등급과 이상점수 4등급을 합산하거나 하나의 값으로 합쳐 보이지 않는다 (F21)
- 보조배터리의 누적 사이클·잔존수명·내부 저항에 값을 채우지 않는다 — 측정 모드 2에서는 산출할 수 없다 (F21)
- 가정한 효율값과 떨어진 자리에 절대 SOH를 보이지 않는다 (F21)

## 과업 플로우

화면 이동이 아니라 순서와 게이트를 고정한다. 각 단계를 어느 영역에서 수행하는지는 지정하지 않는다.

### T0. 진입 잠금

**게이트** — 일반 사용자는 측정 대상 배터리를 연결하기 전까지 T3(자산 등록·선택)을 제외한 모든 과업에 진입할 수 없다. 잠긴 대상은 선택해도 이동하지 않으며, 잠겨 있다는 사실과 푸는 방법이 보여야 한다.

로그인 직후 도착지는 배터리 자산관리(F6)다. 관리자는 이 게이트를 받지 않는다.

**불변** — 배터리가 연결되지 않은 상태에서 F4·F8·F9·F10·F11·F12·F13·F14·F21에 도달하는 경로는 존재할 수 없다.

**추적** — REQ-WEB-073

### T1. 가입·로그인·계정 찾기

1. 로그인 절차를 시작한다
2. 이메일과 비밀번호로 로그인하거나, 관리자 계정으로 로그인하거나, Google 계정으로 로그인한다
3. 계정이 없으면 가입으로 넘어간다 — 이름, 이메일(중복 확인), 비밀번호, 전화번호를 입력하고 이용약관에 동의해 가입을 완료한다. 언제든 기존 계정 로그인으로 되돌아갈 수 있다
4. 이메일이나 비밀번호가 기억나지 않으면 계정 찾기로 넘어간다 — 가입한 이메일로 비밀번호 재설정 링크를 받거나, 이름과 전화번호로 본인 확인을 거쳐 마스킹된 이메일을 확인한다
5. 로그인한 뒤에는 언제든 로그아웃해 세션을 종료할 수 있다

**추적** — REQ-WEB-003, REQ-WEB-005, REQ-WEB-006, REQ-WEB-007, REQ-WEB-008, REQ-WEB-009, REQ-WEB-010, REQ-WEB-011, REQ-WEB-012, REQ-WEB-013, REQ-WEB-014

### T2. 측정 시작·종료

1. 저장된 배터리를 확인한다 — 측정 모드로 범위를 좁히고, 정렬 기준(최근 측정순·이상점수 높은순·SOC 낮은순)을 고를 수 있어야 한다
2. 대상을 선택한다
3. **게이트** — 한 번에 하나만 연결되며 기존 연결은 해제된다는 사실을 알리고 확인을 받는다
4. 측정 세션이 시작되고 실시간 관제 정보(F4)에 반영된다
5. 측정 세션을 사용자가 직접 끝내는 동작은 없다. 데이터 수신이 끊기거나, 다른 배터리를 연결하거나, 배터리가 운영 차단되면 서버가 세션을 끝내고, 그 사실이 전달되면 T0의 잠금 상태로 되돌아간다

3에서 확인 대신 취소하거나, 선택한 배터리의 상세·이력(F7)으로 먼저 갈 수 있어야 한다.

**실패 경로** — 진단기가 오프라인이면 3에서 중단하고 사유를 알린다
**불변** — 게이트 3을 건너뛰고 세션을 시작하는 경로는 존재할 수 없다

**추적** — REQ-WEB-032, REQ-WEB-033, REQ-WEB-034, REQ-WEB-039

### T3. 배터리 자산 등록·수정

1. 새 배터리 등록을 시작한다
2. 배터리 이름, 측정 모드, 제조사(선택), 모델(선택), 직렬 셀 수(선택)를 입력한다
3. **게이트** — 배터리 종류(`chemistry`)는 필수 입력이다. 채우지 않으면 등록을 완료할 수 없다
4. 등록하면 `battery_id`가 발급되고 측정 모드가 자산에 고정된다
5. 이미 등록된 배터리는 정보를 불러와 이름·제조사·모델·직렬 셀 수·메모를 수정하고 저장할 수 있다. 측정 모드는 자산에 고정되어 등록 후에는 바뀌지 않으며, `battery_id`도 어떤 경로로도 바뀌지 않는다

**추적** — REQ-WEB-036, REQ-WEB-037, REQ-WEB-038

### T4. 이상 징후 확인 → 근거 확인

1. 현재 이상점수와 정상·주의·경고·위험 구간, 점수 추세를 확인한다
2. 더 자세한 확인이 필요하면 이상 탐지 확인으로 넘어간다
3. 활성 이상 이벤트 수, 오늘 발생한 이상 수, 최고 이상점수, 모델 동작 상태를 확인한다
4. 이상점수에 기여한 요인(V_drop, dT/dt, I_smooth 등)을 근거로 확인한다
5. 건강도(SOH, RUL, 누적 사이클, 내부 저항)를 함께 확인한다
6. 이상 이벤트 항목을 선택하거나 더 보기를 실행해 발생 시각·원인·조치를 포함한 상세를 확인한다

**추적** — REQ-WEB-021, REQ-WEB-022, REQ-WEB-042, REQ-WEB-043, REQ-WEB-044, REQ-WEB-045

### T5. 추세·이력 조회 및 내보내기

1. 저장된 배터리에서 상세·이력으로 넘어가 기본 정보, 현재 상태, 최근 측정값을 확인한다
2. 과거 측정 세션(세션 ID, 시간, 상태, 이상점수)을 확인한다
3. 추세를 살핀다 — 24시간·7일·30일 기간을 전환하고, 온도·전압 등 표시 지표를 바꾸고, 비교 추가로 다른 배터리·세션을 겹쳐 본다
4. 이벤트 이력에서 검색어로 좁히고, 상태 기준으로 필터링하고, 페이지를 넘긴다
5. 이벤트 항목을 선택해 상세와 관련 센서값을 확인한다
6. CSV는 100ms Raw 센서 행으로, PDF는 집계 추세 보고서로 내보낸다. Raw CSV 1시간 초과 범위는 비동기 작업 완료 후 다운로드한다

**추적** — REQ-WEB-040, REQ-WEB-041, REQ-WEB-035, REQ-WEB-046, REQ-WEB-047, REQ-WEB-048, REQ-WEB-049, REQ-WEB-050, REQ-WEB-051, REQ-WEB-052, REQ-WEB-053, REQ-WEB-054, REQ-WEB-055

### T6. 알림 수신 → 확인(Ack)

1. 새 알림이 오면 미확인 알림을 연다
2. 인앱·카카오 알림 이력, 발생 시간, 확인 상태를 확인한다
3. 개별 항목을 확인(Ack) 처리해 대응 확인 상태를 남기거나, 모두 확인으로 미확인 알림을 한 번에 처리한다
4. 전체 이력이 필요하면 알림 센터로 넘어간다

**추적** — REQ-WEB-016, REQ-WEB-056, REQ-WEB-057, REQ-WEB-058, REQ-WEB-027

### T7. 위험 제어 — 릴레이 차단·복구

1. 현재 회로 상태(정상 연결 / 차단됨)를 확인한다
2. 차단 또는 복구를 요청한다
3. **서버 자동 승인 게이트** — 재인증·사유·권한·소유권·디바이스·interlock을 서버가 즉시 검증한다. 관리자 사람이 따로 승인하는 대기 단계는 없다
4. 서버가 승인한 뒤에만 실행·감사 기록·상태 이벤트가 발생하고, 승인/거부 결과와 바뀐 회로 상태가 보인다

**불변** — 서버 승인 전에 릴레이 상태·interlock·감사 로그를 변경하는 경로는 존재할 수 없다

### T8. 자동 차단(Fail-Safe) 수신 대응

1. 서버 `relay.autoCut` Fail-Safe 이벤트를 수신했을 때만 즉시 알림이 뜬다 — trigger code, 대표 온도(접촉/IR 중 큰 값), 대상 배터리, 회로가 이미 차단된 상태임을 함께 확인한다
2. 확인을 눌러 알림을 닫는다. 이후 릴레이 제어(F12)에서 현재 회로 상태를 다시 확인할 수 있다

이 흐름은 승인 절차가 없다 — Fail-Safe는 AI 판정이나 사용자 승인과 무관하게 서버가 이미 실행한 차단을 통보만 한다. AI 위험 등급이나 프론트 임계 비교는 이 자동 차단 통보를 열 수 없다.

**추적** — REQ-WEB-064

3. **게이트** — 두 진단 모두, 부하를 걸어 배터리를 의도적으로 발열시킨다는 사실과 소요 시간을 알리고 확인을 받아야 실행된다. 확인 없이 실행하는 경로는 존재할 수 없다
4. **게이트** — 정밀 용량 테스트는 추가로, 정격 용량이 등록되어 있어야 하고 완충 상태임을 확인받아야 실행된다. 시작 잔량이 100%가 아니면 결과는 건강도가 아니다
5. 진단이 진행되는 동안 현재 단계와 목표 전류, 남은 시간 추정을 확인한다
6. 진행 중인 진단은 언제든 중단할 수 있다. 중단에는 재인증도 사유 입력도 요구하지 않는다
7. 완료된 결과를 확인하고, 과거 진단 이력과 비교한다

**실패 경로** — 진단기가 오프라인이거나 릴레이가 차단 상태면 3에서 중단하고 사유를 알린다

**불변** — 자동 차단(Fail-Safe)은 진단보다 우선한다. 안전 조건이 걸리면 진단 절차와 무관하게 개입하며, 그때 부하를 먼저 0으로 내린 다음 회로를 차단한다. 이 순서가 뒤바뀌는 경로는 존재할 수 없다
**불변** — 완충 확인을 거치지 않은 결과, 그리고 중단된 부분 결과를 건강도로 쓰는 경로는 존재할 수 없다

**추적** — REQ-WEB-137, REQ-WEB-138, REQ-WEB-139, REQ-WEB-140, REQ-WEB-141

## 기능 영역

각 절은 화면이 아니라 기능의 묶음이다. 새 디자인은 이 묶음을 자유롭게 나누거나 합칠 수 있으나, 각 절의 정보와 동작은 어딘가에서 반드시 도달 가능해야 한다.

> F5는 결번이다. v3에 `devices` 화면이 구현돼 있으나 도달 경로가 없어 제외했다. 되살릴지는 별도 판단 사항이다.

### F4. 실시간 관제

**목적** — 연결된 배터리 한 대의 현재 상태를 파악하고, 위험하면 즉시 차단으로 넘어간다.

**반드시 제공하는 정보**
- 연결된 배터리 식별자와 측정 세션 진행 여부
- 최종 이상점수(0–100 정수)와 4등급 판정, 그리고 4등급의 임계 구간
- 전압·전류·온도·SOC 현재값과 각각의 등급 — 등급은 지표마다 정해진 임계값이 있어야 매길 수 있으며, 임계값이 아직 없는 지표는 값만 보이고 등급은 비어 있다
- 네 지표의 최근 추이
- 최근 공지

**반드시 가능한 동작**
- 측정 대상 배터리 변경 → T2
- 릴레이 차단 진입 → T7
- 이상 근거 확인 → F8
- 추세 전체 확인 → F9
- 공지 전체 확인 → F13
- 표시 지표를 전압·전류·온도·SOC 중에서 바꾸기

**상태·예외**
- 연결된 배터리 없음 — T0 게이트가 걸린 상태
- 진단기 오프라인
- 데이터 수신 지연
- 지표 임계값이 아직 없어 등급을 매길 수 없을 때(현재 전압·전류·SOC) — 등급 없이 값만 보인다는 사실이 드러나야 한다

**제약**
- 실시간 갱신 중 요소의 위치와 크기가 흔들리지 않아야 한다
- 이상점수와 4등급 판정은 항상 함께 읽혀야 한다. 점수만 단독으로 내보내지 않는다
- 4등급 임계 구간을 함께 보일 때는 4구간을 모두 보인다
- 상대 시간(예: "2일 전")은 저장된 문자열이 아니라 절대 시각으로부터 화면이 계산해서 보여준다. 서버는 상대 시간 문자열을 만들지 않는다
- 네 지표 모두 등급을 매기는 것이 목표이지만, 현재 임계값이 정해진 지표는 온도뿐이다. 전압·전류·SOC는 임계값 미정으로 등급이 비어 있으며, 정해지는 대로 채워진다 — 이는 고정 요구사항이 완화된 것이 아니라 현재 데이터 상태다

**검수 체크리스트**
- [ ] 정보 5종이 모두 도달 가능한가
- [ ] 동작 6종이 모두 가능한가
- [ ] 예외 4종의 표시가 정의돼 있는가
- [ ] 등급 구간이 4개로 표시되는가 (3구간은 v3 버그다)
- [ ] 시각이 상대 시간 문자열이 아니라 절대 시각 기준으로 계산되는가

### F6. 배터리 자산관리

**목적** — 사용자가 소유한 배터리 자산을 등록·조회·수정하고, 측정할 대상을 선택해 연결한다.

**반드시 제공하는 정보**
- 저장된 배터리 목록과 총 개수
- 각 배터리의 식별자(라벨), 배터리 종류(chemistry), 직렬 셀 수, 제조사·모델(입력된 경우), 자산에 고정된 측정 모드
- 각 배터리의 현재 연결 여부
- 각 배터리의 최근 측정값(SOC, 이상점수, 마지막 측정 시각) — 아직 측정 이력이 없으면 그 사실이 드러나야 한다
- 측정 모드 기준으로 좁힌 목록 결과
- 정렬 기준(최근 측정순 · 이상점수 높은순 · SOC 낮은순)과 현재 선택된 기준
- 연결 확인 단계에서 선택한 배터리의 식별자·모델, "한 번에 하나만 연결되며 기존 연결은 해제된다"는 안내
- 연결하려는 배터리를 담당하는 진단기의 식별자, 통신 상태(정상·지연·오프라인), 마지막 수신 시각 — 진단기가 오프라인일 때의 예외를 판단하는 근거다
- 신규 등록 입력 중 필수·선택 구분, 등록 완료 시 battery_id가 발급되고 측정 모드가 자산에 고정된다는 안내
- 정보 수정 단계에서 battery_id와 측정 모드는 바꿀 수 없다는 안내

**반드시 가능한 동작**
- 새 배터리 등록 → T3
- 저장된 배터리를 선택해 연결 확인으로 진입 → T2
- 측정 모드 기준으로 목록 좁히기
- 정렬 기준 바꾸기
- 배터리 정보(이름·제조사·모델·직렬 셀 수·메모) 수정 → T3
- 선택한 배터리의 상세·이력 확인 → F7
- 연결 확인에서 취소하거나, 확인 대신 상세·이력으로 먼저 이동 → F7

**상태·예외**
- 저장된 배터리가 하나도 없을 때
- 아직 한 번도 측정되지 않은 배터리의 최근 측정값 표시
- 연결하려는 배터리의 진단기가 오프라인일 때 — 연결을 중단하고 사유를 알린다
- 이미 다른 배터리가 연결되어 있어 연결하면 그 연결이 해제될 때

**제약**
- 이 영역은 배터리가 연결되지 않은 상태(T0 게이트)에서 일반 사용자에게 유일하게 열려 있는 곳이다. 나머지 8개 목적지는 모두 잠긴다
- 배터리 종류(chemistry)는 등록 시 필수 입력이다. 채우지 않으면 등록을 완료할 수 없다
- 측정 모드는 등록된 뒤 자산에 고정되며 어떤 경로로도 수정할 수 없다. 모드를 바꾸려면 새 자산을 등록한다
- battery_id는 발급된 뒤 어떤 경로로도 바뀌지 않는다

**검수 체크리스트**
- [ ] 목록·등록·수정·연결 네 동작이 모두 가능한가
- [ ] 배터리 종류를 채우지 않으면 등록이 막히는가
- [ ] 재연결 시 측정 모드 재선택 없이 이전 이력이 이어지는가
- [ ] 정렬·모드 좁히기가 모두 동작하는가
- [ ] 배터리 미연결 상태에서 이 영역만 열려 있는가

### F7. 배터리 상세·이력

**목적** — 등록된 배터리 한 대의 기본 정보, 현재 상태, 측정 이력을 확인한다.

**반드시 제공하는 정보**
- 배터리 식별자(battery_id), 라벨, 소유자, 배터리 종류, 직렬 셀 수, 제조사·모델(입력된 경우), 자산에 고정된 측정 모드
- 현재 전압·전류·온도·SOC와 현재 이상점수·등급
- 최근 30일 이상점수 추세
- 기간(24시간·7일·30일)별 전압·전류·온도·SOC 추세
- 과거 측정 세션 목록 — 세션 식별자, 측정 기간, 세션 중 최고 이상점수와 등급, 세션 상태
- 이 화면에서 바로 측정을 시작하는 진입점

**반드시 가능한 동작**
- 배터리 자산관리 목록으로 돌아가기 → F6
- 이 배터리로 측정 시작(연결 확인으로 진입) → T2
- 추세 기간 전환과 비교 대상 추가 → T5
- 과거 세션 항목에서 해당 이벤트 이력으로 이동 → F10
- 이 배터리의 이상 근거·건강도 확인 → F8

**상태·예외**
- 아직 측정 이력이 없는 배터리
- 과거 측정 세션이 없는 배터리
- 진단기가 오프라인이라 이 화면에서 바로 측정을 시작할 수 없을 때

**제약**
- 셀 단위 데이터는 제공하지 않는다. 측정하는 온도는 접촉 온도와 IR 표면 온도 두 값뿐이며, 셀별 온도나 그 분포를 보여주는 정보는 범위 밖이다
- 대시보드 온도 영역은 `온도 (°C)`와 숫자만 표시한다. 값은 유효한 접촉 온도와 IR 표면 온도 중 큰 값이며, 둘 다 없으면 `—`로 표시한다. 선택된 센서 소스는 화면에 별도 표기하지 않는다
- 전류·전력 정본 부호는 양수=충전, 음수=방전, 0=대기다. 화면은 절댓값과 방향 라벨을 함께 보여준다
- 모드 2 SOC는 측정 세션 시작을 100%로 본 상대값이며 `상대 SOC · 측정 시작=100%`를 숨기지 않는다
- battery_id는 화면에 노출하되 어떤 경로로도 수정할 수 없다
- 측정 모드는 이 화면에서 바꿀 수 없다. 모드를 바꾸려면 배터리 자산관리(F6)에서 새 자산을 등록한다

**검수 체크리스트**
- [ ] 기본 정보·현재 상태·추세·과거 세션 네 정보 묶음이 모두 도달 가능한가
- [ ] 기간 3종(24시간/7일/30일) 전환이 가능한가
- [ ] 셀 단위 온도나 그 분포가 어디에도 노출되지 않는가
- [ ] 과거 세션에서 이벤트 이력으로 이동할 수 있는가

### F8. 이상 탐지

**목적** — 연결된 배터리의 이상 탐지 결과를 종합적으로 확인하고, 점수에 기여한 근거와 배터리 건강도를 함께 판단 자료로 확인한다.

**반드시 제공하는 정보**
- 모델 동작 상태(정상 동작·저하·중단)
- 활성 이상 이벤트 수, 오늘 발생한 이상 수, 오늘 최고 이상점수와 발생 시각
- 위험도 구간별(정상·주의·경고·위험) 배터리 분포 — 이 계정이 소유한 배터리 기준, 4구간 모두 표시(0건인 구간도 표시)
- 이상점수에 기여한 요인과 기여도(dT/dt, I_smooth, V_drop, SOC_delta 등), 어느 배터리의 어느 시점 점수에 대한 근거인지
- 건강도 — SOH, RUL, 누적 사이클, 내부 저항. 산출된 값이 없으면 그 사실이 드러나야 한다
- 최근·활성 이상 이벤트 목록 — 배터리 식별자, 발생 시각, 이상점수
- 이상 이벤트 상세 — 발생 시각·원인·조치를 포함

**반드시 가능한 동작**
- 활성 이상 이벤트 항목을 선택하거나 더 보기를 실행해 상세 확인
- 전체 이벤트 이력으로 이동 → F10
- 실시간 관제로 돌아가기 → F4

**상태·예외**
- 모델 동작 상태가 저하되었거나 중단됐을 때
- 활성 이상 이벤트가 하나도 없을 때
- 건강도 산출값이 아직 없을 때
- 배터리 미연결로 잠긴 상태 (T0 게이트)

**제약**
- 위험도 구간은 4구간을 모두 표시한다. 0건인 구간도 빠뜨리지 않는다
- 기여 요인의 기여도는 서로 독립이며 합이 1이 되도록 정규화하지 않는다. 점수를 낮추는 방향의 기여는 표시하지 않는다
- 위험도 분포는 이 계정이 소유한 배터리만 집계한다

**검수 체크리스트**
- [ ] 모델 상태·활성 건수·오늘 발생 건수·오늘 최고점수 네 요약이 모두 도달 가능한가
- [ ] 위험도 분포가 4구간 모두 표시되는가(0건 포함)
- [ ] 기여 요인 근거를 확인할 수 있는가
- [ ] 건강도 산출값이 없을 때 그 사실이 드러나는가
- [ ] 활성 이상 이벤트 상세(발생 시각·원인·조치)를 확인할 수 있는가

### F9. 추세

**목적** — 배터리의 전압·전류·온도·SOC 추이를 기간별로 살펴보고, 필요하면 다른 배터리와 겹쳐 비교하거나 조회 결과를 내보낸다.

**반드시 제공하는 정보**
- 기간 선택 상태(24시간·7일·30일)
- 전압·전류·온도·SOC 네 지표 각각의 추이와 현재값
- 각 시점을 짚었을 때의 시각과 값
- 비교 대상으로 추가한 배터리와 추가로 선택 가능한 배터리 목록(최대 5개)

**반드시 가능한 동작**
- 기간 전환(24시간·7일·30일)
- 비교 대상 배터리 추가·해제(최대 5개)
- CSV로 내보내기(확인 절차를 거쳐 실행) — 선택한 배터리·기간의 100ms Raw 센서 행. 1시간 이하는 즉시 스트리밍, 초과는 비동기 작업
- 조회 결과를 PDF로 내보내기(확인 절차를 거쳐 실행) — 선택한 기간·지표와 비교 중인 배터리의 집계된 추세

**상태·예외**

- 비교 대상을 이미 최대 개수까지 선택했을 때
- 배터리 미연결로 잠긴 상태 (T0 게이트)

**제약**
- 표시 지표를 고르는 기능은 이 영역에 없다. 전압·전류·온도·SOC 네 지표를 항상 동시에 보여준다 — 지표를 고르는 것은 실시간 관제의 기능이다 → F4
- 지표별 집계 방식이 다르다. 온도는 구간 내 최고값, 전압·전류·SOC는 평균값으로 집계한다
- CSV와 PDF의 의미는 다르다. CSV는 100ms Raw, PDF는 현재 조회 중인 집계 추세다.

**검수 체크리스트**
- [ ] 기간 전환·비교 추가·CSV 내보내기·PDF 내보내기 네 동작이 모두 가능한가
- [ ] 네 지표가 항상 동시에 표시되는가(지표를 고르는 수단이 없는가)
- [ ] 데이터 없는 구간이 값 0과 구분되어 드러나는가
- [ ] 비교 대상이 최대 5개로 제한되는가
- [ ] 온도와 나머지 지표의 집계 방식이 다르게 반영되는가

### F10. 이벤트 이력

**목적** — 발생한 이상탐지·시스템 이벤트를 검색하고 걸러 살펴보며, 개별 이벤트의 상세를 확인한다.

**반드시 제공하는 정보**
- 배터리 식별자로 좁히는 검색
- 상태 기준 좁히기(전체·위험·경고·주의·차단·정상) 6종과 현재 선택된 기준
- 이벤트 목록 — 발생 시각, 이벤트명, 대상 배터리, 이상점수(점수가 없는 이벤트는 그 사실이 드러나야 한다), 상태
- 전체 건수와 현재 보이는 결과 범위, 페이지 이동
- 이벤트 상세 — 대상 배터리, 이상점수, 발생 시각, 탐지 주체, 원인, 조치

**반드시 가능한 동작**
- 검색어 입력으로 배터리 좁히기
- 상태 기준 선택
- 페이지 이동(이전·다음, 페이지 번호 선택)
- 이벤트 항목 선택 → 상세 확인

**상태·예외**
- 검색·상태 기준 결과가 하나도 없을 때
- 이상점수 없이 발생하는 이벤트(예: 릴레이 자동 차단, 하트비트 미수신)일 때
- 배터리 미연결로 잠긴 상태 (T0 게이트)

**제약**
- 정렬 기준은 이 영역에 없다. 목록은 항상 발생 시각 최신순으로 고정된다. 최근 측정순·이상점수 높은순·SOC 낮은순 정렬은 배터리 자산관리의 기능이다 → F6
- 이벤트명에 셀 번호를 포함하지 않는다(예: "온도 임계값 초과"이지 "온도 임계값 초과 · 셀 3"이 아니다) — 셀 단위 데이터는 범위 밖이다
- 검색은 배터리 식별자만 대상으로 한다. 이벤트 종류로 좁히려면 상태 기준을 쓴다
- 결과 범위 표시(예: "1–5")는 실제로 보여주는 항목 수와 반드시 일치해야 한다
- 센서 원시 데이터를 그대로 보여주는 기능은 이 영역에 없다. 원본 데이터 보기는 알림 센터의 기능이다 → F11

**검수 체크리스트**
- [ ] 검색·상태 기준·페이지 이동·상세 확인 네 동작이 모두 가능한가
- [ ] 상태 기준 6종이 모두 있는가
- [ ] 이상점수가 없는 이벤트에서 그 사실이 드러나는가
- [ ] 결과 범위 표시와 실제 항목 수가 일치하는가
- [ ] 이벤트명에 셀 번호가 없는가
- [ ] 정렬 기준이 이 영역에 없는가(F6에 있다)

### F11. 알림 센터

**목적** — 발생한 알림을 시간순으로 확인하고, 위험 알림을 확인(Ack) 처리해 대응 여부를 남긴다.

**반드시 제공하는 정보**
- 오늘 확인이 필요한 알림 건수
- 오늘 발생한 알림 건수 — 위험, 경고, 주의, 정상·점검(진단기 이벤트 포함)으로 나눈 값
- 알림 목록 — 발생 시각 순으로 확인할 수 있으며, 알림별 심각도, 제목, 설명, 발생 시각, 대상(배터리 또는 진단기), 관련 수치, 발송된 채널을 포함한다
- 위험 등급이면서 아직 확인하지 않은 알림의 원본 센서 데이터(요청 시)

**반드시 가능한 동작**
- 개별 알림을 확인(Ack) 처리
- 미확인 알림을 한 번에 모두 확인 처리
- 원본 센서 데이터 확인

**상태·예외**
- 확인할 알림이 하나도 없을 때
- 미확인 위험 알림이 없어 일괄 확인이 대상이 없을 때
- 배터리 미연결로 잠긴 상태 (T0 게이트)

**제약**
- 확인(Ack)과 원본 데이터 보기는 위험 등급이면서 아직 확인하지 않은 알림에만 제공한다. 경고·정상·점검 알림에는 제공하지 않는다
- 일괄 확인의 대상도 위험 등급 미확인 알림으로 한정한다
- 원본 데이터를 보여줄 때는 이상점수를 환산하지 않은 0.0–1.0 값으로 보여준다. 100배한 정수를 쓰지 않는다

**검수 체크리스트**
- [ ] 오늘 요약(확인 필요 건수·심각도별 건수)과 시간순 알림 목록이 모두 도달 가능한가
- [ ] 개별 확인과 일괄 확인이 모두 가능한가
- [ ] 확인·원본 보기가 위험 등급 미확인 알림에만 노출되는가
- [ ] 원본 데이터의 이상점수가 0.0–1.0로 표시되는가(100배한 정수가 아닌가)

### F12. 릴레이 제어

**목적** — 연결된 배터리 회로를 차단하거나 복구하며, 안전 게이트를 통과한 요청만 실행되게 한다.

**반드시 제공하는 정보**
- 대상 회로 식별자와 현재 회로 상태(정상 연결·차단됨)
- 지금 실행 가능한 동작(차단 또는 복구)과 그 위험 안내
- 최근 제어 이력 — 동작 종류, 시각, 수행 주체(사람 또는 시스템), 사유
- 자동 차단(Fail-Safe) 발생 시 차단 사유, 대상 배터리, 관련 수치(예: 온도), 회로가 이미 차단된 상태라는 사실

**반드시 가능한 동작**
- 차단 또는 복구 실행 요청
- 실행 전 사유 입력과 재인증
- 자동 차단 통보 확인해 닫기

**상태·예외**
- 이미 차단된 상태에서 복구를 시도할 때
- 인터락이 걸려 복구할 수 없을 때 — 복구 불가 사실과 이유가 드러나야 한다
- 사유를 입력하지 않거나 재인증에 실패했을 때 — 실행되지 않고 이유가 드러나야 한다
- 자동 차단이 발생했을 때 — 즉시 통보되며 승인 절차가 없다
- 배터리 미연결로 잠긴 상태 (T0 게이트)

**제약**
- **게이트** — 차단·복구는 서버가 재인증·사유·권한·소유권·디바이스·interlock을 자동 검증해 승인한 뒤에만 실행한다. 별도 관리자 수동 승인 단계는 없다
- 자동 복구는 없다. 한 번 차단된 회로는 반드시 사람이 재인증·사유 입력을 거쳐 수동으로만 복구한다
- 인터락이 걸려 복구할 수 없는 상태에서는 복구 자체를 막는다
- 자동 차단(Fail-Safe) 통보에는 승인·거부 절차가 없다. AI 판정이나 사용자 동의와 무관하게 이미 실행된 차단을 알리기만 한다

**검수 체크리스트**
- [ ] 현재 상태·실행 가능한 동작·제어 이력·자동 차단 정보 네 묶음이 모두 도달 가능한가
- [ ] 차단·복구 실행 전 재인증과 사유 입력이 모두 강제되는가
- [ ] 인터락 상태에서 복구가 막히는가
- [ ] 자동 차단 통보가 승인 절차 없이 즉시 표시되는가

### F15. 관리자 통합 관제

**목적** — 관리자가 전체 시스템 운영 현황을 한눈에 파악하고, 위험 배터리·공지·다른 관리자 조작 이력으로 이동한다.

**반드시 제공하는 정보**
- 전체 유저 수와 최근 7일 신규 유저 수
- 전체 배터리 수와 최근 7일 신규 배터리 수
- 활성 세션 수
- 위험·경고 배터리 수와 최근 24시간 발생 건수
- 최근 7일 이벤트 추이 요약
- 배터리 운영 상태 분포(정상·주시·제한) 각각의 건수
- 측정 모드별(1·2) 배터리 건수
- 최근 위험 배터리 목록 — 식별자, 이상점수
- 최근 공지 목록 — 분류, 제목, 게시일
- 최근 관리자 조작 이력 — 행위, 시각

**반드시 가능한 동작**
- 이벤트 추이 자세히 확인 → F20
- 최근 위험 배터리 더보기 → F17
- 공지 관리로 이동 → F18
- 최근 관리자 조작 더보기(감사 로그로 이동) → F19
- 다른 관리자 화면(유저 계정 관리·배터리 운영 관리·공지사항 관리·감사 로그)으로 이동
- 관리자 모드 종료(일반 사용자 화면으로 복귀 또는 로그아웃)

**상태·예외**
- 위험 배터리가 하나도 없을 때
- 최근 공지가 하나도 없을 때
- 일반 사용자가 관리자 화면 접근을 시도했을 때 — 거부되고 그 시도 자체가 감사 로그에 남는다

**제약**
- 전체 운영 요약에는 오프라인 디바이스 건수를 포함하지 않는다. 디바이스 상태 화면이 범위 밖이므로 이 요약도 같은 기준을 따른다
- 여기서 말하는 배터리 운영 상태 분포(정상·주시·제한)는 이상 탐지 등급(주의·경고·위험)과 다른 축이다. 둘을 같은 값으로 섞어 쓰지 않는다
- 값은 실시간으로 밀어주지 않고 일정 주기로 새로고침한다
- 이 영역은 일반 사용자에게 노출되지 않는다

**검수 체크리스트**
- [ ] 정보 10종이 모두 도달 가능한가
- [ ] 동작 6종이 모두 가능한가
- [ ] 예외 3종의 표시가 정의돼 있는가

### F16. 유저 계정 관리

**목적** — 관리자가 전체 사용자 계정을 조회·검색·필터링하고, 계정 정보 수정과 정지·해제, 비밀번호 재설정을 수행한다.

**반드시 제공하는 정보**
- 유저 목록 — 이름, 이메일, 권한, 등록 배터리 수, 상태

- 상태 필터(전체·활성·정지)와 현재 선택된 기준
- 권한 필터(전체·일반·관리자)와 현재 선택된 기준
- 유저 상세 — 아이디, 전화번호, 권한, 가입일, 등록 배터리 수, 최근 접속
- 유저가 등록한 배터리 목록과 각 배터리의 운영 상태
- 유저의 활동 로그 — 행위, 부가 정보, 시각

**반드시 가능한 동작**
- 이름·이메일로 검색
- 상태 기준으로 목록 좁히기
- 권한 기준으로 목록 좁히기
- 유저 선택 → 상세 확인
- 유저 정보(이름·아이디·전화번호) 수정
- 비밀번호 재설정 이메일 발송 요청
- 계정 정지 또는 해제 — **게이트** — 사유 입력 필수

**상태·예외**
- 검색·필터 결과가 하나도 없을 때
- 정지된 계정 — 웹 로그인만 막히고 진행 중인 측정 세션과 데이터 적재는 계속된다는 사실이 드러나야 한다
- 등록된 배터리가 없는 유저의 상세 확인
- 사유를 입력하지 않고 정지·해제를 시도할 때 — 실행되지 않는다

**제약**
- **게이트** — 계정 정지·해제는 사유 입력을 거쳐야 실행되며, 그 조작은 감사 로그에 남는다
- 권한(일반·관리자) 변경은 제공하지 않는다. 관리자 계정은 운영자가 별도 절차로 만든다
- 등록 배터리 수는 유저가 등록한 배터리로부터 계산되는 값이며, 이 화면에서 직접 고쳐 쓸 수 없다
- 비밀번호 재설정은 재설정 링크를 이메일로 보내는 동작이다. 관리자가 새 비밀번호를 직접 입력하지 않는다
- 이 영역은 일반 사용자에게 노출되지 않는다

**검수 체크리스트**
- [ ] 정보 7종이 모두 도달 가능한가
- [ ] 동작 7종이 모두 가능한가
- [ ] 예외 4종의 표시가 정의돼 있는가
- [ ] 정지·해제 실행에 사유 입력이 강제되는가
- [ ] 권한 변경 수단이 어디에도 없는가
- [ ] 등록 배터리 수가 읽기 전용으로 표시되는가
- [ ] 비밀번호 재설정이 이메일 발송으로만 제공되는가

### F17. 배터리 운영 관리

**목적** — 관리자가 전체 배터리 자산의 운영 상태와 최근 위험도를 파악하고, 개별 배터리의 운영 상태를 전환하며 관리자 메모를 남긴다.

**반드시 제공하는 정보**
- 배터리 목록 — 배터리 식별자, 소유자, 모델, 측정 모드, 최근 이상점수, 운영 상태
- 배터리 라벨 또는 소유자명으로 좁힌 검색 결과
- 운영 상태 필터(전체·NORMAL·WATCH·BLOCKED)와 현재 선택된 기준
- 배터리 상세 — 이상점수, 온도, 전압, SOC
- 배터리 상세 — 직렬 구성, 연결된 진단기와 그 상태, 관리자 메모
- 배터리 운영 로그 — 사건 종류, 관련 수치, 시각

**반드시 가능한 동작**
- 배터리 라벨·소유자명으로 검색
- 운영 상태 기준으로 목록 좁히기
- 배터리 선택 → 상세 확인
- 운영 상태 변경(NORMAL·WATCH·BLOCKED) — **게이트** — 현재와 다른 모든 상태 전환에 사유·확인 필수
- 관리자 메모 입력·별도 저장

**상태·예외**
- 검색·필터 결과가 하나도 없을 때
- 연결된 진단기가 없을 때(활성 세션 없음)
- 관리자 메모가 아직 비어 있을 때
- 어떤 운영 상태 전환이든 사유를 입력하지 않아 실행되지 않을 때

**제약**
- **게이트** — 현재와 다른 모든 운영 상태 전환은 사유 입력과 변경 확인을 거쳐야 실행되며, 감사 로그에 남는다
- 운영 상태와 관리자 메모는 별도 저장하며 각각 감사 로그에 남는다. 메모 저장에는 상태 변경 사유를 요구하지 않는다
- 운영 상태는 NORMAL·WATCH·BLOCKED 세 값에 각각 하나의 한국어 표기만 고정해서 쓴다. 같은 상태를 서로 다른 두 벌의 표기로 병행해서 보여주지 않는다
- BLOCKED로 전환하면 해당 배터리로 새 측정 세션을 열 수 없고, 진행 중인 세션이 있으면 종료된다
- BLOCKED 전환은 운영 통제이며 회로 차단(릴레이)을 수반하지 않는다. 회로 차단이 필요하면 별도로 → F12에서 재인증·사유를 거쳐 수행한다
- 설치 위치 정보는 제공하지 않는다 — 저장할 곳이 없다
- 이 영역은 일반 사용자에게 노출되지 않는다

**검수 체크리스트**
- [ ] 정보 6종이 모두 도달 가능한가
- [ ] 동작 5종이 모두 가능한가
- [ ] 예외 4종의 표시가 정의돼 있는가
- [ ] 모든 실제 운영 상태 전환에 사유 입력과 확인이 강제되는가
- [ ] 운영 상태 변경과 관리자 메모 입력이 모두 상세에서 가능한가
- [ ] 운영 상태 표기가 한 벌로만 쓰이는가
- [ ] BLOCKED 전환이 릴레이를 직접 차단하지 않는가

## 보조배터리 진단 영역

### F21. 보조배터리 진단

> 이 영역만 일반 사용자 영역인데 관리자 영역 뒤에 있다. 번호는 추가 순서이며 F15~F20(관리자)과 무관하다.
>
> 물리적 근거·측정 산식·안전 문턱의 정본은 `docs/hardware/mode2_powerbank_diagnosis_spec.md`다. 이 절은 그 스펙에서 **사용자에게 보여야 할 것과 가능해야 할 동작**만 옮긴 것이며, 산식을 여기서 다시 정의하지 않는다.

**목적** — 연결된 보조배터리의 등록 정보, 현재 출력량, 열화상태를 한자리에서 확인하고, 열화를 재는 두 종류의 진단을 실행한다.

**반드시 제공하는 정보**

*식별 — 등록된 값*
- 배터리 식별자(battery_id), 라벨, 배터리 종류, 제조사·모델(입력된 경우), 자산에 고정된 측정 모드
- 정격 용량, 광고 정격 출력 전류(모드 2 등록 시 필수)

*현재 출력량 — 실측한 값*
- 경부하 기준 출력전압과 그것이 최소 유지 부하에서 잰 값이라는 사실, 현재 전압·전류·전력. 전류와 전력은 절댓값과 방향(충전·방전) 표기로 보인다. 원시 부호를 그대로 노출하지 않는다
- 상대 SOC, 그리고 그 값이 **측정 시작 시점을 100%로 본 상대값**이라는 사실
- 표면 온도, 그리고 각 값이 몇 밀리초 전에 실측된 것인지

*열화 — 진단 결과*
- 진단 종류(빠른 진단·정밀 용량 테스트), 신뢰도, 측정 시각, 잔량 힌트 단수
- 빠른 진단 세 지표 — 레귤레이션 이탈 전류(그 값이 상한인지 여부 포함), 발열 기울기, 스펙 도달률 — 과 열화 등급
- 정밀 용량 테스트 — 뽑아낸 Wh, 기준선 Wh, 기준선 대비 상대 SOH, 참고용 절대 SOH와 그때 가정한 효율, 방전 전류, 부분 결과 여부
- 아직 한 번도 진단하지 않았다는 사실
- 기준선이 1회뿐이어서 상대 SOH를 낼 수 없다는 사실
- 누적 사이클·잔존수명·내부 저항이 **이 측정 모드에서는 산출 불가**라는 사실과 그 이유
- 진단이 진행 중이면 현재 단계, 목표 전류, 경과 시간과 남은 시간 추정

*안전*
- 가스 상태, 릴레이 회로 상태, 최종 이상점수와 4등급
- 진단 중에는 이상 알림이 억제된다는 사실. 단 자동 차단은 억제되지 않는다는 사실

*이력*
- 이 배터리의 과거 진단 목록 — 측정 시각, 종류, 신뢰도, 핵심 결과값

**반드시 가능한 동작**
- 빠른 진단 실행 → T16
- 정밀 용량 테스트 실행 → T16
- 진행 중인 진단 중단
- 잔량 힌트 단수 입력·수정
- 과거 진단 이력 확인과 개별 결과 상세 확인
- 실시간 관제로 이동 → F4
- 이 배터리의 상세·이력으로 이동 → F7
- 릴레이 차단으로 이동 → T7

단, 위 진단 실행은 `MODE2_FULL`처럼 필수 안전계층과 연속 감시가 준비된 프로필에서만 활성화한다. `COMBINED_EXISTING_PARTS_V1`은 전기 시운전 프로필이므로 빠른 진단·정밀 용량시험 동작을 비활성화하고 **`안전 프로필 준비 필요`** 사유를 표시한다. 사람이 지켜본다는 확인으로 이 게이트를 해제하지 않는다.

`COMBINED_EXISTING_PARTS_V1`에서는 계약상 `soc_pct`·가스·접촉온도·진단 단계·목표 부하가 `null`이다. 잠금 화면은 이 값을 이전 세션·모드에서 가져오거나 목업 수치로 채우지 않고 `— · 프로필상 산출 불가` 또는 `안전 계층 미준비`로 표시한다. IR 표면온도와 INA226 전압·전류·전력처럼 해당 프로필에서 실제 측정 가능한 값만 보여준다. 숨은 프로토타입 속성의 `MODE2_FULL`은 목표 화면 검토용이며 실서버 안전 게이트를 우회하지 않는다.

**상태·예외**
- 연결된 배터리 없음 — T0 게이트가 걸린 상태
- 연결된 배터리의 측정 모드가 2가 아닐 때 — 이 영역의 진단은 보조배터리 전용이다
- 정격 용량이 등록되지 않아 정밀 용량 테스트를 시작할 수 없을 때
- 진단 이력이 하나도 없을 때
- 기준선이 1회뿐이라 상대 SOH를 낼 수 없을 때
- 진단이 안전 조건에 걸려 중단됐을 때 — 어느 조건이었는지 드러나야 한다
- 진단 중 다른 배터리가 연결되거나 배터리가 운영 차단되어 세션이 끝났을 때 — 그 진단은 무효다
- 진단기가 오프라인일 때
- 지시한 목표 전류와 실측 전류의 차이가 커서 결과를 신뢰할 수 없을 때
- 릴레이가 차단 상태라 부하 경로가 없을 때
- 필수 안전계층·연속 감시가 없는 `COMBINED_EXISTING_PARTS_V1`일 때 — `안전 프로필 준비 필요`, 진단 실행 불가

**제약**
- 열화 등급과 이상점수 4등급은 **서로 다른 축**이다. 열화는 수명, 이상점수는 열폭주 위험이다. 두 값을 합산하거나 하나의 값으로 합쳐 보이지 않는다. 두 등급에 같은 이름(주의)이 존재하므로 어느 축의 등급인지 항상 함께 읽혀야 한다
- 누적 사이클·잔존수명·내부 저항은 이 측정 모드에서 값이 채워지지 않는다. 비어 있음을 감추지 않고, 왜 비었는지 확인할 수 있어야 한다
- 절대 SOH는 효율 가정에 의존하는 참고값이다. 가정한 효율값과 함께 읽히지 않는 절대 SOH를 보이지 않는다
- 상대 시간은 저장된 문자열이 아니라 절대 시각으로부터 화면이 계산해서 보여준다
- 측정값·시각·식별자는 실시간 갱신 중 폭이 흔들리지 않아야 한다
- 진단 안내 문구는 서버가 만들지 않는다. 서버는 사유와 등급을 뜻하는 값만 주고 문장은 화면이 조립한다

**검수 체크리스트**
- [ ] 식별·현재 출력량·열화·안전·이력 다섯 정보 묶음이 모두 도달 가능한가
- [ ] 진단을 한 번도 하지 않은 배터리에서 "진단 없음"이 드러나는가
- [ ] 누적 사이클·잔존수명·내부 저항이 비어 있는 이유를 확인할 수 있는가
- [ ] 절대 SOH가 가정한 효율값과 항상 함께 읽히는가
- [ ] 열화 등급과 이상점수 등급이 서로 구분되어 읽히는가
- [ ] 두 진단의 실행 게이트(T16)를 건너뛰는 경로가 없는가
- [ ] 진행 중 진단을 중단할 수 있는가
- [ ] 배터리 미연결 상태에서 이 영역이 잠기는가

## 부록 A. 목업 데이터

새 디자인은 이 값을 그대로 쓴다. 여기에 없는 수치를 지어내지 않는다. 값은 프로토타입(`설계 산출물/셀가드 프로토타입_v3.html`)의 데이터 배열에서 그대로 옮겼으며, 화면마다 표 행 수는 프로토타입과 동일하게 유지했다.

### 추세 파형은 예외다

이 부록에는 시점별 값이 없다. 단일 시점의 값과 집계된 건수만 있다. 그래서 시간에 따라 값이 변하는 모습을 보여야 하는 곳은 이 부록만으로 그릴 수 없다.

**해당하는 곳** — 실시간 관제(F4)의 최근 추이, 배터리 상세·이력(F7)의 최근 30일 이상점수 추세와 기간별 지표 추세, 추세(F9)의 네 지표 추이. 이벤트 추이(F20)는 해당하지 않는다 — 구간별 건수가 이 부록에 있으므로 그 값을 그대로 쓴다.

**이 세 곳에 한해 파형을 만들어 써도 된다.** 대신 아래를 지킨다.

- 파형의 현재값(가장 최근 시점)은 이 부록의 해당 값과 이어져야 한다. 실시간 관제의 전압 파형은 `11.46 V`에서 끝난다
- 파형이 등급 판정을 뒤집으면 안 된다. 이상점수 18은 정상인데 파형만 위험 구간을 넘나들면 안 된다
- 추세(F9)의 집계 규칙과 어긋나면 안 된다 — 온도는 구간 내 최고값, 전압·전류·SOC는 평균값이다
- 데이터가 없는 구간을 넣었다면 값이 0인 경우와 구분되게 그린다. 이는 F9의 제약과 같다
- 같은 자리에는 늘 같은 파형이 나와야 한다. 다시 그릴 때마다 모양이 달라지면 화면끼리 어긋나고 검수도 할 수 없다
- 셀 단위로 나누지 않는다

**허용 범위는 모양뿐이다.** 파형을 만들어도 된다는 것이지, 이 부록에 있는 다른 수치를 만들어도 된다는 뜻이 아니다. 표의 행, 요약 건수, 점수, 식별자는 여전히 지어내지 않는다.

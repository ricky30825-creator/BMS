# 모드 1 (외부 셀) — 에지 데이터 수집 스펙

라즈베리파이(에지)에서 센서를 읽어 `battery-raw-metrics` 프레임을 만드는 개발자를 위한 문서다.

- 회로도: `hardware/mode1/cellguard_mode1.kicad_pro` / `.svg`
- 조립·배선: `docs/hardware/mode1_beginner_guide.md`
- 상위 API 계약: `docs/backend_contract.md`

**범위**: 모드 1(외부 셀)만. 모드 2(보조배터리) 회로는 아직 없다.

## 0. 한눈에 보기

**I2C 버스 1** (`/dev/i2c-1`), 3.3V, 100kHz. 확인: `sudo i2cdetect -y 1` → `40 48 55 5a 5b`

| 주소 | 부품 | 읽는 값 | 주소 결정 |
|---|---|---|---|
| `0x40` | INA226 | 전압·전류·전력 | A0/A1 = GND (모듈 기본값) |
| `0x48` | ADS1115 | 압력 (A0 채널) | `ADDR` → GND |
| `0x55` | BQ27441 | SOC | **하드웨어 고정 — 변경 불가** |
| `0x5A` | MLX90614 **#1** | IR 표면온도 (셀 중앙) | 출고 기본값 |
| `0x5B` | MLX90614 **#2** | IR 표면온도 (셀 단자쪽) | EEPROM `0x0E` 변경 (§6-3) |

**핵심 상수** — 코드에 박기 전에 이 표와 대조한다.

| 항목 | 값 | 절 |
|---|---|---|
| 발행 주기 | **100ms** | §1 |
| INA226 Configuration (`0x00`) | **`0x4527`** (AVG=16, 1.1ms×2, 연속) → 35.2ms | §3-2 |
| INA226 `Current_LSB` | **0.0002 A** → 측정 상한 **6.55 A** | §3-3 |
| INA226 CAL (`0x05`) | **R010 → 2560** / R002 → 12800 / R100 → 256 | §3-3 |
| INA226 `Power_LSB` | **0.005 W** (= 25 × Current_LSB) | §3-3 |
| ADS1115 Config (`0x01`) | **`0x4283`** (A0 단극, ±4.096V, 연속, 128SPS) → 7.8ms | §5-1 |
| MLX90614 ConfigRegister1 (`0x25`) | **IIR=`100`, FIR=`111`** → 정착 **95.2ms** | §6-2 |
| DS18B20 해상도 | **12비트** (0.0625°C / 750ms) | §7 |
| 릴레이 GPIO | CH1 **5**(충전) · CH2 **6**(방전) · CH3 **13**(마스터) · CH4 **19**(예비) | §8-1 |
| 릴레이 극성 | **active-LOW** — `0`=도통, `1`=차단 | §8-2 |

**필드별 실제 갱신 주기** — 100ms로 새 값이 나오는 건 전기량과 압력뿐이다.

| 필드 | 센서 | 갱신 주기 | 100ms 프레임 10개 중 실측 |
|---|---|---|---|
| `pressure_raw` | ADS1115 | **7.8ms** | 10개 전부 |
| `voltage_v`·`current_a`·`power_w` | INA226 | **35.2ms** | 10개 전부 |
| `temp_ir_surface` | MLX90614 ×2 | **95.2ms** | 10개 전부 |
| `temp_contact` | DS18B20 ×3 | **750ms** | 1~2개 |
| `soc_pct` | BQ27441 | **약 1000ms** | 1개 |

> **온도는 다점 측정이다.** 접촉 3점(DS18B20 ×3) + IR 2존(MLX90614 ×2)을 재고 **최댓값**을 `temp_contact`·`temp_ir_surface`에 싣는다. MLX90614는 소자 1개짜리라 시야각 안의 평균만 내므로, 공간 피크를 만들려면 여러 개를 다른 지점에 겨누는 수밖에 없다(§6-4).

> **`0x55`(BQ27441)는 셀을 꽂아야 보인다.** 셀에서 전원을 받기 때문이다. 릴레이 CH3(마스터)을 열면 버스에서 사라지는데 **정상 동작이다** — 센서 오류로 오인하지 않도록 CH3 상태를 함께 확인한다(§8-6).

> **1-Wire는 I2C가 아니다.** DS18B20은 GPIO4(물리핀 7)에 붙고 커널 드라이버가 sysfs로 노출한다.

## 1. 신선도 필드 `age_ms`

AI 특징에 `dT_dt`(온도 변화율)와 `d2T_dt2`(가속도)가 들어 있다. **`temp_contact`는 750ms 동안 값이 동결**되므로, 이걸 100ms 간격으로 미분하면 **0이 7번 나오다 한 번 튀는 계단 파형**이 된다. 2차 미분에서는 그 계단이 임펄스 열로 증폭된다.

그래서 프레임에 **각 값이 몇 ms 전에 실측됐는지**를 함께 싣는다. 정보를 하나도 버리지 않고 문제를 AI 쪽에서 풀 수 있게 하는 방식이다.

```json
"age_ms": { "soc_pct": 640, "temp_contact": 310, "temp_ir_surface": 40 }
```

| 규칙 | 내용 |
|---|---|
| 키 단위 | **스칼라 필드 기준.** `temp_points`의 지점별 age는 싣지 않는다 |
| 키가 없으면 | **그 프레임에서 실측된 것**이다 (INA226·ADS1115) |
| `temp_contact` | DS18B20 3점이 동시 변환이므로 세 점이 같은 값이다 |
| `temp_ir_surface` | MLX90614 2개를 순차로 읽어 최대 95.2ms 어긋난다. **더 오래된 쪽**을 싣는다(보수적) |
| 소비 방식 | AI가 `age_ms > 100`인 구간의 미분을 버릴지 보간할지 정한다. 에지는 관여하지 않는다 |

> **DS18B20 해상도를 낮춰 갱신을 빠르게 하지 않는다.** 9비트면 변환이 93.75ms로 줄지만 분해능이 0.5°C가 되는데, 열폭주 초기 상승이 분당 1~2°C라 그 계단이 그대로 노이즈가 된다. **12비트를 유지한다.**

> **`therm_bulk_read` 미지원 커널이면 접촉 온도가 2250ms까지 늘어난다**(§7-2). 기동 시 반드시 확인할 것.

## 2. 수집 스레드 구조

센서마다 주기가 다르므로 **한 루프에서 순차로 읽으면 안 된다.** 가장 느린 것이 전체를 붙잡는다.

```
[ADS1115 스레드]   50ms 주기
[INA226 스레드]    35ms 주기로 읽어 최신값 갱신
[MLX90614 스레드]  95ms 간격으로 #1(0x5A)·#2(0x5B) 순차 읽기
[BQ27441 스레드]   1000ms 주기
[DS18B20 스레드]   Skip ROM + Convert T 로 3개 동시 변환 -> 750ms 후 셋을 각각 읽기
        ↓  각자 (값, 측정시각) 을 공유 상태에 씀
[발행 스레드]      100ms 주기로 공유 상태를 스냅샷 → Kafka 발행
```

I2C 버스는 하나이므로 **버스 접근에는 단일 락**을 건다. 1-Wire는 별도 버스라 락이 필요 없다.

## 3. INA226 (0x40) — 전압 · 전류 · 전력

### 3-1. 레지스터

| 주소 | 이름 | 형식 | 변환 |
|---|---|---|---|
| `0x00` | Configuration | u16 | §3-2 |
| `0x01` | Shunt Voltage | **i16** | × 2.5 µV |
| `0x02` | Bus Voltage | u16 | × 1.25 mV |
| `0x03` | Power | u16 | × Power_LSB (0.005) |
| `0x04` | Current | **i16** | × Current_LSB (0.0002) |
| `0x05` | **Calibration** | u16 | §3-3 |
| `0x06` | Mask/Enable | u16 | **bit 2 = OVF(산술 오버플로)** — §3-3 |
| `0xFE` | Manufacturer ID | u16 | `0x5449` ("TI") — 연결 확인용 |
| `0xFF` | Die ID | u16 | `0x2260` — 연결 확인용 |

모든 레지스터는 **16비트 빅엔디안**이다 (`i2c_smbus_read_word_data`를 쓰면 바이트를 뒤집어야 한다).

### 3-2. Configuration = `0x4527`

| 비트 | 필드 | 값 | 의미 |
|---|---|---|---|
| 15 | RST | 0 | 리셋 안 함 |
| 14:12 | (고정) | `100` | 데이터시트 고정값 |
| 11:9 | AVG | `010` | 16회 평균 |
| 8:6 | VBUSCT | `100` | 버스 전압 변환 1.1ms |
| 5:3 | VSHCT | `100` | 션트 전압 변환 1.1ms |
| 2:0 | MODE | `111` | 연속 측정 (션트 + 버스) |

갱신 주기 = 16 × (1.1 + 1.1) = **35.2ms**.

평균 16회를 쓰는 이유: 릴레이 코일 때문에 전원이 지저분해서, 평균 없이는 전류가 튄다.

### 3-3. Calibration — 션트 저항값을 확인해야 계산된다

```
Current_LSB = 0.0002 A
CAL         = 0.00512 / (Current_LSB × R_shunt)
Power_LSB   = 25 × Current_LSB = 0.005 W
```

**보드 실크스크린을 읽고 아래 표에서 고른다** (`mode1_beginner_guide.md` §2-③).

| 실크스크린 | R_shunt | **CAL (`0x05`에 쓸 값)** | 션트 ADC 한계 | **실제 측정 상한** |
|---|---|---|---|---|
| `R002` / `2m` | 0.002 Ω | **12800** (`0x3200`) | 40.96 A | **6.55 A** |
| `R010` / `10m` | 0.01 Ω | **2560** (`0x0A00`) | 8.19 A | **6.55 A** |
| `R100` / `0.1` | 0.1 Ω | **256** (`0x0100`) | 0.82 A | **0.82 A** |

`current_a = raw_0x04 × 0.0002`, `power_w = raw_0x03 × 0.005` — 션트값과 무관하게 동일하다. 달라지는 건 `0x05`에 쓰는 CAL뿐이다.

> ### ⚠️ 측정 상한을 정하는 건 션트가 아니라 Current 레지스터다
>
> ```
> 실제 상한 = min( 81.92mV / R_shunt ,  32767 × Current_LSB )
> ```
>
> R002·R010은 션트 여유가 40.96A·8.19A나 되지만 **레지스터가 먼저 6.55A에서 랩어라운드**한다. 넘치면 값이 0으로 감기거나 **부호가 뒤집혀 방전이 충전으로 보인다.** 조용히 오염되는 종류의 고장이다.
>
> **`Mask/Enable`(0x06)의 OVF 비트(bit 2)를 매 프레임 확인한다.** 데이터시트: *"OVF: Math Overflow Flag — ... indicates that current and power data can be invalid."* OVF=1이면 `current_a`·`power_w`를 `null`로 내리고 이벤트를 발행한다. **이 검사 없이는 오버플로를 알아챌 방법이 없다.**
>
> 상한을 6.55A로 잡은 근거는 **셀 스펙이 아니라 보호회로(PCM) trip 전류(통상 4~10A)**다. PCM trip이 6.55A를 넘는 순간에는 OVF가 뜨는데 정상이다 — 보호회로가 끊기는 과도구간의 정확한 전류값은 필요 없고 플래그와 이벤트만 남기면 된다.

> **`Current_LSB`와 CAL은 같은 설정 파일에 둔다.** 하드코딩하면 한쪽만 바뀌어 값이 배수로 틀어진다. 실물 션트값 확인 전 기본값은 `R010`(CAL=2560).
>
> **검산**: `0x01`(Shunt Voltage) × 2.5µV ÷ R_shunt 가 `0x04`(Current) × Current_LSB 와 일치해야 한다. 어긋나면 CAL이 틀린 것이다. 기동 시 한 번 돌려 로그에 남긴다.

### 3-4. 부호 규약 — 양수 = 충전

회로도상 **`IN+` = 릴레이 CH3 쪽, `IN−` = 셀 쪽**이고 INA226은 `V(IN+) − V(IN−)`를 잰다.

| 상태 | 전류 방향 | `current_a` | `power_w` |
|---|---|---|---|
| **충전** | 릴레이 → 셀 (IN+ → IN−) | **양수 (+)** | 양수 |
| **방전** | 셀 → 릴레이 (IN− → IN+) | **음수 (−)** | 음수 |
| 차단/무부하 | 없음 | 0 근처 | 0 근처 |

**에지는 부호를 살려 발행한다.** 충·방전 구분이 AI 특징(`Wh_cumsum`)에 직접 필요하고, 절댓값으로 내리면 복원할 방법이 없다.

- **AI**: 부호 그대로 쓴다.
- **프론트엔드**: 표시할 때만 `abs()`하고 방향은 라벨(`충전`/`방전`)로 낸다. 사용자에게 `-1.25 A`를 그대로 보이지 않는다.

### 3-5. `voltage_v`는 보정하지 않는다

> **2026-07-31 정정.** 이전 판은 "`CELL_N`과 GND 사이에 BQ27441의 20 mΩ 센스 저항이 있으니 `voltage_v`에 `±|current_a| × 0.02`를 더해 보정하라"고 적었다. **틀렸다 — 그런 저항은 그 자리에 없다.**
>
> SparkFun Battery Babysitter 공식 회로도(v10) 확인 결과:
> - 배터리 `−`(`JP6.−` / `JP5.1`)는 보드 `GND`에 **직결**돼 있다. `CELL_N`과 GND 사이 직렬 저항은 없다.
> - BQ27441의 센스 저항 `R11`은 **0.01 Ω(10 mΩ)** 이며, 배터리 **`+` 쪽 하이사이드**에 있다 — `BATTERY_IN` ↔ `V_BATT` 사이이고 `SRP`/`SRN`이 그 양끝을 잰다.
>
> 따라서 보정식을 적용하면 **없는 오차를 3A에서 60 mV씩 만들어 넣게 된다.** 삭제한다.

`VBUS`는 `CELL_P`(셀 + 바로 옆)에서 따고 기준점은 시스템 GND인데, **셀의 −가 곧 시스템 GND다**(Babysitter 배터리 `−` → 보드 `GND` → GND 레일). 그래서 `VBUS`는 셀 단자 전압을 그대로 읽는다.

- **`voltage_v = raw × 0.00125`를 그대로 발행한다.** 에지·AI·프론트 어디서도 전류 기반 보정을 하지 않는다.
- 남는 오차는 **배선 저항으로 인한 IR 강하**뿐이다 — 셀 `−` → Babysitter 배터리 `−` → 보드 GND → GND 레일 → INA226 `GND` 경로. 고정 저항이 아니라 배선 품질에 달렸으므로 **계산으로 보정할 수 없고, 배선으로 줄인다**: `CELL_N`은 배터리 `−` 한 점에만 물고(스타 그라운드), 0.75SQ를 쓰고, BW150 부하의 `−` 귀환이 센서 GND 구간을 지나지 않게 한다.
- 이 오차가 실제로 얼마인지는 실측 항목이다(§13 H5).

## 4. BQ27441 (0x55) — SOC

Battery Babysitter [PRT-13777]에 탑재. **셀에서 전원을 받으므로 셀이 없거나 릴레이 CH3이 열리면 응답하지 않는다.**

### 4-1. 표준 커맨드 (전부 **리틀엔디안** 16비트)

| 주소 | 이름 | 단위 | 비고 |
|---|---|---|---|
| `0x02` | Temperature | 0.1 K | `°C = raw/10 − 273.15`. 게이지 내부 온도이지 셀 표면온도가 아니다 |
| `0x04` | Voltage | mV | **셀 양단 직접 측정** — INA226 검산용 |
| `0x06` | Flags | 비트필드 | §4-3 |
| `0x0C` | RemainingCapacity | mAh | |
| `0x0E` | FullChargeCapacity | mAh | |
| `0x10` | AverageCurrent | mA (**부호 있음**) | 방전이 음수 |
| `0x18` | AveragePower | mW (부호 있음) | TRM Table 4-1. **`0x16`이 아니다** — 0x16/0x17은 표준 커맨드에 없는 주소다 |
| `0x1C` | **StateOfCharge** | **%** | → `soc_pct` |
| `0x20` | StateOfHealth | % | |

> **INA226과 엔디안이 반대다.** INA226은 빅엔디안, BQ27441은 리틀엔디안이다. 여기서 실수하면 값이 그럴싸하게 틀린다(예: `0x5100` = 20736 대신 `0x0051` = 81).

### 4-2. ⚠️ 배터리를 바꿀 때마다 Design Capacity를 다시 써야 한다

18650(2550mAh)과 리튬폴리머(1000mAh)를 번갈아 물리면 **그때마다** 다시 설정해야 SOC가 맞는다. 안 하면 SOC가 그럴싸한 숫자로 계속 틀린다.

| 셀 | Design Capacity | Design Energy (= 용량 × 3.7) | Terminate Voltage |
|---|---|---|---|
| 18650 [ZM18650-2600-KC01] | 2550 mAh | 9435 mWh | 3000 mV |
| 리튬폴리머 [TW102050] | 1000 mAh | 3700 mWh | 3000 mV |

**설정 절차 (Configuration Update 모드)**

```
1.  Control(0x00) ← 0x8000  두 번            # UNSEAL
2.  Control(0x00) ← 0x0013                   # SET_CFGUPDATE
3.  Flags(0x06) 의 bit4(CFGUPMODE) 가 1이 될 때까지 폴링 (최대 1초)
4.  BlockDataControl(0x61) ← 0x00            # 블록 데이터 접근 활성화
5.  DataBlockClass(0x3E) ← 0x52              # State 서브클래스
6.  DataBlock(0x3F)      ← 0x00              # 블록 오프셋 0
7.  0x40~0x5F (32바이트) 읽기
8.  Design Capacity  = 오프셋 10~11 (0x4A/0x4B)   # 블록 안은 빅엔디안
    Design Energy    = 오프셋 12~13 (0x4C/0x4D)
    Terminate Voltage= 오프셋 16~17 (0x50/0x51)
9.  새 값을 써 넣고 32바이트의 체크섬을 재계산해 BlockDataChecksum(0x60) 에 쓴다
        checksum = 255 - (sum(32바이트) & 0xFF)
10. Control(0x00) ← 0x0042                   # SOFT_RESET
11. Flags(0x06) 의 CFGUPMODE 가 0이 될 때까지 폴링
12. Control(0x00) ← 0x0020                   # SEALED (선택)
```

> **이 절차는 반드시 실물로 검증할 것.** 오프셋과 체크섬 규칙은 TI BQ27441-G1 TRM(SLUUAC9) 근거이나, 한 단계만 틀려도 게이지 설정이 조용히 깨진다. **검증법**: 설정 후 `FullChargeCapacity(0x0E)`를 읽어 방금 쓴 Design Capacity 근처 값이 나오는지 확인한다.
>
> 연결 확인은 `Control(0x00) ← 0x0001`(DEVICE_TYPE) 후 읽어 **`0x0421`**이 나오는지로 한다.

### 4-3. ⚠️ Flags (0x06) 비트 — 절대 비트 번호로 옮길 때 틀리기 쉽다

**TRM Table 4-4는 High Byte와 Low Byte를 각각 `bit7..bit0`으로 표기한다.** 이걸 절대 비트로 환산하는 과정에서 실수가 나오므로, 아래 표의 마스크를 그대로 쓴다.

| 절대 비트 | 마스크 | 이름 | 의미 |
|---|---|---|---|
| 0 | `0x0001` | DSG | 1 = 방전 중 |
| 1 | `0x0002` | SOCF | SOC 최종 경고 임계 도달 |
| 2 | `0x0004` | SOC1 | SOC 1차 경고 임계 도달 |
| 3 | `0x0008` | BAT_DET | 1 = 배터리 감지됨 |
| 4 | `0x0010` | CFGUPMODE | 1 = 설정 변경 모드 |
| **5** | **`0x0020`** | **ITPOR** | 1 = **설정이 초기화됨** → Design Capacity를 다시 써야 한다 |
| 7 | `0x0080` | OCVTAKEN | relax 모드에서 OCV 측정 완료 |
| **8** | `0x0100` | **CHG** | 고속 충전 허용 |
| 9 | `0x0200` | FC | 완충 감지 |
| 14 | `0x4000` | UT | 저온 (기본 0°C 이하) |
| 15 | `0x8000` | OT | 과온 (기본 55°C 이상) |

> ⚠️ **bit 8은 ITPOR이 아니라 `CHG`다.** 여기를 헷갈리면 **충전할 때마다 "게이지 리셋됨"으로 오탐하고 정작 진짜 리셋은 영영 못 잡는다.**

> **기동할 때마다 `ITPOR`(bit 5, `0x0020`)을 확인한다.** 1이면 §4-2를 다시 돌리고 `battery-events`에 알린다. 이걸 안 보면 SOC가 틀린 채로 계속 돈다.

## 5. ADS1115 (0x48) — 압력

### 5-1. 레지스터와 Config

| 주소 | 이름 |
|---|---|
| `0x00` | Conversion (읽기) |
| `0x01` | Config |

**16비트 빅엔디안.** Config = **`0x4283`**:

| 비트 | 필드 | 값 | 의미 |
|---|---|---|---|
| 15 | OS | 0 | (연속 모드에선 무시) |
| 14:12 | MUX | `100` | **A0 vs GND** (단극) |
| 11:9 | PGA | `001` | ±4.096 V |
| 8 | MODE | `0` | 연속 변환 |
| 7:5 | DR | `100` | 128 SPS (7.8ms) |
| 4:0 | 비교기 | `00011` | 비교기 비활성 |

변환: **`V = raw × 4.096 / 32768`** = `raw × 0.000125` V

> PGA를 ±4.096V로 두지만 VDD가 3.3V라 입력은 3.3V를 못 넘는다. 헤드룸으로 두는 것이지 3.3V 이상을 잰다는 뜻이 아니다.

### 5-2. FSR 406 → `pressure_raw`

회로: `3.3V ── FSR406 ──┬── ADS1115 A0`, 그 접점에서 `── R1(10kΩ) ── GND`

```
V_A0 = 3.3 × 10k / (R_FSR + 10k)
```

FSR은 **힘이 커질수록 저항이 낮아진다.**

| 상태 | R_FSR | V_A0 | raw |
|---|---|---|---|
| 안 눌림 | 매우 큼 (수 MΩ) | 0 V 근처 | 0 근처 |
| 살짝 눌림 | 수십 kΩ | 0.5~1 V | 4000~8000 |
| 세게 눌림 | 수백 Ω ~ 수 kΩ | 2.5~3.2 V | 20000~26000 |

**`pressure_raw`는 ADC 원시 카운트를 그대로 싣는다.** 힘(N)으로 환산하지 않는다 — FSR은 개체차가 크고 부착 방식에 따라 특성이 완전히 달라져서, 환산해봐야 의미 없는 정밀도를 만들 뿐이다.

### 5-3. 압력 임계는 baseline 대비 상대값이다

절대 카운트는 쓰지 않는다. **예압(끼울 때 주는 초기 압력)에 따라 baseline이 매번 달라져서** 절대 임계는 셀을 다시 끼울 때마다 무의미해진다.

```
baseline   = 세션 시작 후 안정화 10초 구간의 pressure_raw 중앙값
상대상승률 = (pressure_raw − baseline) / baseline
```

- **baseline은 측정 세션마다 새로 잡는다.** 이전 세션 값을 재사용하면 안 된다.
- baseline 산출 중(시작 10초)에는 압력 기반 차단을 **비활성**으로 둔다. 이 구간에 셀을 만지지 않는다.
- **`baseline < 500 카운트`면 부착 불량**으로 보고 이벤트를 내고 압력 계층을 비활성화한다. (0에 가까우면 나눗셈이 발산한다.)
- `pressure_raw`는 계속 **원시 카운트 그대로** 발행한다. baseline·상승률 계산은 판정하는 쪽에서 한다.

> **차단할 상승률(%)은 실측 없이 정할 수 없다**(§13 H8). 그 전까지 압력 계층은 **경고만 내고 릴레이는 건드리지 않는다.**

### 5-4. 채널 배분

**ADS1115 1개(4채널)로 충분하다.** 아날로그 센서는 모드별로 1개씩만 붙는다.

| 채널 | 모드 1 (외부 셀) | 모드 2 (보조배터리) |
|---|---|---|
| `A0` | **FSR 406 압력** (`pressure_raw`) | **MQ-2 가스** (`gas_raw`) — 5V AOUT이라 분압 필요 |
| `A1`·`A2`·`A3` | 미배선 | 미배선 |

- **모드 1에는 가스 센서를 달지 않는다** — MQ-2 히터가 상시 150mA@5V로 발열해 같은 셀에 붙은 DS18B20 3점·MLX90614 2존을 오염시킨다. 모드 1의 핵심은 다점 온도이므로 온도 정확도를 우선한다.
- **음향 센서는 전 모드에 없다.** `acoustic_raw`는 `null` 고정이다(§10).
- 미배선 채널은 **읽지 마라.** 플로팅 입력이라 의미 없는 값이 나온다.

> 모드 2 회로는 아직 없다. 위 배분은 모드 2 회로를 그릴 때의 계약이다.

## 6. MLX90614 ×2 (0x5A / 0x5B) — IR 표면온도 2존

**부품**: DFRobot Gravity SEN0206 = **MLX90614-DCC**, FOV **35°**, 3.3~5V, 출고 주소 0x5A.

**SMBus 프로토콜**이다. 일반 I2C 읽기가 아니라 repeated-start가 필요하다. Linux에서는 `i2c_smbus_read_word_data`(파이썬 `smbus2`의 `read_word_data`)가 맞게 동작한다.

### 6-1. RAM 읽기

| 커맨드 | 이름 | 의미 |
|---|---|---|
| `0x06` | Ta | 센서 자체(주변) 온도 |
| `0x07` | **TOBJ1** | **대상 표면온도** → `temp_ir_surface` |
| `0x08` | TOBJ2 | 2번 필드 (단일 존 모델에는 없음) |

읽으면 3바이트가 온다: `LSB, MSB, PEC`. 값은 **리틀엔디안 16비트**.

```
T(°C) = raw × 0.02 − 273.15
```

**유효성 검사**: MSB의 최상위 비트가 1이면 오류 플래그다. `raw`가 `0x0000`이나 `0xFFFF`면 통신 실패로 본다.

### 6-2. ⚠️ 필터 재설정은 선택이 아니라 전제다 — `IIR=100`, `FIR=111`

**출고 설정(IIR 50% + FIR 1024)은 갱신이 864.9ms이고, 그 위에 스파이크를 50%로 깎는다.** IIR의 "최대 스텝"은 한 샘플에서 출력이 따라갈 수 있는 변화량의 상한이라, 0.5면 입력이 갑자기 튀어도 출력은 절반까지만 따라간다. 앱노트가 이 기능을 설명하는 문장이 *"뜨거운 물체가 FOV를 지나가는데 그것을 측정하고 싶지 않을 때 IIR을 쓴다"*이다. **열폭주 초기의 급격한 온도 스파이크가 정확히 그 신호다.**

| 항목 | 값 |
|---|---|
| ConfigRegister1 (EEPROM `0x05`, 커맨드 `0x25`) 비트 10..8 (FIR) | **`111`** (1024 탭 — 이 속도에서 얻을 수 있는 최저 노이즈) |
| 같은 레지스터 비트 2..0 (IIR) | **`100`** (스파이크 감쇠 없음) |
| 정착시간 | **95.2ms** — 100ms 프레임에 실측으로 들어온다 |

`FIR=110`(512탭, 62.5ms)으로 내려 창당 2샘플을 얻는 방법도 있으나 **쓰지 않는다.** 노이즈가 약 1.41배 늘어나는데, 시간축 피크로 잡으려는 건 노이즈 스파이크가 아니라 실제 온도 상승이라 노이즈를 키우면 피크 판정이 오염된다. 창당 1샘플이어도 `IIR=100`이면 그 샘플이 감쇠 없는 실값이라 목적은 달성된다.

**정착시간 공식** (Melexis 앱노트 *Understanding MLX90614 on-chip digital signal filters*):

```
Tset = 9.719 + IIRSetting × (FIRSetting + 5.26)
             + IIRSetting × (FIRSetting + 12.542)
             + Dual × IIRSetting × (FIRSetting + 12.542)      [ms]

FIRSetting:  101→9.28(256탭)   110→17.472(512탭)   111→33.856(1024탭)
IIRSetting:  100→1(감쇠없음)   101→4   110→8   111→9   000~011→10(0.5)
```

| 설정 | 정착시간 |
|---|---|
| **IIR=`100`, FIR=`111`** | **95.2ms ← 확정값** |
| IIR=`100`, FIR=`110` | 62.5ms |
| IIR=`000`, FIR=`111` | **864.9ms ← 공장 기본값** |

**EEPROM 쓰기 절차 (반드시 read-modify-write)**

```
1. 현재 값 읽기:  SMBus read word, 커맨드 0x25
2. FIR(10..8), IIR(2..0) 비트만 교체.  나머지 비트는 그대로 유지한다.
   ⚠️ 특히 비트 3과 비트 6은 절대 바꾸지 않는다.
3. 지우기:        SMBus write word, 커맨드 0x25, 데이터 0x0000
4. 5ms 이상 대기
5. 쓰기:          SMBus write word, 커맨드 0x25, 새 값
6. 5ms 이상 대기 후 다시 읽어 값이 반영됐는지 확인
7. 전원 재인가 (EEPROM 설정은 리셋 후 적용된다)
```

> **비트 3을 건드리면 공장 캘리브레이션이 날아가고 되돌릴 수 없다.** 데이터시트: *"Bit 3 should not be altered as this will cancel the factory calibration."* 통짜로 쓰지 말고 반드시 읽어서 해당 비트만 바꾼다.
>
> **EEPROM은 쓰기 횟수에 한계가 있다.** 기동할 때마다 쓰지 말고 **읽어서 다르면 쓰는 방식**으로 한다.
>
> **검증법**: 설정 후 손을 센서 앞에 갑자기 넣었다 빼며 `TOBJ1`을 20ms마다 로깅한다. 약 95ms 안에 안착하면 성공, 약 865ms면 재설정이 안 먹은 것이다.

**누가 언제 하는가 — 두 겹이다.**

| 겹 | 시점 | 하는 일 |
|---|---|---|
| 1 | **조립 시 1회 (수동)** | 두 센서의 `0x25`를 위 절차대로 쓴다. 동작하는 파이썬 예제는 `mode1_beginner_guide.md` **STEP 19**에 있다 |
| 2 | **에지 기동 시마다 (자동)** | `0x25`를 **읽어서** 목표값과 다르면 이벤트를 발행한다. 다르면 그 세션의 IR 온도는 **피크가 절반으로 깎인 데이터**이므로 조용히 넘기면 안 된다 |

조립 때 손으로 끝내는 이유는 **주소 변경(`0x2E`)과 같은 EEPROM·같은 PEC 규칙·같은 전원 재인가**라 한자리에서 처리하는 게 자연스럽고, 에지 소프트웨어가 없는 시점에도 하드웨어가 완성 상태로 남기 때문이다. 겹 2는 센서를 교체했을 때 재설정을 빠뜨리는 것을 잡는 안전망이다.

> ⚠️ **겹 2에서 자동으로 쓰지는 않는다.** EEPROM 쓰기 횟수 한계가 있고, 쓴 뒤 전원 재인가가 필요해 런타임에 반영할 수 없다. **읽어서 알리는 것까지가 소프트웨어의 몫이다.**

### 6-3. #2의 주소를 0x5B로 바꾸는 절차

**두 센서 모두 출고 시 `0x5A`다. 반드시 한 개씩 따로 연결해서 작업한다.** 둘을 동시에 물린 채로 쓰면 두 개가 같이 응답해 버스가 깨진다.

```
1. #2로 쓸 센서 하나만 버스에 연결한다.  (#1은 뽑아 둔다)
2. 확인:  sudo i2cdetect -y 1   ->  5a 하나만 보여야 한다
3. 현재 값 읽기:  SMBus read word, 주소 0x5A, 커맨드 0x2E
4. 지우기:        SMBus write word, 주소 0x5A, 커맨드 0x2E, 데이터 0x0000
5. 10ms 이상 대기
6. 쓰기:          SMBus write word, 주소 0x5A, 커맨드 0x2E, 데이터 0x005B
                  (하위 바이트에만 주소가 들어간다 — "LSB only")
7. 전원 재인가.   EEPROM 값은 리셋 후에 적용된다.
8. 확인:  sudo i2cdetect -y 1   ->  5b 로 바뀌어 있어야 한다
9. #1을 다시 연결하고 둘 다 확인:  5a 와 5b 가 같이 보인다
```

> ⚠️ **쓰기 프레임에는 PEC 바이트가 필수다.** write word 프레임은 `SA+W | 커맨드 | LSByte | MSByte | PEC`이고(데이터시트 Figure 7), PEC는 `SA<<1`부터 MSByte까지의 **CRC-8(다항식 X⁸+X²+X¹+1, 초기값 0)**이다. 없거나 틀리면 칩이 **에러를 내지 않고 그냥 무시한다** — "지우기는 된 것 같은데 쓰기가 안 먹는다"는 형태로 나타난다. `smbus2`의 `write_word_data()`는 PEC를 안 붙이므로 `bus.pec = 1`을 켜거나 `i2c_msg.write()`로 프레임을 직접 구성한다. 동작하는 파이썬 예제는 `mode1_beginner_guide.md` STEP 18에 있다. **§6-2의 `0x25` 재설정에도 똑같이 적용된다.**
>
> EEPROM 커맨드는 `0x20 | EEPROM주소`다. EEPROM `0x0E` → 커맨드 **`0x2E`**, ConfigRegister1 `0x05` → **`0x25`**.
>
> **주소 `0x00`은 general call이라 MLX90614가 자기 주소와 무관하게 항상 응답한다.** 주소를 잘못 써서 못 찾게 됐다면 `0x00`으로 접근해 복구할 수 있다. 이때도 버스에 센서가 하나뿐이어야 한다.
>
> **주소를 바꾼 센서에는 케이블에 라벨을 붙인다.** 겉으로는 구분할 방법이 없다.

### 6-4. 왜 2개인가 — 공간 피크는 소자 1개로 불가능하다

**MLX90614는 서모파일 소자 하나짜리, 즉 1픽셀 센서다.** 데이터시트: *"The measured value is the average temperature of all objects in the Field Of View of the sensor."* 설정으로 바꿀 수 있는 게 아니라 소자의 물리적 성질이다.

| 피크의 종류 | 의미 | 가능한가 |
|---|---|---|
| **시간축 피크** | 100ms 창 안 여러 샘플 중 최댓값 | **가능** — §6-2 설정 + §6-5 |
| **공간 피크** | FOV 안에서 가장 뜨거운 지점 | **불가능** — 단일 소자 |

**→ 그래서 2개를 다른 지점에 겨눠 2픽셀로 만든다.** 해상도는 거칠지만, "한쪽 끝만 뜨겁다"를 한 개짜리 광각 평균이 완전히 지워버리는 것보다는 훨씬 낫다.

| | 겨누는 곳 | 주소 |
|---|---|---|
| U3 (#1) | 셀 **중앙** | `0x5A` |
| U9 (#2) | 셀 **단자쪽**(양극 부근 — 내부 저항이 가장 큰 지점) | `0x5B` |

**FOV가 셀만 보게 만든다 — 부착 거리 2cm 이내.** 스팟 지름 = `2 × 거리 × tan(17.5°)` = `0.63 × 거리`:

| 센서~셀 거리 | 스팟 지름 | 18650(지름 1.8cm) 기준 |
|---|---|---|
| 1cm | 0.63cm | 셀 안에 완전히 들어감 |
| **2cm** | **1.26cm** | 셀 안에 들어감 — **권장 상한** |
| 3cm | 1.89cm | 셀 폭을 살짝 넘음 |
| 5cm | 3.15cm | 배경이 절반 이상 섞임 |
| 10cm | 6.31cm | 대부분이 배경 온도 |

5cm만 떨어져도 상온 배경이 절반 넘게 섞여 **실제 셀 온도보다 낮게** 읽힌다. 부착 치수는 가이드 §3.

> FOV 35°는 **감도 50% 지점** 기준이다(데이터시트 Figure 27). 그 바깥의 복사도 약하게 기여하므로 위 표는 하한이 아니라 목표치다. 가까울수록 좋다.
>
### 6-4b. 향후 IR 어레이로 교체할 여지 — 계약을 지금 그렇게 잡아 둔다

**현재 구성은 2존 + 접촉 3점 = 5점이다.** 다만 **공간 피크를 직접 내주는 IR 어레이 센서(MLX90640 32×24 등)로 바꿀 가능성이 있다.** 어레이는 픽셀별 값을 주므로 "단소자라 공간 피크가 불가능하다"는 위 §6-4의 전제 자체가 사라진다.

**교체가 오면 무엇이 바뀌고 무엇이 그대로인가** — 지금 계약을 이 경계에 맞춰 두면 교체가 국소 작업으로 끝난다.

| | 교체 시 |
|---|---|
| **그대로 유지** | `temp_ir_surface` — 정의가 **"IR로 본 표면온도의 공간 피크"**여서 소자 구성과 무관하다. 어레이에서는 ROI 안 픽셀의 `max`가 된다 |
| **그대로 유지** | §6-5의 두 겹 피크 규칙(시간축 위에 공간축), §9 프레임 필드 이름, 등급 판정 |
| **없어짐** | 주소 분리(`0x2E`)·필터 재설정(`0x25`)·2개 배치 — 전부 단소자 MLX90614 전용이다. 가이드 STEP 4·18·19가 통째로 사라진다 |
| **길이가 바뀜** | `temp_points.ir` — 현재 고정 2(`[중앙, 단자쪽]`), 어레이면 ROI 존 개수만큼 |

> ⚠️ **그래서 `temp_points.ir`의 길이 2를 코드에 상수로 박지 마라.** 배열을 순회하고 최댓값을 쓰는 방식으로 짜면 교체가 설정 변경으로 끝난다. 반대로 `ir[0]`·`ir[1]`을 직접 인덱싱하면 교체 때 AI 특징 추출까지 손봐야 한다. **`temp_ir_surface`가 계약의 본체이고 `temp_points.ir`는 부가 정보다.**

> 접촉 3점(DS18B20)은 교체 대상이 아니다. IR은 표면만 보고 접촉은 다른 열경로를 보므로, 어레이로 바꿔도 접촉 3점은 남는다.

### 6-5. `temp_ir_surface` 산출 — 피크가 두 겹이다

```
[MLX90614 스레드]  95ms 간격으로 #1(0x5A)·#2(0x5B)의 TOBJ1을 순차로 읽어
                   각각 100ms 발행 창의 버퍼에 모음
[발행 스레드]      T1 = max(#1 샘플들)                 <- 시간축 피크
                   T2 = max(#2 샘플들)
                   temp_ir_surface = max(T1, T2)      <- 공간 피크
                   temp_points.ir  = [T1, T2]
                   샘플이 0개면 직전 값 유지 + age_ms 갱신
```

**두 축 모두 평균이 아니라 최댓값**을 쓴다. 열폭주 탐지에서 놓치면 안 되는 건 순간적으로 튀는 고온과 국부적으로 뜨거운 지점이지, 평활화된 대표값이 아니다.

> **두 존의 차이(`|T1 − T2|`)도 그 자체로 지표다.** 셀 한쪽 끝만 달아오르는 것은 국부 과열의 직접 증거라, `temp_points.ir`로 개별값을 함께 싣는다(§9).
>
> **순서를 바꾸면 안 된다.** 진짜로 의미 있는 건 §6-2의 IIR 재설정이고 `max`는 그 위에 얹는 마무리다. 출고 설정 그대로 `max`만 취하면 **이미 절반으로 깎인 값들 중 최댓값**을 고르는 셈이다.

### 6-6. 그 밖의 주의사항

- 방사율(emissivity) 기본값은 1.0이다. 배터리 표면(무광 필름)은 0.9~0.95라 **약간 낮게 읽힌다.** 칼만 필터와 내부 셀 온도 추정은 AI 서버 몫이므로 **에지는 raw 그대로 보낸다.**
- 정확도(±0.5°C)는 **센서가 열평형 상태일 때만** 보장된다. 센서 뒤나 옆에 발열체가 있으면 패키지에 온도 구배가 생겨 값이 틀어진다.
- I2C 클럭 스트레칭 문제로 간헐적 오류가 나면 `/boot/firmware/config.txt`에 `dtparam=i2c_arm_baudrate=50000`으로 낮춘다.

## 7. DS18B20 ×3 (1-Wire) — 접촉 온도 3점

커널 드라이버(`w1-gpio` + `w1_therm`)가 sysfs로 노출한다. 1-Wire 프로토콜을 직접 구현할 필요가 없다.

### 7-1. 활성화와 읽기

`/boot/firmware/config.txt`: `dtoverlay=w1-gpio,gpiopin=4`

```
/sys/bus/w1/devices/28-XXXXXXXXXXXX/w1_slave

a1 01 4b 46 7f ff 0c 10 07 : crc=07 YES
a1 01 4b 46 7f ff 0c 10 07 t=26062
```

- 첫 줄이 `YES`로 끝나야 유효하다. `NO`면 **CRC 실패 — 그 값은 버린다.**
- `t=26062` → **26.062 °C** (밀리도).
- **`85000`(85.0°C)은 오류 코드다.** 변환이 끝나기 전에 읽었거나, 전원 문제이거나, 4.7kΩ 풀업이 없을 때 나온다. 정상값으로 취급하면 안 된다.

### 7-2. 3개를 같은 버스에 다는 방법

**1-Wire는 원래 멀티드롭이다.** 각 DS18B20이 공장에서 구워진 **고유 64비트 ROM 코드**를 갖고 있어 주소 설정 작업이 없다. 세 개를 같은 3선(GPIO4 + 3.3V + GND)에 병렬로 물리면 커널이 각각을 `28-`로 시작하는 별개 디렉토리로 잡아 준다.

**⚠️ 개수가 늘어도 변환 시간은 750ms 그대로다.** `Skip ROM(0xCC) + Convert T(0x44)`를 한 번 쏘면 버스의 **모든** 센서가 동시에 변환을 시작한다. 순차로 하나씩 시키면 2250ms가 된다.

| 방법 | 하는 법 | 특징 |
|---|---|---|
| **일괄 변환** (권장) | `/sys/bus/w1/devices/w1_bus_master1/therm_bulk_read`에 `trigger`를 쓰고, 750ms 뒤 각 센서의 `temperature` 파일을 읽는다 | 한 번에 셋 다. 커널 5.x+ 필요 |
| 개별 읽기 | 각 `w1_slave`를 읽는다 | 파일을 열 때마다 그 센서만 변환 → **750ms × 3 = 2250ms** |

> **기동 시 `ls /sys/bus/w1/devices/w1_bus_master1/therm_bulk_read`로 지원 여부를 확인해 로그에 남기고**, 미지원이면 `battery-events`로 알린다. §1의 신선도 문제가 3배로 악화된다.

### 7-3. ⚠️ ROM 코드와 물리 위치의 대응

**ROM 코드만 봐서는 어느 센서가 셀의 어디에 붙어 있는지 알 수 없다.** 커널이 잡는 순서는 버스 스캔 순서이지 배선 순서가 아니다.

**대응 절차 (조립 시 1회)**: 세 센서를 다 연결하고 ROM 코드를 나열한다 → 손가락으로 하나만 잡는다 → 값이 올라간 것의 ROM 코드가 그 센서다 → 셋을 반복해 설정 파일에 고정한다.

```yaml
# 예: edge/config.yaml
ds18b20:
  "28-0316a279c1ff": { position: "bottom" }   # 셀 하단
  "28-0316b4410aff": { position: "middle" }   # 셀 중앙
  "28-0316c8823bff": { position: "terminal" } # 셀 상단·단자쪽
```

> **ROM 코드를 하드코딩하지 마라.** 설정 파일로 뺀다. 센서를 교체하면 ROM 코드가 바뀌므로, 설정 파일에 없는 코드가 나타나면 조용히 무시하지 말고 이벤트를 발행한다 — 위치를 모르는 센서의 값은 `temp_points.contact`에 넣을 자리가 없다.

### 7-4. `temp_contact` 산출

```
temp_contact = max(유효한 3점)
```

- CRC 실패(`NO`)·85.0°C 값은 최댓값 계산에서 **제외**한다. **85.0°C는 오류 코드인데 그대로 넣으면 항상 그게 최댓값이 된다.**
- 유효한 값이 하나도 없으면 `temp_contact = null` + 이벤트.
- 개별값은 `temp_points.contact`에 **위치 순서(bottom, middle, terminal)로 고정 배열**해 싣는다. ROM 코드 순서가 아니다.

> **왜 최댓값인가**: 열폭주는 국부에서 시작한다. 3점 평균을 쓰면 한 점만 뜨거워진 초기 상태가 1/3로 희석된다. **지점 간 온도차(`max − min`)가 벌어지는 것 자체가 국부 과열의 직접 증거**라, `temp_points`를 함께 싣는다(§9).

## 8. 릴레이 GPIO 제어 계약

### 8-1. 채널 매핑

| 채널 | BCM | 물리 핀 | 역할 | 경로 |
|---|---|---|---|---|
| CH1 | **GPIO5** | 29 | 충전 | ZY12PDN 5V → Babysitter `VIN` |
| CH2 | **GPIO6** | 31 | 방전 | Babysitter `SYS+` → BW150 부하 + |
| CH3 | **GPIO13** | 33 | **마스터 Kill-Switch** | 셀 + 메인 경로 (INA226 `IN+` ↔ Babysitter `BAT+`) |
| CH4 | **GPIO19** | 35 | 예비 (모드 2용, 미배선) | — |

### 8-2. active-LOW

| GPIO 값 | 릴레이 접점 | 회로 |
|---|---|---|
| `0` (LOW) | 붙음 | **도통** |
| `1` (HIGH) | 떨어짐 | **차단** |

모든 배터리 경로가 **NO(Normally Open)** 접점을 지난다 → 전원 상실·부팅 중·프로세스 크래시 = **자동 차단(fail-safe)**.

### 8-3. 부팅 시 보장 — 세 겹

| 겹 | 수단 | 커버 구간 | 확실성 |
|---|---|---|---|
| 1 | `/boot/firmware/config.txt`의 `gpio=5,6,13,19=op,dh` | 펌웨어 부팅 시점 | **⚠️ Pi 5에서 검증 필요**(§13 H3) |
| 2 | 하드웨어 10kΩ 풀업 (R3~R6) | **전원 인가 순간부터 항상** | 확실 |
| 3 | 소프트웨어가 기동 직후 네 핀을 `1`로 명시 설정 | 프로세스 시작 이후 | 확실 |

> 1번이 안 되더라도 치명적이지는 않다 — **2번이 이 셋 중 유일하게 소프트웨어에 의존하지 않는 층**이라 전원 인가 순간부터 항상 유효하다. 그래서 **R3~R6을 생략하면 안 된다.**

### 8-4. ⚠️ 인터락 규칙

```
불변식 1:  CH1 == 0  AND  CH2 == 0   은 절대 허용하지 않는다   (충전·방전 동시 금지)
불변식 2:  CH3 == 1  이면 CH1·CH2 값과 무관하게 셀은 분리 상태다
```

**전환 절차** (충전 ↔ 방전):
```
1. 현재 채널을 1(차단)로 올린다
2. ≥ 50 ms 기다린다            ← 기계식 릴레이 접점이 실제로 떨어지는 시간
3. 다음 채널을 0(도통)으로 내린다
```
50ms를 안 기다리면 두 접점이 겹치는 순간이 생겨 **충전기 출력과 전자부하가 직결**된다.

**차단 절차** (Fail-Safe / Kill-Switch):
```
1. CH1 ← 1, CH2 ← 1   (동시)
2. CH3 ← 1
```
순서를 지킨다. **CH3을 먼저 열면 부하 전류가 흐르는 중에 접점이 떨어져 아크가 튄다.**

### 8-5. 자동 복구 없음

**한 번 차단되면 재인증 + 사유 입력으로 수동 복구만 가능하다.** 에지 소프트웨어는 스스로 릴레이를 다시 붙이지 않는다. 온도가 내려갔다고 자동 재개하는 로직을 만들지 말 것.

### 8-6. CH3을 열었을 때의 부작용 (센서 오류로 오인 금지)

| 현상 | 원인 | 처리 |
|---|---|---|
| I2C `0x55`가 사라짐 | BQ27441이 셀에서 전원을 받음 | 정상. `soc_pct` = null, 오류 아님 |
| `current_a` ≈ 0 | 경로가 끊김 | 정상 |
| `voltage_v`는 계속 나옴 | INA226은 Pi 3.3V로 동작 | 정상 — **셀 개방전압(OCV) 감시가 살아있다** |

CH3이 열린 상태에서 `0x55` 미응답을 센서 오류로 쏘면 알림이 폭주한다. **릴레이 상태를 조건으로 걸어야 한다.**

> **셀 보호회로(PCM)가 끊길 때도 같은 증상이 난다** — 전압이 0으로 떨어지고 `0x55`가 사라진다. CH3이 닫혀 있는데 이 현상이 나오면 PCM 동작을 의심한다. 회로에 퓨즈가 없어 PCM이 유일한 과전류 보호다.

## 9. `battery-raw-metrics` 매핑 (모드 1)

| JSON 필드 | 출처 | 변환 |
|---|---|---|
| `device_id` | 설정 파일 | 라즈베리파이 식별자 |
| `mode` | 고정 | `1` |
| `timestamp` | 발행 시각 | ISO8601, ms 포함, UTC |
| `voltage_v` | INA226 `0x02` | `raw × 0.00125` **그대로 발행 — 보정 없음**(§3-5) |
| `current_a` | INA226 `0x04` (i16) | `raw × 0.0002` — **양수 = 충전** (§3-4) |
| `power_w` | INA226 `0x03` | `raw × 0.005` |
| `soc_pct` | BQ27441 `0x1C` (LE) | 그대로 (%) |
| `temp_contact` | DS18B20 ×3 sysfs | `t / 1000` (°C) → **3점의 최댓값**(§7-4) |
| `temp_ir_surface` | MLX90614 ×2 `0x07` (LE) | `raw × 0.02 − 273.15` → **2존 × 시간축의 최댓값**(§6-5) |
| `temp_points.contact` | DS18B20 ×3 | `[하단, 중앙, 단자쪽]` — **위치 고정 순서**, ROM 코드 순서 아님 |
| `temp_points.ir` | MLX90614 ×2 | `[중앙(0x5A), 단자쪽(0x5B)]` |
| `pressure_raw` | ADS1115 `0x00` (A0) | ADC 원시 카운트 그대로 |
| `gas_raw` | — | **`null`** (§10) |
| `acoustic_raw` | — | **`null`** (§10) |
| `age_ms` | 각 값의 실측 시각 | 발행 시각 − 실측 시각 (ms). **키가 없으면 이번 프레임 실측** (§1) |

### 9-1. 프레임 예시

```json
{

  "mode": 1,
  "timestamp": "2026-07-28T12:00:00.100Z",

  "voltage_v": 3.82,
  "current_a": -1.25,
  "power_w": -4.78,
  "soc_pct": 81,

  "temp_contact":    36.8,
  "temp_ir_surface": 38.1,

  "temp_points": {
    "contact": [34.1, 36.8, 35.2],
    "ir":      [38.1, 35.9]
  },

  "gas_raw": null,
  "pressure_raw": 420,
  "acoustic_raw": null,

  "age_ms": { "soc_pct": 640, "temp_contact": 310, "temp_ir_surface": 40 }
}
```

### 9-2. `temp_points` 규칙

| 규칙 | 내용 |
|---|---|
| 배열 길이 | `contact` 3, `ir` 2로 **고정**. 센서가 죽어도 길이는 유지하고 해당 자리에 `null` |
| 순서 | **물리 위치 고정**. `contact` = `[하단, 중앙, 단자쪽]`, `ir` = `[중앙, 단자쪽]` |
| 스칼라와의 관계 | `temp_contact == max(non-null contact)`, `temp_ir_surface == max(non-null ir)` — **불변식**. 어긋나면 버그다 |
| 전부 null이면 | 스칼라도 `null` + `battery-events` 발행 |
| 소비자 | **AI 특징용이다.** 프론트엔드에 노출하지 않는다 |

> **이건 "셀 단위 데이터"가 아니다.** `docs/backend_contract.md`가 범위 밖으로 규정한 건 팩 안의 **여러 셀**(히트맵, `cellIndex`)이다. `temp_points`는 **셀 1개 표면의 여러 지점**이라 다른 얘기다.

> `insulation_mohm`은 스키마에 없다. 넣지 말 것.
>
> `battery_id`는 에지가 모른다. 백엔드가 세션 태깅으로 적재 시점에 붙인다.

## 10. `null`로 고정되는 필드

| 필드 | 모드 1 | 모드 2 | 근거 |
|---|---|---|---|
| `gas_raw` | **`null` 고정** | MQ-2로 측정 | MQ-2 히터가 상시 150mA@5V로 발열해 같은 셀에 붙은 온도 센서 5개를 오염시킨다. 모드 1은 다점 온도가 핵심이라 온도를 택했다 |
| `acoustic_raw` | **`null` 고정** | **`null` 고정** | 센서를 도입하지 않는다. 필드는 스키마에 남긴다 |

**`acoustic_raw`를 왜 필드로만 남기나**: 진짜 조기 신호인 미세 크랙의 음향방출(AE)은 **100kHz~1MHz** 대역이라 ADS1115(860SPS)로는 원리적으로 못 잡는다. 피에조로 잡을 수 있는 건 벤트 파열음뿐인데, 그 시점이면 가스·압력·온도가 이미 먼저 울린다. 나중에 전용 AE 센서를 붙일 여지를 스키마 변경 없이 남겨 둔다.

> ### ⚠️ 모드 1의 사후 대응 안전계층은 압력(FSR 406) 단독이다
>
> 가스·음향 임계 차단은 모드 1에 **존재하지 않는다.** 릴레이 차단 로직을 짤 때 셋이 다 있다고 가정하면 안 된다.
>
> 게다가 압력 계층조차 차단 임계가 미정이라 당분간 **경고만 낸다**(§5-3). **가스 센서 없이 무인 방치 실험을 하지 않는 것**을 권장한다.

## 11. 오류 · 디그레이드 처리

`battery-events` 토픽으로 발행한다. **문구는 만들지 않는다** — code + params만 보낸다.

| 상황 | 감지 방법 | 처리 |
|---|---|---|
| I2C NACK (센서 미응답) | 읽기 예외 | 3회 재시도(50ms 간격) 후 해당 필드 `null` + 이벤트 |
| INA226 ID 불일치 | `0xFE ≠ 0x5449` | 기동 실패로 처리. 배선/주소 오류 |
| INA226 산술 오버플로 | Mask/Enable(`0x06`) **bit 2** (`& 0x0004`) | `current_a`·`power_w`를 `null`로. 전류가 6.55A를 넘은 것(§3-3) |
| BQ27441 `ITPOR` = 1 | Flags(`0x06`) **bit 5** (`& 0x0020`) | Design Capacity 재설정(§4-2) 후 이벤트 |
| BQ27441 미응답 + CH3 열림 | 릴레이 상태 확인 | **정상.** 이벤트 발행 안 함 |
| BQ27441 미응답 + CH3 닫힘 | 릴레이 상태 확인 | 셀 미장착·배선 오류·PCM 차단. 이벤트 |
| DS18B20 CRC `NO` | `w1_slave` 첫 줄 | 그 지점만 `null`, max에서 제외. 5회 연속이면 이벤트 |
| DS18B20 값 = 85.0 | 값 비교 | 변환 미완료/풀업 없음. **max에서 반드시 제외** — 안 그러면 늘 이게 최댓값이 된다 |
| DS18B20 디바이스가 3개가 아님 | 글롭 결과 개수 | 배선 오류·접촉 불량. 이벤트. 남은 센서로 계속 동작하되 빠진 자리는 `null` |
| 설정 파일에 없는 ROM 코드 | 매핑 조회 실패 | 센서 교체 후 §7-3 재매핑 안 함. 이벤트. 위치를 모르므로 값을 쓰지 않는다 |
| MLX90614 `0x5B`가 안 보임 | `i2cdetect` / NACK | 주소 변경 실패·배선 불량. 이벤트. `temp_ir_surface`는 #1만으로 계속 산출 |
| MLX90614 두 개가 같은 주소 | `0x5A`만 잡히고 값이 튐 | **버스 충돌이라 값을 믿으면 안 된다.** 이벤트 + 해당 필드 `null` |
| MLX90614 오류 플래그 | MSB 최상위 비트 | 폐기 + 이벤트 |
| MLX90614 필터가 공장 기본값 | 기동 시 **두 개 다** `0x25` 읽어 IIR 비트 확인 | `100`이 아니면 §6-2대로 재설정. 안 하면 피크가 절반으로 깎이고 갱신이 865ms가 된다 |
| DS18B20 일괄 변환 미지원 | `therm_bulk_read` 파일 확인 | 750ms → 2250ms. 기동 시 로그 + 이벤트 (§7-2) |
| 압력 baseline < 500 카운트 | 세션 시작 10초 후 | FSR 부착 불량. 이벤트 + 압력 계층 비활성 (§5-3) |
| 프레임 발행 지연 > 200ms | 발행 스레드 자체 계측 | 성능 이벤트. 스레드 경합 의심 |

**모든 센서가 죽어도 릴레이 차단 경로는 살아 있어야 한다.** 센서 읽기 코드의 예외가 제어 스레드를 죽이지 않도록 분리한다.

## 12. 검증 절차 — ATORCH BW150 대조

BW150은 **데이터 경로가 아니다.** 하지만 INA226이 맞게 재고 있는지 확인하는 **기준기**로는 쓸 수 있다. (주기 1초, 시리얼 `0xFF 0x55` 프레임 9600 8N1, **절연 없음** — 측정 회로와 GND 공통.)

**절차**

1. BW150을 CC(정전류) 모드로 0.5A / 1.0A / 2.0A에 각각 고정하고 방전시킨다.
2. BW150 시리얼 값을 **오프라인 CSV**로 기록한다 (Kafka로 보내지 않는다).
3. INA226 100ms 스트림을 **1초 평균으로 리샘플**해 CSV와 시각 정렬한다.
4. 비교한다.

**허용 오차**

| 항목 | 허용치 | 근거 |
|---|---|---|
| 전류 | **±2% 또는 ±20mA 중 큰 값** | INA226 게인 오차 0.1% + 션트 공차 1% + BW150 자체 오차 |
| 전압 | **±30mV** | §3-5 보정 오차 + 배선 저항 |
| 전력 | **±3%** | 전압·전류 오차가 곱해지므로 둘의 합보다 조금 넉넉하게 |
| SOC | **±10%** (사이클 적산) | 만충→완방 1사이클의 적산 Wh를 BW150의 Wh와 비교 |

- **온도는 이 검증 대상이 아니다.** BW150에 셀 표면온도 기준기가 없다. DS18B20·MLX90614는 **얼음물(0°C)·체온(36.5°C) 2점 대조**로 따로 확인한다.
- SOC를 순시 대조하지 않는 이유: BQ27441의 SOC는 적산 기반이라 순간값 비교가 무의미하다.

허용치를 넘으면 의심 순서: ① CAL 값(§3-3) ② 션트 저항 실측값 ③ Kelvin 배선(션트 감지선이 전류 경로에 끼어 있는지) ④ GND 공통 여부.

> **BW150 프레임 파싱이 안 되면 화면을 눈으로 읽어 수동 기록해도 이 검증은 성립한다**(§13 H7).

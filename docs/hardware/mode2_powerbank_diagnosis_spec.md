# 모드 2 (보조배터리) — 즉시 진단 스펙

완제품 USB 보조배터리를 진단기에 연결했을 때 **그 배터리의 정보·현재 출력량·열화상태를 한 자리에서** 확인하게 하는 기능의 계약서다.

- 상위 API 계약: `docs/backend_contract.md`
- 디자인 무관 기능 계약: `docs/product_contract.md` F21
- 모드 1 대응 문서: `docs/hardware/mode1_backend_spec.md`
- 회로도: **아직 없지만 막는 것도 없다.** 부하 수단(§2-4)·릴레이 매핑(§2-5)·배선(§2-7)이 모두 확정됐고 BW150의 5V 부하 가능 여부도 제조사 사양표로 통과했다. `hardware/mode2/` 작업을 착수할 수 있다
- 보유부품 통합형 조립 가이드: [`mode1_mode2_combined_beginner_guide.md`](mode1_mode2_combined_beginner_guide.md) — `COMBINED_EXISTING_PARTS_V1`. STEP 1~29를 자체적으로 싣는 단독 작업서이며(모드 1 회로를 STEP 12까지 만들어 둔 상태에서 이어받아도 된다) **0.5A·10초 전기 시운전 프로필**이다. 안전 준비가 끝날 때까지 F21 빠른 진단·정밀 용량시험은 차단한다. 아래 완전형 릴레이 매핑과 혼용하지 않는다

**범위**: 모드 2(보조배터리)만. 이 문서는 설계 계약이며 회로도·목업·구현 코드는 후속이다.

> **한 줄 요약** — 보조배터리는 부스트 컨버터가 셀을 가려서 셀을 직접 볼 수 없다. 그래서 **"부하를 걸었을 때 어떻게 반응하는가"**로 열화를 우회 추정하고, 그 결과를 **빠른 진단(약 2분, 신뢰도 낮음)**과 **정밀 용량 테스트(수 시간, 신뢰도 높음)** 두 층으로 나눠 낸다. 여기에 **열폭주 위험 스크리닝(15분, §9)**이 더해진다 — 같은 부하 반응을 쓰지만 **열화(수명)가 아니라 이상점수(열폭주 위험) 축**의 판정이다.

## 1. ⚠️ 출력단 내부저항은 무의미하다 — 먼저 읽을 것

배터리 열화를 재는 고전적 방법은 내부저항이다. 부하를 걸었다 끊으며 `ΔV/ΔI`를 재면 셀이 늙은 만큼 값이 커진다. **모드 1(외부 셀)에서는 이게 통한다.** 셀 단자에 직접 붙기 때문이다.

**모드 2에서는 통하지 않는다.**

```
 [셀 3.0~4.2V] ── [보호회로] ── [DC-DC 부스트] ── [USB 출력 5V] ── 진단기 INA226
                                     ▲
                          여기가 전압을 5V로 붙잡는다
```

완제품 보조배터리는 셀과 USB 출력 사이에 **승압 컨버터**가 있다. 셀이 4.2V든 3.2V든 컨버터가 출력을 5V로 레귤레이션한다. 즉 진단기가 INA226으로 재는 `voltage_v`는 **셀 전압이 아니고 컨버터 출력 전압**이다.

따라서 출력단에서 `ΔV/ΔI`를 재면 나오는 값은:

- ❌ 셀의 내부저항이 **아니다**
- ✅ 컨버터의 출력 임피던스 + 케이블·커넥터 접촉저항이다 

이 값은 셀이 얼마나 늙었는지와 거의 무관하다. **모드 2의 `internalResistanceMohm`은 `null`로 확정한다**(§5).

### 그래서 무엇을 보는가

컨버터는 전압은 붙잡지만 **에너지를 만들어내지는 못한다.** 셀이 열화하면 컨버터가 셀에서 끌어와야 하는 전류가 커지고, 그 결과가 출력 쪽에 세 가지 흔적으로 남는다.


| 흔적                 | 물리                                    | 열화 시 방향            |
| ------------------ | ------------------------------------- | ------------------ |
| **레귤레이션을 포기하는 지점** | 셀 전압이 처지면 입력 전류(`≈ I_out×5V/(V_cell×η)`)가 커져 컨버터의 **스위치 전류 한계**에 닿거나, 부하 순간 셀 전압이 팩 BMS의 **저전압 차단(UVLO)**에 찍힌다. (~~듀티 한계~~가 아니다 — 5V 승압은 셀 3.0V에서도 듀티 40%라 한계(90%+)에 안 닿는다. 2026-08-08 정정) | 더 **낮은** 전류에서 무너진다 |
| **같은 출력에 대한 발열**   | 셀 내부저항 상승분이 `I²R` 손실로 열이 된다           | 더 **빨리** 뜨거워진다     |
| **광고 스펙 도달 여부**    | 정격 2A를 못 내면 셀이나 컨버터가 그만큼 못 버틴다        | 도달률이 **떨어진다**      |


이 셋이 §3 빠른 진단의 3지표다. 그리고 이 셋 전부보다 확실한 건 **실제로 몇 Wh가 나오는지 끝까지 빼 보는 것**이며(§4), 그게 정밀 테스트다.

## 2. 하드웨어 전제

### 2-0. 하드웨어 프로필 — 완전형과 보유부품 통합형을 섞지 않는다

하드웨어 프로필은 에지 배포 설정값이며 API의 `mode`를 대체하지 않는다. 서버는 동일 값을 `device_id`별 배포 메타데이터로 관리하고, Raw 프레임에는 추가하지 않는다. 둘 다 측정 모드는 `2`지만 릴레이와 안전 가용성이 다르다.


| 프로필                          | 용도                          | 릴레이 계약                                          | F21 진단 실행                   |
| ---------------------------- | --------------------------- | ----------------------------------------------- | --------------------------- |
| `MODE2_FULL`                 | 이 문서 §2-1~§2-7의 완전한 모드 2 회로 | CH1 충전·CH2 방전·CH3 마스터·CH4 포트 선택                 | backend capability·물리 안전 게이트에 따름           |
| `COMBINED_EXISTING_PARTS_V1` | 모드 1 회로와 INA226·4채널 릴레이를 공유 | CH1·CH2는 모드 2에서 항상 OFF, CH3 마스터, CH4 모드 2 방전 경로 | backend capability로 실행하되 물리 기능은 시운전·프로필 제약을 따른다 |


`COMBINED_EXISTING_PARTS_V1`의 고정 제한:

- 모드 2 자동 충전과 충전전류 측정 없음 — 외부 충전기로 완충
- MQ-2 없음 — `gas_raw=null`, 가스 Fail-Safe 없음
- DS18B20·FSR은 모드 2에서 사용하지 않음 — `temp_contact=null`, `temp_points.contact=null`, `pressure_raw=null`
- `soc_pct`는 V1 시운전 프레임에서 반드시 `null`; 적산 구현은 안전 재검증 후 새 프로필 버전으로 승격할 때 §3-5의 상대 적산 의미로 추가
- 빠른 진단·정밀 용량시험 API의 실행 여부는 backend capability·릴레이·디바이스 게이트로 판단한다. Fail-Safe 문턱 `0` 자체를 `SAFETY_PROFILE_NOT_READY`로 바꾸지 않는다
- `SOURCE_P`에는 셀 홀더 양극과 USB-A VBUS 중 하나만 체결하고, 두 전원을 영구 병렬하지 않음

이 프로필을 제품 F21 진단으로 승격하려면 MQ-2 분압·배치와 임계, 온도 절대값·상승률, 최소 유지 부하, BW150 제어/컷오프, INA226 연속 OVF 감시를 실측·구현하고 재검증해야 한다. **사람이 지켜본다는 조건은 이 게이트를 대체하지 않는다.**

### 2-1. 재사용하는 센서

모드 1과 모드 2는 **인터락으로 동시 활성이 불가**하므로(`CLAUDE.md`) 같은 소자를 물리적으로 옮겨 쓸 수 있다.


| 소자             | 주소                  | 모드 2에서의 역할                                                                          | 필드                                  |
| -------------- | ------------------- | ----------------------------------------------------------------------------------- | ----------------------------------- |
| INA226 **×1**  | I2C `0x40`          | 전압·전류·전력. **CH4로 방전(USB-A 출력)·충전(입력 포트) 두 경로를 번갈아 본다**(§2-7)                        | `voltage_v`, `current_a`, `power_w` |
| MLX90614 ×2    | I2C `0x5A` / `0x5B` | 케이스 표면 IR 온도 2존 (중앙 / USB 포트쪽)                                                      | `temp_ir_surface` = 두 존의 최댓값        |
| MQ-2 → ADS1115 | I2C `0x48` `A0`     | 오프가스 감지 — 모드 2의 사후 대응 안전계층. ⚠️ **히터가 상시 150mA@5V로 발열해 §3-2의 발열 기울기를 오염시킨다**(§8 H11) | `gas_raw`                           |
| 릴레이 4채널        | GPIO 5/6/13/19      | 충전·방전 경로 + 마스터 차단 + **CH4 포트 선택**(§2-5)                                             | —                                   |


**모드 2에 없는 것**: DS18B20(케이스에 가려 셀 접촉 불가) → `temp_contact`는 `null`. FSR 406(외장 케이스에 부착 불가) → `pressure_raw`는 `null`. BQ27441(셀에 접근 불가) → `soc_pct`는 INA226 적산 상대값.

### 2-2. IR 부착 거리는 모드 1보다 여유롭다

MLX90614-DCC는 FOV 35°라 스팟 지름 = `0.63 × 거리`다. 모드 1은 18650 지름이 1.8cm라 **2cm 이내**여야 했지만, 보조배터리는 케이스 폭이 6~7cm이므로 **5cm 거리에서도 스팟 3.2cm**로 대상 안에 들어온다.

**두 존의 겨냥 지점**: `0x5A` = 케이스 중앙(셀 뭉치 위), `0x5B` = **USB-A 출력 포트쪽**(§2-7에서 방전 경로로 확정한 그 포트). 포트쪽을 반드시 한 존으로 두는 이유는 부스트 컨버터와 출력 MOSFET이 그쪽에 몰려 있어 부하를 걸면 거기가 가장 먼저 뜨거워지기 때문이다.

⚠️ **두 존의 시야가 겹치면 안 된다.** 5cm 거리에서 스팟이 3.2cm이므로 **최소 4cm 이상 벌린다.** 겹치면 두 센서가 같은 곳을 봐서 2개를 쓴 의미가 사라진다(모드 1의 같은 조항과 동일한 이유).

⚠️ **거치대로 위치를 재현할 수 있어야 한다.** IR 거리가 3cm였다 7cm였다 하면 같은 배터리도 다른 온도로 읽혀 **지난 진단과 비교가 안 된다.** 발열 기울기가 열화 지표인 만큼 거리 재현성이 곧 측정 신뢰도다.

### 2-3. ⚠️ 케이스 표면온도는 셀 온도가 아니다

모드 1의 온도 임계(55/60°C)를 모드 2에 그대로 쓰면 안 된다. 보조배터리는 플라스틱·알루미늄 외장이 열을 막아서 **셀이 70°C일 때 케이스 표면은 45°C밖에 안 될 수 있다.** 열시정수도 길어 케이스 온도는 셀보다 수십 초 늦게 따라온다.

그러므로 모드 2의 온도 판단은 **절대값보다 상승률(`dT/dt`)이 주 근거**다. 절대값 문턱은 보수적으로(§3-3) 잡고, 문턱 자체는 실측 후 확정한다(§8 H2).

### 2-4. 부하 수단 — 보유한 ATORCH BW150을 쓴다 (2026-07-28)

§3의 계단 스윙은 **전류를 지정할 수 있는 부하**를 요구한다. **이미 BOM에 있는 BW150 WiFi Standard Edition(×1)을 쓴다.**

> ⚠️ **이 문서 초판은 "BW150은 전류 설정이 수동 버튼이라 자동화 불가"라고 적었다. 틀렸다.**
> `CLAUDE.md`의 *"BW150은 데이터 경로가 아니다"*는 **텔레메트리 주기가 1초라 100ms 스트림에 못 섞인다**는 뜻이지 제어가 안 된다는 뜻이 아니다. 그 조항은 그대로 유효하며(진단 중 측정은 전적으로 INA226이 한다), 부하로 쓰는 것과 충돌하지 않는다 — `CLAUDE.md`는 애초에 BW150을 **"방전 부하 + INA226 검증용 기준기"**로 지정해 두었다.

**BW150을 고르는 근거**


| 근거                         | 내용                                                                                                                                                                   |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **제어가 된다**                 | ATORCH 로드의 시리얼 프로토콜은 양방향이다. `1250MA`/`12.5A`(정전류 지정), `ON`/`OFF`(출력), `10.5VCUT`(컷오프)이 문서화돼 있다. 공개 파이썬 구현이 있다([`tshaddack/dl24`](https://github.com/tshaddack/dl24)) |
| **정밀 테스트는 자동화가 아예 필요 없다**  | §4는 **단일 고정 전류**를 몇 시간 거는 것이다. 1.0A를 한 번 걸어 두면 끝이라 BW150이 코드 없이 오늘 당장 해낸다. 계단 스윙이 필요한 건 §3 빠른 진단뿐이다                                                                  |
| **WiFi 에디션이면 절연 문제가 사라진다** | `CLAUDE.md`가 지적한 *"USB 절연이 없어 측정 회로와 GND가 묶인다"*는 **CH340G 유선을 꽂을 때** 생기는 문제다. Tuya/WiFi로 명령을 넣으면 갈바닉 연결이 아예 없다                                                       |
| **자체 안전 컷오프가 있다**          | 화면의 `STOP: <03.0V><04.2V><0150W><100°C`. 저전압·과전력·**100°C 과열**이 하드웨어 레벨로 걸리고 온도 프로브도 동봉이다. §3-3의 소프트웨어 계층과 **독립된** 안전층이 하나 더 생긴다                                      |
| **부품 추가 구매가 없다**           | 방열 설계도 BW150이 팬으로 이미 해결해 둔 문제다                                                                                                                                       |


#### ✅ V1 통과 — 5V 부하는 사양 범위 안이다 (제조사 사양표 확인, 2026-07-28)

한때 **보드 실크스크린의 `input 8V<V<36V P=U*I<150W`** 때문에 5V 보조배터리를 못 물리는 것 아니냐는 의심이 있었다. **제조사 사양표로 해소됐다 — 그건 부하 입력 범위가 아니다.**


| 항목         | BW150 사양                                           | 이 스펙이 쓰는 값          | 여유                                          |
| ---------- | -------------------------------------------------- | ------------------- | ------------------------------------------- |
| **부하 전압**  | **DC 1V ~ 200V**                                   | 5V                  | 범위 한가운데. 사양서가 *"1V 배터리를 테스트할 수 있으며"*라고 명시한다 |
| **부하 전류**  | 전압 &lt; 5V → `0.01~20A`<br>`전압 &gt; 5V → 0.01~25A` | 0.1 ~ 2.0A          | **10배 이상**                                  |
| **부하 전력**  | 전압 &lt; 36V → **150W**                             | 최대 **10W**(5V × 2A) | **15배**                                     |
| **설정 분해능** | **0.01A**                                          | 계단 0.5A, 미세 스윕 0.1A | 10배                                         |


- **최소 전류 0.01A**라 §2-6의 최소 유지 부하 `0.1A`가 하한의 10배다. 안정적으로 걸리고, H9 실측 결과에 따라 위아래로 조정할 여지도 넉넉하다.
- **분해능 0.01A**라 §3 P6의 0.1A 간격 미세 스윕이 그대로 가능하고, 필요하면 더 촘촘하게도 간다.
- 기기 화면에 18650 전압인 `04.11V`가 떠 있던 것도 이 사양과 일치한다.

⚠️ **배선 지침 — `8V<V<36V`라고 적힌 단자에는 물리지 않는다.** 그 표기가 보드 어딘가에 실제로 인쇄돼 있다는 사실 자체는 남아 있다. 부하 입력이 아니라면 보조전원이나 CDCDC 모드 쪽 단자일 텐데, **보조배터리를 거기 잘못 물리면 사양 밖 동작이 된다.** 조립 문서에 *"부하 입력 단자에 물린다"*를 명시하고, 어느 단자가 무엇인지는 실물에서 확인한다(§8 H1).

| **V2** | BW150이 DL24와 같은 명령셋을 받는가 | 위 파이썬 구현은 **DL24P에서만 검증**됐다. BW150은 같은 ATORCH 소프트웨어 제품군(DL24·DL24P·BW150·BW600 공용 매뉴얼)이지만 확인된 것은 아니다 |
| **V3** | Tuya/블루투스로 명령을 넣을 수 있는가  | 되면 절연 문제가 사라진다. 안 되면 CH340G 유선이며, GND 결합을 감수하거나 USB 절연기를 단다                                          |


**V2·V3가 안 돼도 BW150은 살린다 — 사람이 돌리고 파이가 구간을 검출한다.**

전류를 사람이 손으로 바꾸되, **라즈베리파이는 INA226이 읽는 `current_a`에서 계단(plateau)을 스스로 검출해 구간을 나눈다.** 명령한 시각이 아니라 **측정된 전류가 안정된 시각**부터 §3의 창을 세므로, 조작이 느리거나 불규칙해도 산식이 깨지지 않는다. 정밀 테스트는 애초에 조작이 한 번뿐이라 영향이 없다.

**그래서 V1이 통과한 시점에서 `hardware/mode2/` 회로도를 막는 항목은 없다.**

**대체 후보 (보존용 — V1이 통과했으므로 채택하지 않는다)**


| 후보                                      | 장점                                                                           | 막히는 지점                                                                                                                     |
| --------------------------------------- | ---------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| (b) 고정저항 뱅크 + 릴레이                       | 부품값이 싸고 단순하다. 5V 기준 0.5A=10Ω/2.5W, 1.0A=5Ω/5W, 1.5A=3.3Ω/7.5W, 2.0A=2.5Ω/10W | 계단이 **이산적**이라 §3 P6의 0.1A 미세 스윕이 불가능하다. 4채널 릴레이를 부하에 다 쓰면 **안전 차단 채널이 남지 않는다**. 저항 자체 발열을 IR 센서에서 격리해야 한다                  |

### 2-5. 릴레이 채널 매핑 (2026-07-28 확정)


| CH  | GPIO       | 모드 1 | **모드 2**                                       |
| --- | ---------- | ---- | ---------------------------------------------- |
| CH1 | **GPIO5**  | 충전   | **충전** — ZY12PDN 5V → 노드 M                     |
| CH2 | **GPIO6**  | 방전   | **방전** — 노드 M → BW150 부하                       |
| CH3 | **GPIO13** | 마스터  | **마스터** — INA226 `IN+` ↔ 노드 M                  |
| CH4 | **GPIO19** | 예비   | **포트 선택** — INA226 `IN−`를 출력/입력 포트에 붙인다 (§2-7) |


**CH1·CH2·CH3는 모드 1과 같다. 이게 결정적이다 — 안전 인터락 코드가 한 벌로 유지된다.** `CH1·CH2 동시 도통 금지, 전환 시 50ms 이상 대기`가 모드 판별 없이 그대로 적용된다. 안전 로직에서 두 벌은 곧 버그다. `active-LOW`(`0`=도통, `1`=차단)와 NO 접점도 그대로 — 정전·부팅 중·크래시 시 자동 차단된다.

**CH4만 모드 2에서 용도가 생긴다.** INA226이 1개뿐인데 충전 포트와 방전 포트가 물리적으로 다르기 때문이다(§2-7). ⚠️ **CH4는 안전 채널이 아니다** — 측정 경로 선택기일 뿐이고, 안전은 전적으로 CH3(마스터)가 책임진다. 그래서 CH4가 인터락 코드에 끼어들지 않으며, **모드 1의 안전 로직은 손대지 않는다.**

**CH1(충전)이 있어서 얻는 것**: §4-1의 완충 게이트가 지금은 **사용자 자기신고 하나**뿐이다. 충전 경로가 있으면 **충전 전류가 테이퍼되는 것을 관측해 완충을 기계적으로 판정**할 수 있다. 승압회로 때문에 출력 전압으로는 잔량을 알 수 없으므로(§1), **이게 완충을 객관적으로 확인할 유일한 방법이다.**

⚠️ **모드 2 고유의 부작용 — CH3를 열면 INA226이 0V를 읽는다.** 모드 1에는 "CH3를 열면 BQ27441이 I2C `0x55`에서 사라진다"는 부작용이 있었다. 모드 2에는 BQ27441이 없는 대신 이것이 있다: 마스터를 차단하면 보조배터리가 **무부하가 되어 스스로 출력을 끊고**(§2-6), 전압이 0V로 읽힌다. **이를 "배터리 사망"이나 센서 오류로 오독하면 안 된다.** 릴레이 상태를 조건으로 걸지 않으면 오탐이 폭주한다.

### 2-6. ⚠️ 보조배터리는 무부하가 되면 출력을 스스로 끊는다

대부분의 보조배터리는 소비 전류가 수십 mA 이하로 10~30초 지속되면 출력을 자동으로 차단한다. 절전 기능이며 고장이 아니다.

**이것이 §3의 두 구간을 깬다.**

- **P0** — "10초 무부하"로는 출력이 애초에 켜지지 않아 기준전압을 0V로 읽는다
- **P5** — 부하를 완전히 해제하는 순간 팩이 꺼져 회복 전압을 못 잰다

**그래서 P0·P5는 무부하가 아니라 `최소 유지 부하 0.1A`다.** 따라서 기준전압은 무부하 전압이 아니라 **경부하 출력전압**이며, 필드 이름도 `vLightLoadV`다(`vOpenCircuitV`가 아니다). §3-2의 94% 이탈 문턱은 이 기준 대비로 그대로 성립한다.

유지 부하의 크기와 팩이 꺼지기까지의 시간은 제품마다 다르므로 실측 항목이다(§8 H9).

### 2-7. 배선 — USB-A 방전 / USB-C 충전, INA226 1개 (2026-07-28 확정)

**확정 사항**


| 항목     | 값                                                |
| ------ | ------------------------------------------------ |
| 방전 경로  | **USB-A 출력 포트**                                  |
| 충전 경로  | **USB-C(또는 micro-USB) 입력 포트** — 방전과 **다른 물리 포트** |
| 션트     | **R010 (0.01 Ω)** → **CAL = 2560** (`0x0A00`)    |
| INA226 | **1개** (`0x40`). CH4로 두 포트를 번갈아 본다               |


> 포트가 **하나로 겸용**인 제품이면 CH4가 필요 없다 — 충·방전이 한 노드에서 만나 션트 하나가 자동으로 둘 다 본다. 그때는 CH4를 예비로 되돌린다. 실물 확인 항목(§8 H10).

#### 2-7-1. 신호부 — 모드 1과 100% 동일


| INA226 핀 | →   | 연결처                |
| -------- | --- | ------------------ |
| `VCC`    | →   | 3.3V 레일            |
| `GND`    | →   | GND 레일             |
| `SDA`    | →   | Pi 핀 **3** (GPIO2) |
| `SCL`    | →   | Pi 핀 **5** (GPIO3) |
| `ALE`    | →   | **안 붙임**           |


#### 2-7-2. 전력부

```
                          ┌─ CH1(충전) ◀── ZY12PDN 5V +
INA226 IN+ ── CH3 ── 노드M ┤
     ║ (션트 R010)         └─ CH2(방전) ──▶ BW150 부하 +
INA226 IN− ── CH4 ─┬─ NO ──▶ USB-A 출력 포트 VBUS   (방전)
                   └─ NC ──▶ USB-C 입력 포트 VBUS   (충전)

INA226 VBUS ─────────────▶ USB-A 출력 포트 VBUS  ★ CH4를 거치지 않는다
GND ────────────────────── USB-A 출력 포트 GND → 시스템 GND 스타점 (한 가닥)
```


| 네트           | 어디서              | →   | 어디로                                              |
| ------------ | ---------------- | --- | ------------------------------------------------ |
| `PB_OUT_P`   | USB-A 출력 `VBUS`  | →   | CH4 **NO** ***그리고*** INA226 `**VBUS**` (★ 아래 경고) |
| `PB_IN_P`    | USB-C 입력 `VBUS`  | →   | CH4 **NC**                                       |
| —            | CH4 **COM**      | →   | INA226 `**IN−**`                                 |
| `RLY_CH3_IN` | INA226 `**IN+**` | →   | CH3 **COM**                                      |

| —            | CH1 **NO**       | →   | ZY12PDN `VOUT+`                                  |
| —            | CH2 **NO**       | →   | BW150 부하 `+`                                     |
| `PB_N`       | USB-A 출력 `GND`   | →   | 시스템 GND 스타점 **한 점에만**                            |


**부호는 양쪽 다 저절로 맞는다** (모드 1과 동일: 양수 = 충전)


|     | 전류 경로                                                | 방향          | `current_a` |
| --- | ---------------------------------------------------- | ----------- | ----------- |
| 방전  | 팩출력 → CH4 → `IN−` → 션트 → `IN+` → CH3 → CH2 → BW150   | `IN−`→`IN+` | **음수**      |
| 충전  | ZY12PDN → CH1 → CH3 → `IN+` → 션트 → `IN−` → CH4 → 팩입력 | `IN+`→`IN−` | **양수**      |


#### 2-7-3. ★ `VBUS`는 CH4를 거치면 안 된다 — 모드 1과 달라지는 유일한 지점

모드 1은 `IN−`와 `VBUS`를 **같은 점에** 물었다. **모드 2에서 그렇게 하면 안 된다.**

```
   ✗ 모드 1 습관대로                  ✓ 모드 2에서 맞는 배선

   팩 출력 ─[CH4]─┬─ IN−             팩 출력 ─┬─[CH4]─ IN−
                  └─ VBUS                     └─────── VBUS
```

릴레이 접점 저항은 **50~100mΩ**이다. 2A에서 **100~200mV**가 떨어지는데 §3-2의 이탈 판정 문턱이 `V_light`의 6%(5V에서 300mV)다. **릴레이 하나가 문턱의 3분의 1에서 3분의 2를 먹는다.** 멀쩡한 배터리가 열화 판정을 받는다.

`VBUS`를 CH4 **앞**(팩 출력 포트)에서 따오면 접점 저항이 전류 경로에만 남고 측정에서 빠진다. BW150 쪽 전압 여유만 조금 깎일 뿐 정확도에는 영향이 없다.

#### 2-7-4. ⚠️ CH4는 반드시 무전류에서 전환한다 (냉전환)

전류가 흐르는 중에 접점을 옮기면 **아크가 튀어 접점이 탄다.** 접점 저항이 올라가면 §2-7-3에서 피한 문제가 되돌아온다.

```
1. CH1·CH2 차단           → 전류 0
2. CH3(마스터) 차단        → 완전 무전류
3. 50ms 이상 대기
4. CH4 전환
5. 50ms 이상 대기
6. CH3 도통 → CH1 또는 CH2 도통
```

#### 2-7-5. 릴레이 상태표 (`active-LOW`: `0`=도통)


| 상태                       | CH1 충전 | CH2 방전 | CH3 마스터 | CH4 포트선택     |
| ------------------------ | ------ | ------ | ------- | ------------ |
| 정지 · 부팅 · 정전 · Fail-Safe | `1`    | `1`    | `**1**` | —            |
| **방전 (진단)**              | `1`    | `0`    | `0`     | `0` = NO(출력) |
| **충전**                   | `0`    | `1`    | `0`     | `1` = NC(입력) |


> CH4가 NC 접점을 쓰므로 "정전 시 자동 차단" 원칙에서 벗어나 보이지만, **CH3가 NO라 정전이면 전류가 애초에 안 흐른다.** 안전은 CH3가 책임진다(§2-5).

#### 2-7-6. 배치와 배선 규격

**INA226을 USB-A 브레이크아웃 바로 옆에 둔다.** 팩 커넥터와 `VBUS` 탭 사이 구간만 측정 오차에 들어가고, 릴레이·BW150으로 가는 긴 배선은 `IN+` 하류라 아무 영향이 없다.

**USB-A 케이블 굵기가 결과를 바꾼다.** 2A 기준:


| 케이블                 | 왕복 저항    | 2A 강하      | 판정 문턱(300mV) 대비    |
| ------------------- | -------- | ---------- | ------------------ |
| 28AWG · 1m (흔한 싸구려) | ~0.4 Ω   | **800 mV** | ❌ **2.7배 — 결과 조작** |
| 24AWG · 50cm        | ~0.08 Ω  | 160 mV     | ⚠️ 53%             |
| **20AWG · 20cm**    | ~0.014 Ω | **28 mV**  | ✅ 9%               |


**규칙: 20cm 이내 · 20AWG 이상.** 가장 좋은 건 **브레이크아웃에 직접 꽂아 케이블을 없애는 것**이다.

`**PB_N`(GND)은 스타점 한 곳에만 문다.** 충전 전류는 입력 포트로 들어가 **팩 내부를 거쳐 출력 포트 GND로 돌아 나온다** — 두 포트의 GND가 팩 안에서 공통이기 때문이다. 입력 포트 GND를 따로 또 물면 그라운드 루프가 생긴다.

**USB-A는 CC 저항이 필요 없다.** USB-C였다면 `CC1`/`CC2`에 5.1kΩ 풀다운이 없으면 `VBUS`가 0V였다. USB-A는 `VBUS`·`GND` 두 가닥이면 된다. `D+`/`D−`는 **열어 둔다**(2A가 안 뽑히면 그때 `D+`↔`D−` 단락을 시도 — §8 H12).

#### 2-7-7. 션트 R010 — 계산값


| 항목               | 값                                                             |
| ---------------- | ------------------------------------------------------------- |
| `R_shunt`        | 0.01 Ω                                                        |
| **CAL (`0x05`)** | **2560** (`0x0A00`)                                           |
| `Current_LSB`    | 0.0002 A                                                      |
| `Power_LSB`      | 0.005 W                                                       |
| 변환               | `current_a = raw_0x04 × 0.0002`, `power_w = raw_0x03 × 0.005` |
| 측정 상한            | **6.55 A** — 션트 한계(8.19A)가 아니라 **Current 레지스터**가 먼저 걸린다       |



| 사용 범위   | 션트 전압 | ±81.92mV 사용률 | 카운트  |
| ------- | ----- | ------------ | ---- |
| 최소 0.1A | 1 mV  | 1.2%         | 400  |
| 최대 2.0A | 20 mV | 24%          | 8000 |


**기동 시 검산** — `0x01`(Shunt Voltage) × 2.5µV ÷ 0.01Ω 이 `0x04`(Current) × 0.0002 와 일치해야 한다. 어긋나면 CAL이 틀린 것이다.

> 모드 2는 최대 2A라 오버플로가 사실상 없지만 `**Mask/Enable`(0x06) bit 2 = OVF 확인은 그대로 유지한다.** 모드 1과 코드를 한 벌로 쓰기 위해서다.

#### 2-7-8. 연결 후 확인 순서


| 순서  | 확인                    | 기대값                                                 |
| --- | --------------------- | --------------------------------------------------- |
| 1   | 팩 없이 `i2cdetect -y 1` | `**40**`                                            |
| 2   | 션트 실크스크린              | `R010` (다르면 CAL 재계산)                                |
| 3   | 팩 연결 + 유지 부하 0.1A     | `voltage_v` ≈ **5.0V**                              |
| 4   | 부하 0.5A               | `current_a` ≈ **−0.5** ← **양수면 `IN+`/`IN−`가 뒤바뀐 것** |
| 5   | 검산 (§2-7-7)           | 일치                                                  |
| 6   | 부하 2.0A               | OVF 비트 = 0                                          |
| 7   | CH4를 충전 쪽으로 + CH1 도통  | `current_a` **양수**                                  |


4번과 7번이 핵심이다. **부호가 반대로 나오면 즉시 `IN+`/`IN−`를 바꿔 단다.** 에러가 안 나고 조용히 틀리는 종류의 실수다.

| **P7** | **40s** | **`0.9 × regulationKneeA`**(붕괴점을 못 찾았으면 2.0A. 최소 유지 부하 0.1A가 하한) | **신규 — 발열 탐침 구간.** `thermalProbeLoadA`·`thermalPerWattCPerMinPerW` 산출(§3-2 ④) |
| **P5** | **30s** | **0.1A**(최소 유지) | 부하를 내린 뒤의 회복 전압 + **회복 구간 온도 기울기**(§3-2 ④) |
| **P6** | ≤60s    | 미세 스윕           | 무너진 두 단계 사이를 0.1A 간격으로 재스윕. 안 무너졌으면 **생략** |


각 단계의 **후반 절반만** 쓴다. 부하를 바꾼 직후에는 컨버터가 재정착하는 과도구간이라 값이 흔들린다.

**P3만 40초인 이유**: 케이스의 열시정수가 수십 초 단위라(§2-3) 20초 기울기는 노이즈에 묻힌다. 발열 기울기를 재는 구간만 두 배로 둔다.

**⚠️ P0·P5가 무부하가 아니라 0.1A인 이유**: 보조배터리는 무부하가 지속되면 출력을 스스로 끊는다(§2-6). 진짜 무부하로 두면 기준전압을 0V로 읽고 회복 전압도 못 잰다.

**P7이 P4 다음(붕괴점 확정 뒤)에 오는 이유**: P7의 목표 전류는 `regulationKneeA`의 0.9배인데, 이 값은 P0~P4를 다 올라가야 나온다. P7을 그 앞에 두면 목표 전류 자체를 계산할 수 없다. 같은 절대 전류가 팩마다 다른 자극이라(정격 1A 팩엔 과부하, 정격 3A 팩엔 경부하) 붕괴점을 모르는 채로 고정 전류를 걸면 팩 간 발열 비교가 성립하지 않는다 — 그래서 P3(1.5A 고정)의 발열 기울기와 별개로, 붕괴점 대비 정규화된 자극에서 한 번 더 잰다. 0.9는 §9-2 S1d가 EIS 변조 중심에 쓰는 값과 같다.

**P5를 10초에서 30초로 늘린 이유**: P7 직후가 회복 구간이라 "부하를 내렸는데도 온도가 계속 오르는지"를 여기서 볼 수 있다(§9-3 스칼라 ⑩ `T_recover_slope`, §9-7 — 양수면 내부 발열 확정이라 최강 적신호로 다룬다). 10초로는 최소자승 기울기가 안정적으로 안 나온다. **단 이번엔 원값(`recoverySlopeCPerMin`)만 내고 판정·중단 조건으로 승격하지 않는다**(§8 H21).

**단계 경계는 명령 시각이 아니라 측정 전류에서 잡는다.** 부하를 프로그램이 제어하든 사람이 손으로 돌리든(§2-4), 라즈베리파이는 INA226의 `current_a`가 목표값 근처에서 안정된 시점을 계단으로 검출하고 **거기서부터** 위 창을 센다. 그래서 조작이 느리거나 불규칙해도 §3-2의 산식이 깨지지 않는다.

### 3-2. 산지표

**① `regulationKneeA` — 레귤레이션 이탈 전류**

출력전압이 `**V_light`의 94%** 아래로 떨어지는 최소 전류.

- 2.0A까지 버티면 값은 `2.0`에 `kneeIsUpperBound: true`를 붙인다. "2.0A 이상"이지 "정확히 2.0A"가 아니다.
- ⚠️ 이탈은 점진적 처짐만이 아니라 **래치오프(출력 소실, 5V→0V)**로도 나타난다 — IP5306류는 출력 <4.4V 30ms면 통째로 차단한다(§9-1 ②, 2026-08-08 웹 검증). 소실도 정상적인 이탈 관측으로 기록하고, 부하 0A → 팩 재기동 대기 절차를 밟는다. 저가 IC는 한계가 0.8A라 P2(1.0A)에서 이미 걸릴 수 있다 — 시퀀스가 저전류→상행이어야 하는 이유다.
- 절대값(4.7V)이 아니라 `**V_light` 비율**을 쓰는 이유: 9V·12V PD 모드에서도 같은 산식이 성립해야 한다.
- 94%를 고른 근거: 5V에서 4.70V이며 USB 2.0 다운스트림 포트 하한 4.75V 바로 아래다. 이 선을 넘으면 그 보조배터리는 USB 규격 안에서 그 전류를 못 내고 있다는 뜻이다.

**② `thermalSlopeCPerMin` — 발열 기울기**

P3(1.5A) 40초 구간 `temp_ir_surface`의 최소자승 기울기를 분당으로 환산한다. 최소자승을 쓰는 이유는 두 점 차분이 IR 노이즈에 취약하기 때문이다.

**③ `specAttainmentPct` — 스펙 도달률**

```
specAttainmentPct = min(실제 지속 도달 전류, 광고 정격 전류) / 광고 정격 전류 × 100
```

"광고 정격 전류"는 사용자가 자산 등록 시 입력한 값이다. 입력이 없으면 이 지표는 `null`이고 등급 판정에서 제외한다.

**④ P7·P5 발열 원값 — 판정 산식이 아니다**

아래 3개는 **측정만 하고 판정하지 않는** 원값이다. 등급도 문턱도 붙지 않는다. 판정 방식(문턱이냐 학습 모델이냐, 기준선을 어떻게 잡느냐)은 아직 미정이다(§8 H21).

| 필드 | 뜻 |
|---|---|
| `thermalProbeLoadA` | P7에 실제로 건 전류(붕괴점의 0.9배, 상한 조건은 위 P7 행 참조) |
| `thermalPerWattCPerMinPerW` | P7 구간 `temp_ir_surface`의 최소자승 기울기(°C/분) ÷ 그 구간 전력 `\|V_median × I_median\|`. 단위 °C/분/W |
| `recoverySlopeCPerMin` | P5 구간 `temp_ir_surface`의 최소자승 기울기(°C/분). 부호가 정보 — 양수면 부하를 내렸는데도 계속 뜨거워지는 중이라는 뜻(§9-7) |

`thermalPerWattCPerMinPerW`를 전력으로 나누는 이유: `dT/dt ≈ P/C`라 발열 기울기가 팩 열용량(대략 무게에 비례)에 좌우된다. 같은 부하를 걸어도 열용량이 작은 팩이 몇 배 빨리 뜨므로, 절대 기울기만으로는 팩 간 비교도 열화 판단도 안 된다. 전력으로 정규화하면 부하 크기 차이가 흡수되고, 남는 건 그 팩의 열용량·열 결합 상수뿐이라 **같은 자산의 세션 간 비교**가 성립한다(§9-3 시계열 피처 #6 `dT_per_W`와 같은 양). ⚠️ 이것도 팩의 물리 상수(무게·구조)에 좌우되므로, **처음 보는 팩을 1회 측정한 이 값만으로는 절대 판정이 여전히 불가능하다** — 같은 자산의 이력이 쌓여야 의미가 생긴다.

### 3-3. 안전 중단 조건

아래 중 **하나라도** 걸리면 **부하를 먼저 0A로 내리고** 릴레이를 차단한다. 순서가 중요하다 — 부하가 걸린 상태에서 경로를 끊으면 인덕티브 킥과 아크가 생긴다(§2-7-4와 같은 이유).

**차단은 CH3(마스터)로 한다.** CH4는 안전 채널이 아니므로 중단 절차에서 건드리지 않는다(§2-5).


| 조건       | 값                    | 상태                                               |
| -------- | -------------------- | ------------------------------------------------ |
| 표면온도 절대값 | 50°C                 | `**정의 필요**` — §2-3 때문에 셀 온도가 아니다. 실측 후 확정(§8 H2) |
| 표면온도 상승률 | `dT/dt` &gt; 5°C/min | `**정의 필요**` — 주 판단 근거이므로 이쪽이 더 중요하다              |
| 가스       | `gas_raw` 임계 초과      | 모드 2 Fail-Safe 계층. 진단과 무관하게 항상 동작                |
| 출력전압 붕괴  | `V_light`의 80% 미만    | 확정 — 컨버터가 완전히 무너진 상태                             |


위 표는 `MODE2_FULL`의 진단 중단 계약이다. `COMBINED_EXISTING_PARTS_V1`은 가스·온도 연속 감시가 완성되지 않았으므로 이 표를 일부만 적용해 진단을 시작하지 않는다. 해당 프로필은 조립 가이드의 0.5A·10초 시운전에서 멈춘다.

### 3-4. 등급 판정

문턱값 `S1`(발열 기울기 상한)은 **실측 전에는 정할 근거가 없다**(§8 H3). 판정의 **형태만** 확정한다.

> **등급 산식은 P7 추가로 바뀌지 않는다.** 발열 기울기 조건은 여전히 P3(1.5A 고정) 구간 `thermalSlopeCPerMin` 기준이다. P7의 `thermalProbeLoadA`·`thermalPerWattCPerMinPerW`, P5의 `recoverySlopeCPerMin`은 원값으로만 실려 나가며 이 표의 어느 조건에도 아직 연결되어 있지 않다(§8 H21).


| 등급      | 조건                                                        |
| ------- | --------------------------------------------------------- |
| `양호`    | 이탈점 ≥ 광고 정격 전류 **AND** 발열 기울기 &lt; `S1` **AND** 도달률 ≥ 95% |
| `주의`    | 위 세 조건 중 하나가 벗어남                                          |
| `열화 의심` | 둘 이상이 벗어남 **또는** 이탈점 &lt; 광고 정격의 70%                      |


⚠️ 이 등급은 `**CLAUDE.md`의 4단계 이상등급(정상·주의·경고·위험)과 다른 축이다.** 열화는 수명 이야기이고 이상점수는 열폭주 위험 이야기다. 두 값을 같은 이름으로 부르거나 합산하지 않는다.

### 3-5. ⚠️ 빠른 진단이 절대 SOH를 못 내는 이유

**모드 2의 `soc_pct`는 측정 시작 시점을 100%로 가정한 INA226 적산 상대값이다**(`CLAUDE.md`, 2026-07-28 확정). 즉 **진단을 시작하는 순간의 실제 잔량을 우리는 모른다.**

잔량은 3지표 전부를 오염시킨다 — 잔량 20%인 새 배터리는 잔량 90%인 열화 배터리보다 이탈점이 낮게 나온다. 셀 전압이 낮으면 같은 출력에 입력 전류가 커져 컨버터의 전류 한계에 더 빨리 닿기 때문이다(§1의 2026-08-08 정정 참조).

그래서 빠른 진단은:

- `confidence: "LOW"`를 **항상** 붙인다
- `socHintLevel`을 함께 기록한다 — 보조배터리 겉면의 잔량 표시(대개 LED 4단)를 사용자가 알려주면 `1`~`4`, 아니면` null`. 이력을 비교할 때 **같은 힌트 단수끼리만** 비교한다
- 같은 자산의 빠른 진단 결과가 2회 미만이면 등급 대신 **"기준선 수집 중"**임이 드러나야 한다

## 4. 정밀 용량 테스트 (Capacity Test)

**소요**: 수 시간. **신뢰도**: `HIGH`. 열화의 유일한 신뢰 지표다.

### 4-1. 절차

1. **게이트 — 완충 확인.** 시작 SOC가 100%여야 결과가 SOH가 된다. 기본은 사용자 자기신고이고, **CH1 충전 경로가 붙어 있으면 충전 전류가 테이퍼되는 것을 관측해 기계적으로 판정한다**(§2-5). 승압회로 때문에 출력 전압으로는 잔량을 알 수 없으므로(§1) 이게 유일한 객관적 확인 방법이다
2. 소요 시간 추정을 알린다 — `ratedWh / (V_light × 방전전류)`
3. 정전류 방전. 기본 **1.0A**(설정 가능). 컷오프까지
4. `deliveredWh = ∫ V·I dt` (INA226 100ms 적산)
5. 컷오프 판정 — 출력전압이 `V_light`의 80% 아래로 무너져 **회복하지 않거나**, 보조배터리가 출력을 스스로 끊음
6. 결과 저장. 이 자산의 첫 테스트면 `baselineWh`로 기록

방전 전류 기본값을 1.0A로 둔 이유: 10000mAh급에서 약 0.2C에 해당해 표준 용량시험 관행에 맞고, 발열이 §3-3 중단 문턱을 건드리지 않을 만큼 낮다. 2.0A로 올리면 시간이 절반이 되지만 부스트 손실과 발열이 함께 커져 값이 낮게 나온다 — **방전 전류를 결과와 함께 기록해 다른 전류로 측정한 값끼리 비교하지 않게 한다.**

### 4-2. ⚠️ 부스트 효율을 보정하지 않으면 새 배터리도 SOH 85%가 된다

이 산식에서 가장 흔한 함정이다.

10000mAh 보조배터리의 정격은 `3.7V × 10Ah = 37Wh`인데, 이건 **셀 기준**이다. 출력단 5V에서 실제로 뽑히는 건 부스트 효율 η(85~~90%)를 곱한 **31~~33Wh**다.

```
잘못:  31.5Wh / 37Wh = 85.1%  →  방금 산 배터리가 "열화 15%"로 나온다
```

η는 제품마다 다르고 부하 전류에 따라서도 변해서 **가정할 수 없다.** 그래서 두 값을 나눠서 낸다.


| 필드          | 산식                                  | 성격                                                                                |
| ----------- | ----------------------------------- | --------------------------------------------------------------------------------- |
| `sohRelPct` | `deliveredWh / baselineWh × 100`    | ✅ **신뢰값.** 같은 자산의 첫 테스트를 100%로 삼은 상대값이라 η가 분자·분모에서 약분된다                           |
| `sohAbsPct` | `deliveredWh / (ratedWh × η) × 100` | ⚠️ **참고값.** η 가정에 전적으로 의존한다. `assumedEfficiency`를 응답에 반드시 동봉해 어떤 가정에서 나온 값인지 드러낸다 |


η 기본값 **0.88**은 `정의 필요`다(§8 H4) — 실측 여러 대의 첫 테스트값과 정격을 비교해 확정한다.

**첫 테스트에서는 `sohRelPct`가 정의되지 않는다.** `baselineWh`가 곧 그 측정값이므로 100%가 되는데, 그건 "열화 없음"이 아니라 "비교 대상 없음"이다. **첫 테스트는 `sohRelPct: null` + `isBaseline: true`로 낸다.**

### 4-3. 중단과 부분 결과

- 사용자는 언제든 중단할 수 있다. 릴레이 차단·세션 종료·전원 이탈도 중단이다
- **중단된 결과는 SOH로 쓰지 않는다.** `partial: true`로 기록만 하고 `sohRelPct`·`sohAbsPct`는 `null`이다. `baselineWh` 후보로도 쓰지 않는다
- §3-3의 안전 중단 조건은 정밀 테스트에도 그대로 적용된다

⚠️ **v3 프로토타입의 `SOH 92% · RUL ~480 사이클 · 누적 사이클 312 · 내부 저항 18.4 mΩ`는 목업 숫자다.** 모드 2에서 이 네 값이 다 채워진 화면은 만들 수 없다. 값이 없다는 사실이 화면에 드러나야 한다.

**대안** — 정밀 테스트가 2회 이상 쌓이면 `sohRelPct` 하락 추세로 "SOH 80% 도달 예상 시점"을 낼 수 있다. 사이클이 아니라 **날짜** 단위다. 여러 회 측정이 전제라 **후속 과제**로 남긴다.

## 6. 데이터 스키마 확장

### 6-1. `battery-raw-metrics` — 필드 2개 추가

진단은 raw 스트림을 대체하지 않는다. 진단 중에도 100ms 프레임은 그대로 흐르고, 그 위에 **어느 단계에서 찍힌 프레임인지**를 태그로 얹는다.

```json
{
  "version": 1,
  "device_id": "string",
  "mode": 2,
  "timestamp": "ISO8601 UTC (Z suffix)",
  "voltage_v": 5.02,
  "current_a": -1.50,
  "power_w": -7.53,
  "soc_pct": 74,
  "temp_contact": null,
  "temp_ir_surface": 38.1,
  "temp_points": { "contact": null, "ir": [38.1, 35.9] },
  "gas_raw": 812,
  "pressure_raw": null,
  "acoustic_raw": null,
  "diag_phase": "P3",
  "load_target_a": 1.5,
  "age_ms": { "soc_pct": 640, "temp_ir_surface": 40 }
}
```


| 필드              | 값                                                                            | 뜻                                                                |
| --------------- | ---------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| `diag_phase`    | `null` | `"P0"`…`"P7"` | `"CAPACITY"` | `"S0"`·`"S1A"`…`"S1F"`·`"S2"`·`"S3"` | 진단 단계. `null`이면 진단 중이 아니다. 스크리닝 wire 값은 이 표의 대문자 표기를 사용한다. **`P6`≠`P7`** — `P6`은 붕괴 구간 미세 스윕(§3-1, 현재 미구현)이고 `P7`은 붕괴점의 0.9배로 40초간 거는 발열 탐침 구간(§3-2 ④)이다 |
| `load_target_a` | `null` | 실수                                                                  | 그 프레임에서 **지시한** 목표 전류. 실측은 `current_a`이며 둘의 차이가 부하 제어 오차다        |


**기존 규약 준수** — `current_a`·`power_w`는 부호를 살린다(양수=충전, 음수=방전). 보조배터리를 **방전**시키는 진단이므로 음수이고, CH4를 충전 쪽으로 돌린 구간에서는 **양수**다(§2-7-2). 프론트는 표시할 때만 `abs()`하고 방향은 라벨로 낸다. `age_ms`는 그 프레임에서 실측되지 않은 필드에만 넣는다.

⚠️ `**temp_points.contact`는 배열이 아니라 통째로 `null`이다.** 모드 1은 길이 3 고정에 결측만 `null`이지만, 모드 2는 DS18B20이 아예 없다(§2-1). **길이 3 배열을 기대하고 인덱싱하면 모드 2 프레임에서 깨진다.** `temp_points.ir`은 모드 1과 같이 배열이며, `CLAUDE.md`의 경고대로 **길이를 상수로 박지 말고 순회해 최댓값을 쓴다.**

#### `COMBINED_EXISTING_PARTS_V1` 시운전 프레임 오버라이드

이 프로필은 진단이 아니라 수동 시운전이므로 `diag_phase=null`, `load_target_a=null`이다. 값이 없는 센서를 모드 1 값으로 대체하지 않는다.


| 필드                           | 시운전 값                       |
| ---------------------------- | --------------------------- |
| `mode`                       | `2`                         |
| `temp_contact`               | `null`                      |
| `temp_points.contact`        | `null`                      |
| `pressure_raw`               | `null`                      |
| `gas_raw`                    | `null`                      |
| `soc_pct`                    | **반드시 `null`**              |
| `temp_points.ir`             | `[0x5A 중앙, 0x5B 포트쪽]` 실측 배열 |
| `diag_phase`·`load_target_a` | 둘 다 `null`                  |


위 표의 `null`은 선택값이 아니다. 모드 1 캐시값이나 추정값으로 채우지 않는다. `gas_raw=null`은 센서 정상값이 아니라 **안전 프로필 미준비 표시**다. 이 값을 받은 서버는 빠른 진단·정밀 용량시험 시작을 허용하지 않는다.

### 6-2. `battery-events` — 새 토픽을 만들지 않는다

진단 단계 전환·완료·중단은 **기존 `battery-events` 토픽**에 싣는다. 진단은 raw 스트림 위의 주석이므로 토픽을 늘릴 이유가 없다. 이 문서의 `DIAG_*` 명칭은 진단 이벤트 설계의 정본이며, 현재 `backend/src/kafka.ts`의 백엔드 outbound 4종 parser가 에지 이벤트 전체를 대신 정의하는 것은 아니다.

이벤트 종류: `DIAG_STARTED`, `DIAG_PHASE_CHANGED`, `DIAG_COMPLETED`, `DIAG_ABORTED`(사유 포함). 음성 안내 대상이므로 에지 스피커 카테고리에 매핑한다(**§7-6**).

### 6-3. ⚠️ 진단 구간은 AI가 특별 취급해야 한다

계단 스윙은 **사람이 의도적으로 만든 전류 계단**이다. 정상 사용 패턴이 아니다.


| 항목           | 처리                                                                          |
| ------------ | --------------------------------------------------------------------------- |
| AI 학습셋       | `diag_phase != null` 프레임은 **정상패턴 학습에서 제외**한다. 넣으면 계단 파형을 정상으로 배워 실제 이상을 놓친다 |
| 이상점수 산출      | 계속 산출한다. 끊으면 진단 중 진짜 사고를 놓친다                                                |
| 이상 **알림 발송** | 진단 구간에서는 **억제**한다. 의도한 부하 변동에 매번 알림이 가면 알림이 무의미해진다                          |
| Fail-Safe    | **억제하지 않는다.** 가스·온도 하드 임계는 진단이든 아니든 즉시 차단한다                                 |


태그가 프레임에 실려 있으므로 나중에 판단을 바꿀 수 있다. 태그를 안 남기면 되돌릴 수 없다.

> ⚠️ **"학습에서 제외" 규칙은 연속 감시 모델의 이야기다.** §9의 스크리닝 모델은 **별개 가중치**이며 정반대로 **스크리닝 프레임(`diag_phase = S*`)만** 학습한다 — 고정 자극이라 세션 간 비교가 성립하기 때문이다(§9-4). 두 모델을 혼동하면 조용히 틀린다.

## 7. 기능 계약 (F21의 근거)

`docs/product_contract.md` F21의 원본이다. 형태 어휘를 쓰지 않는다 — 화면 개수·경계·그릇의 형태는 자유다.

### 7-1. 반드시 제공하는 정보

**① 식별 — 등록값**

- 배터리 라벨, `battery_id`, 배터리 종류, 제조사·모델(입력된 경우), 자산에 고정된 측정 모드
- 정격 용량(`capacityWh` 또는 `capacityMah`), 광고 정격 출력 전류(입력된 경우)

**② 현재 출력량 — 실측값**

- 경부하 기준 출력전압(최소 유지 부하 0.1A에서 잰 값, §2-6), 현재 전압·전류·전력. **전류·전력은 절댓값과 방향 라벨로 보인다**(원시 부호를 그대로 노출하지 않는다)
- 상대 SOC와 그것이 **측정 시작을 100%로 본 상대값**이라는 사실
- 표면온도(두 존의 최댓값)와 각 값이 몇 ms 전 실측인지

**③ 열화 — 진단 결과**

- 진단 종류(빠른 진단 / 정밀 테스트), 신뢰도, 측정 시각, 잔량 힌트 단수
- 빠른 진단 3지표 — 레귤레이션 이탈 전류(상한값인지 여부 포함), 발열 기울기, 스펙 도달률, 열화 등급
- 정밀 테스트 — 뽑아낸 Wh, 기준선 Wh, 상대 SOH, 참고 절대 SOH와 그때 쓴 효율 가정, 방전 전류, 부분 결과 여부
- **아직 진단하지 않았다는 사실**, 기준선 수집 중이라는 사실, 산출 불가 항목(누적 사이클·잔존수명·내부저항)이 왜 비어 있는지
- 진단 진행 중이면 현재 단계, 목표 전류, 경과·남은 시간 추정

**④ 안전**

- 가스 상태, 릴레이 회로 상태, 최종 이상점수와 4등급
- 진단 중 알림이 억제된다는 사실

**⑤ 이력**

- 이 자산의 과거 진단 목록 — 시각, 종류, 신뢰도, 핵심 결과값

### 7-2. 반드시 가능한 동작

- 빠른 진단 실행 → **게이트** 7-3①
- 정밀 용량 테스트 실행 → **게이트** 7-3②
- 진행 중인 진단 중단
- 잔량 힌트 단수 입력·수정
- 과거 진단 이력 확인, 개별 결과 상세 확인
- 실시간 관제로 이동 → F4
- 이 배터리의 상세·이력으로 이동 → F7
- 릴레이 차단으로 이동 → T7

### 7-3. 게이트

**① 빠른 진단 실행**

- 활성 측정 세션이 있고, 그 배터리의 측정 모드가 2이고, 진행 중인 진단이 없어야 한다
- **부하를 걸어 의도적으로 발열시킨다는 사실**과 소요 시간을 알리고 확인을 받는다. 확인 없이 실행하는 경로는 없다

**② 정밀 용량 테스트 실행**

- ①의 모든 조건에 더해, **정격 용량이 등록돼 있어야 한다**(없으면 Wh를 비교할 분모가 없다)
- **완충 상태임을 확인받아야 한다.** 시작 SOC가 100%가 아니면 결과는 SOH가 아니다
- 소요 시간 추정을 알리고 확인을 받는다

중단에는 재인증·사유를 요구하지 않는다. 중단은 언제나 더 안전한 방향이므로 막을 이유가 없다. (릴레이 차단·복구는 별개이며 T7의 재인증·사유 게이트를 그대로 받는다.)

### 7-4. 불변

- **Fail-Safe는 진단보다 우선한다.** 가스·온도 임계가 걸리면 진단 절차와 무관하게 즉시 개입하며, 그때 **부하를 0A로 내린 다음** 릴레이를 차단한다. 순서가 뒤바뀌는 경로는 존재할 수 없다
- **열화 등급과 이상점수 등급을 합산하거나 같은 이름으로 부르지 않는다.** 열화는 수명, 이상점수는 열폭주 위험이며 서로 다른 축이다
- **완충 확인을 거치지 않은 정밀 테스트 결과를 SOH로 쓰는 경로는 존재할 수 없다.** 중단된 부분 결과도 마찬가지다
- **모드 2에서 누적 사이클·잔존수명·내부저항에 값이 채워지는 경로는 존재할 수 없다**(§5)
- 진단 중이라도 `battery-raw-metrics` 발행은 멈추지 않는다

### 7-5. 상태·예외

- 정격 용량이 등록되지 않아 정밀 테스트를 시작할 수 없을 때
- 진단 이력이 하나도 없을 때 / 기준선이 1회뿐이라 상대 SOH를 낼 수 없을 때
- 진단 중 안전 조건이 걸려 중단됐을 때 — 어느 조건인지 드러나야 한다
- 진단 중 다른 배터리가 연결되거나 배터리가 운영 차단되어 세션이 끝났을 때 — 진단은 무효다
- 진단기가 오프라인일 때
- 부하 제어 오차가 커서(`load_target_a`와 `current_a`의 차이) 결과를 신뢰할 수 없을 때
- 릴레이가 차단 상태라 부하 경로가 없을 때
- 충전 경로가 보조배터리에 붙지 않아 완충을 기계적으로 확인할 수 없을 때 — 사용자 자기신고로 대체된다는 사실이 드러나야 한다(§8 H13)

### 7-6. 음성 안내 매핑

에지 스피커 카테고리(`CLAUDE.md`)에 붙인다 — 진단 시작·완료는 **연결/측정**, 안전 중단은 **Fail-Safe/릴레이**, 부하 제어 오차는 **센서/디바이스 오류**.

## 8. 미결정

문서로 정할 수 있는 건 다 정했다. 부하 수단(§2-4)과 릴레이 매핑(§2-5)도 2026-07-28에 닫혔다. 남은 건 **실물을 확인하거나 전원을 넣어 봐야 답이 나오는 것**이다.

**2026-09-15 Task 1 Fail-Safe 계약 갱신:** F21 진단 입력에서 압력·음향이
`null`인 사실과 Fail-Safe 센서 프로필을 구분한다. `MODE2_FULL`은 MLX90614
IR 온도·온도 상승률·MQ-2 가스를 사용할 수 있고, `COMBINED_EXISTING_PARTS_V1`
은 실제 배선의 MLX90614 IR 온도·상승률만 사용한다. 두 프로필 모두 접촉
온도·압력·음향은 `null`이며, 존재하지 않는 센서의 트리거를 만들지 않는다.
Fail-Safe 문턱 키는 `tempIrCapC`, `tempRiseRateCPerMin`, `gasRaw` 등을
프로필별 배포 설정에서 공급하고 숫자 `0`은 해당 계층만 비활성화하는
미설정 sentinel이다. H2(온도 절대값)·H3(상승률)·H6(가스)와 센서 배치/챔버
H11·H15의 실측 기록·승인 전에는 값을 활성화하지 않는다. 이는 F21 진단
실행 capability와 별개이며, 외부 provider·실물 릴레이 성공을 의미하지 않는다.
`rated_output_current_a`는 자산 등록 시 **필수 입력**이다. 실제 보유 샘플·
회로·계측 결과와 승인 일자를 표에 남기기 전까지 물리 게이트를 열린 상태로

## 9. 열폭주 위험 스크리닝 (15분) — 2026-08-08 설계 확정

임의의 보조배터리(처음 보는 자산 포함)를 물리면 **15분 세션 안에 "열폭주 위험 징후가 있는가"를 판정**하는 기능이다. 시연 시나리오이자 제품 기능이다.

**§3·§4와 축이 다르다.** 빠른 진단·정밀 테스트는 **열화(수명) 축**(`양호`/`주의`/`열화 의심`)이고, 스크리닝은 **이상점수(열폭주 위험) 축**이다 — 출력은 0.0–1.0 실수와 시스템 고정 임계(0.3/0.6/0.8)로 **계산**한 4등급(정상·주의·경고·위험)이다. §3-4의 경고를 반복한다: **두 축을 합산하거나 같은 이름으로 부르지 않는다.** 한 세션에서 스크리닝과 빠른 진단을 겸하더라도 결과는 두 축으로 따로 낸다.

### 9-1. 왜 성립하는가 — 열량계 원리와 "한계까지 밀기"

셀 전압이 안 보이는데 무엇으로 판정하는가. 두 가지 물리에 기댄다.

**① 케이스는 온도계로는 못 쓰지만 열량계로는 쓴다.** §2-3대로 케이스 표면온도는 셀 온도가 아니다(감쇠·수십 초 지연). 그러나 에너지 보존 때문에 **셀이 만드는 열은 결국 전부 케이스를 통과한다** — 케이스의 주변 대비 상승은 내부 발열량에 비례한다. 스크리닝이 알고 싶은 건 "셀이 몇 도인가"가 아니라 **"이 팩이 같은 일을 하면서 남들보다 열을 많이 만드는가"**이고(열화·미세단락의 서명은 온도 수준이 아니라 초과 발열이다), 그건 케이스 밖에서도 잰다. 팩 열용량(~300 J/K)과 열시정수(수십 분) 때문에 15분 안에 정상상태에 못 가므로 실제로 재는 것은 **기울기 `dT/dt ≈ P/C`**다 — 그래서 세션 시작 시 **팩 무게를 재서**(저울) 열용량 분모로 쓴다(§9-6).

**② 부스터는 한계 근처로 몰리면 셀 정보를 흘린다.** 평상시 부스터의 제어 루프(대역폭 kHz대)는 완벽한 가림막이다 — 느린 섭동은 전부 지워버린다. 그러나 부하로 **스위치 전류 한계·BMS UVLO**(§1의 2026-08-08 정정)까지 밀면 붕괴점(§3-2 ①)·과도응답·저주파 흔들림에 셀 상태가 배어 나온다. 정량적으로, 전류 한계 지배 구간의 붕괴점은 `I_collapse ≈ V_cell(부하 시) × I_sw_limit × η / 5V` — **셀 전압에 거의 비례**하고, 셀 저항이 크면 부하 시 `V_cell`이 더 처져 더 내려온다. **부하는 부스터를 한계까지 미는 도구다.** 부하 하나로 재지 못하던 계기들을 우회 구현한다 — 열량계(발열), 전압계(붕괴점), 용량계(붕괴점의 Wh당 이동), 임피던스계(과도응답·변조).

⚠️ 단 `I_sw_limit`(IC 설계값)과 시작 잔량이 위 식에 곱해져 있어 **붕괴점 절대값은 제품·잔량 교란을 받는다.** 실제 보조배터리 IC의 출력 한계는 **0.8A(HT4928S)~4.8A(IP5318)까지 6배 흩어진다**(2026-08-08 웹 검증) — 생각보다 훨씬 크다. 처음 보는 팩에서 튼튼한 건 이 교란이 상수로 약분되는 **세션 내 차분**(`dI_collapse_dWh`) 쪽이다 — §9-3의 취급 규칙 참조.

⚠️ **붕괴는 "서서히 처짐"만이 아니라 "래치오프(급락 0V)"로도 나타난다**(2026-08-08 웹 검증). IP5306류는 출력이 4.4V 미만으로 30ms 지속되면 **출력을 통째로 차단**하고, 차단되면 최소 유지 부하 0.1A도 못 흐른다. 스윕 상태기계는 ① 반드시 **저전류→상행**으로 올리고, ② 점진적 이탈(94% 붕괴)과 **출력 소실(5V→0V)** 둘 다를 정상적인 붕괴 관측으로 기록하며, ③ 소실 시 **부하 0A → 팩 재기동 대기 → 세션 재개** 절차를 밟는다. 이를 "배터리 사망"이나 센서 오류로 오독하면 안 된다(§2-5의 CH3 부작용과 같은 성격).

전류 채널 주의: 모드 2의 출력 전류는 우리가 CC로 **지시한 값의 메아리**라 그 자체는 정보가 아니다. 정보가 나오는 순간은 추종이 깨질 때뿐(`load_target_a − current_a`, 5V 이탈). 셀 전류는 `P_out/(V_cell×η)`로 숨어 있으므로 **셀 데이터와의 공유 축은 전류가 아니라 전력**이다(§9-5).

| **S1D** EIS 변조 | 8–9.5분  | **`0.9 × I_collapse_early` 중심** ± 0.2A 구형파 0.2~0.5Hz | `eis_response_amp` — **H16 사전 검증 통과 시에만.** 중심이 적응형인 이유: 부스터 제어 루프 대역폭이 kHz대라 0.2~0.5Hz 섭동은 한계 아래에선 완전히 지워진다. 변조 피크가 전류 한계를 건드릴 때의 **클리핑 비대칭**에만 셀 정보가 실리므로 붕괴점 직하에 중심을 잡는다(고정 1.5A 중심으로는 아무것도 안 잡힌다). 탈락하면 이 구간을 S1C·S1E에 배분 |
| **S1E** 계단 ③   | 9.5–11분 | 1.5A                      | 발열 곡선 3점째 + 버스트                                                                                                                                                               |
| **S1F** 후반 스윕  | 11–12분  | S1B와 동일한 2단 스윕                     | `I_collapse_late` → `dI_collapse_dWh`(붕괴점 이동)                                                                                                                                 |
| **S2** 회복      | 12–14분  | **0.1A** 복귀               | `T_recover_slope`·`tau_cooldown`. **부하를 내렸는데 온도가 계속 오르면 최강 적신호이자 즉시 중단 조건**(§9-7)                                                                                             |
| **S3** 판정      | 14–15분  | 0.1A                      | 점수 계산·리포트 생성                                                                                                                                                                  |


- 모든 계단의 목표 전류에 **`min(단계값, 0.7 × 광고 정격 전류)` 상한**을 건다. 정격 1A짜리 팩에 1.5A를 걸면 "위험"이 아니라 "정격 초과"를 재게 된다 — `rated_output_current_a`가 필수 입력(2026-08-06)인 이유가 여기서도 성립한다. 상한 때문에 자극이 달라지는 문제는 `load_target_a`가 모델 입력이라 조건부 응답으로 흡수된다(§9-3).
- P0·P5와 같은 이유로 **무부하 구간이 없다**(§2-6) — 최소 유지 0.1A.
- **완충 후 측정을 권장하고 `socHintLevel`을 기록한다**(§3-5와 같은 장치). 시작 잔량이 낮으면 셀 전압이 낮아 붕괴점 절대값이 열화와 무관하게 내려온다(§9-1 ②의 잔량 교란). 완충을 강제 게이트로 두지는 않는다 — 열·가스 채널과 차분 피처는 잔량에 둔감해서 스크리닝 자체는 성립한다. 다만 잔량 힌트가 없으면 붕괴점 절대값 계열은 판정 가중치를 낮춘다.
- S1 각 구간의 시간 배분은 H2·H3 실측 후 미세 조정한다. 단계 기호·세션 타입 명칭의 최종 표기는 **H18**.

### 9-4. 판정 모델 — AI 이상탐지 중심

**스크리닝 모델은 연속 감시 모델과 별개 가중치의 LSTM-AE다.** §6-3의 "진단 프레임은 정상패턴 학습 제외"는 연속 감시 모델의 규칙이고, 스크리닝 모델은 정반대로 **스크리닝 프레임만** 학습한다 — 고정 자극이라 세션 간 비교가 성립하기 때문이다. 두 모델을 혼동하지 않는다.


| 구성     | 내용                                                                                                                                                             |
| ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 시계열 판정 | 시계열 13개 → LSTM-AE 재구성 오차                                                                                                                                       |
| 스칼라 판정 | 스칼라 11개 → 정상 팩 분포 대비 거리(마할라노비스 수준의 단순 탐지기면 충분)                                                                                                                 |
| 융합     | `Final = α × AE 재구성 오차 + β × 스칼라 거리` — 기존 "AE + Informer 융합" 구조를 계승하며 α·β는 튜닝 대상                                                                               |
| 출력     | 이상점수 0.0–1.0(API 원값) + 임계 0.3/0.6/0.8로 **계산**한 4등급 + **근거 지표**(스칼라는 전부 물리 의미가 있어 "열로 잰 내부저항이 정상 분포 대비 +2.3σ" 같은 문장이 바로 나온다 — 단 문장 조립은 프론트 사전, 서버는 code+params) |


낯선 기기 오판(시연 최대 리스크)의 완화 장치 3겹:

1. 절대값이 아니라 **S0 baseline 대비 델타**로 정규화
2. **S1a 자가 캘리브레이션** — 기기별 케이스·열 결합 편차를 세션 안 실측으로 흡수
3. 임계 캘리브레이션 — hold-out 정상 세션이 **전부 0.3 미만**이 되도록 여유를 두고 설정

학습 데이터: 정상 보조배터리 3~5대 × 반복 세션(잔량·주변온도 다양화). 검증용 의사 이상(개발 전용, 시연 아님): 희생 팩 외부 가열 패드, MQ-2 가스 분사. 목표 — 정상 hold-out 전부 `< 0.3`(오탐 0), 의사 이상 `≥ 0.6` 검출.

보조 실험 2개(§8 H19와 연동):

- **케이스 열 전달함수 실측** — 셀을 희생 팩 셸에 넣고 안(접촉 프로브)·밖(IR)을 동시 기록해 감쇠비 K·지연 τ를 얻는다. 용도 3가지: ⓐ 셀에서 유도한 이상 열 서명(BW150 추출 가이드의 T4 고율·T6 외부가열, `ABNORMAL_HIRATE`·`ABNORMAL_THERMAL`)에 전달함수를 곱해 "케이스 밖에서 보일 이상 신호"의 크기·형태를 계산 → **H2 문턱을 추측이 아닌 실측 기반으로**, ⓑ 케이스 온도→내부 온도 칼만 관측기의 파라미터(아키텍처의 "내부 셀 추정" 자리), ⓒ 셀 데이터의 "케이스화" 증강. K·τ는 그 케이스의 값이므로 **대역 추정용**이고, 실전 기기별 값은 S1a가 잰다.
- **폼팩터 갭 실측** — 18650과 파우치의 발열 패턴이 같다고 **가정하지 않는다.** 다리가 옮기는 건 숫자가 아니라 **구조**(특징 공간에서 이상이 이탈하는 방향)다. 셀 쪽 실험(전달함수·이상 유도)을 **보유한 1000mAh 리튬폴리머 파우치로도 반복**해 차이를 실측하고, 미세조정용 3~5대는 **18650 내장형과 파우치형을 의도적으로 섞는다**(무게·두께로 추정, 희생 팩 분해 시 확인).

### 9-6. 측정 챔버 — 계측기의 일부

스크리닝은 **반밀폐 불연 측정 챔버** 안에서 수행한다. **단열 바구니가 아니다** — 팩 열용량 때문에 15분 안에는 어차피 기울기를 재는 것이라 단열해도 신호가 안 커지고, 위험 팩을 단열재로 감싸는 건 열폭주를 돕는 데다 단열재 자체가 불쏘시개다.

챔버의 목적 4가지:

1. **대류 바람 차단** — 에어컨·통행 기류가 최대 노이즈원이다. 수 °C짜리 신호에 1°C대 변동이 얹히면 판정이 무너진다
2. **센서 거치 기하 고정** — IR 거리·조준각을 브래킷으로 재현(§2-2의 "거치대" 요구의 구현체). 세션 간 비교가 방법론의 심장이므로 기하 재현성이 곧 판정 신뢰도다
3. **가스 농축** — 닫힌 부피에서 VOC가 흩어지지 않아 MQ-2 감도가 수 배가 된다(가장 이른 전조 채널 강화). MQ-2는 위쪽 구석 배치(H11), 히터 발열은 상수라 baseline이 흡수한다
4. **화재 봉쇄** — 불연 트레이의 진화형. 이상 과열 시 열이 빠질 여지는 남긴다(완전 밀폐 금지)

세션 시작 시 **팩 무게를 잰다**(저울 추가) — `dT/dt = P/C`의 분모(열용량 ∝ 질량) 추정용.

**규칙: 챔버는 계측기의 일부다.** 정상 팩 학습 세션·판정 세션·전달함수 실측 전부 **같은 챔버 안**에서 한다. 밖에서 학습하고 안에서 판정하면 도메인이 어긋나 전부 오판이다. 같은 이유로 **H2(온도 문턱)·H6(가스 임계)는 챔버 안에서 실측**해야 한다. 재질·크기·브래킷은 H15.

### 9-7. 안전 바닥 — AI가 우회 못 하는 층

§3-3의 안전 중단 조건이 스크리닝에도 그대로 적용되고, 스크리닝 고유 조건이 하나 늘어난다:


| 조건                          | 값                              | 성격                                    |
| --------------------------- | ------------------------------ | ------------------------------------- |
| §3-3 전체(온도 절대/상승률·가스·출력 붕괴) | 동일                             | 동일 — AI 점수와 무관하게 발동                   |
| **S2 회복 중 온도 지속 상승**        | `T_recover_slope > 0`이 수십 초 지속 | **스크리닝 고유.** 부하가 없는데 온도가 오르면 내부 발열 확정 |


발동 시 **부하를 먼저 0A로 내리고 CH3(마스터)를 차단**한다 — §3-3·§7-4의 순서 규칙 그대로이며 뒤바뀌는 경로는 존재할 수 없다. Fail-Safe는 스크리닝 중에도 억제하지 않는다.

**실행 게이트** — 15분·최대 1.5A 스크리닝은 현재 `COMBINED_EXISTING_PARTS_V1`의 **0.5A·10초 시운전 게이트 밖**이다. 스크리닝을 돌리려면 §2-0의 승격 조건이 선행된다: MQ-2 분압·배선 추가(현 프로필은 MQ-2 없음)와 배치·임계 실측(H6·H11), 온도 문턱(H2), 발열 기울기 분포(H3), 연속 감시 구현, 그리고 챔버(H15). **게이트를 닫기 전 승격 금지이며, 사람이 지켜본다는 조건은 게이트를 대체하지 않는다**(§2-0).

### 9-8. 리포트와 한계 고지

리포트에 반드시 싣는 것:

- 이상점수(0.0–1.0)와 4등급, **근거 지표**(스칼라 11개 중 이탈 상위 항목과 정상 분포 대비 위치)
- **검사 한계 고지** — 발열 수백 mW 미만의 약한 초기 결함은 15분 안에 케이스 표면에 나타나지 않을 수 있다. "위험 징후 없음"이지 "안전 보증"이 아니다
- 정상 팩 학습 분포의 크기(몇 대·몇 세션 기준인지) — 분포가 얇을 때 판정의 무게가 드러나야 한다
- 열화 축 결과(§3·§4)와 같은 화면에 나올 경우에도 **두 축이 섞이지 않게** 낸다(§7-4 불변과 동일)

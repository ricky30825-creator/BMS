# 모드 2 (보조배터리) — 즉시 진단 스펙

완제품 USB 보조배터리를 진단기에 연결했을 때 **그 배터리의 정보·현재 출력량·열화상태를 한 자리에서** 확인하게 하는 기능의 계약서다.

- 상위 API 계약: `docs/backend_contract.md`
- 디자인 무관 기능 계약: `docs/product_contract.md` F21
- 모드 1 대응 문서: `docs/hardware/mode1_backend_spec.md`
- 회로도: **없다.** `hardware/mode2/`는 아직 만들지 않았다(§2-4의 부하 수단이 확정돼야 그릴 수 있다)

**범위**: 모드 2(보조배터리)만. 이 문서는 설계 계약이며 회로도·목업·구현 코드는 후속이다.

> **한 줄 요약** — 보조배터리는 부스트 컨버터가 셀을 가려서 셀을 직접 볼 수 없다. 그래서 **"부하를 걸었을 때 어떻게 반응하는가"**로 열화를 우회 추정하고, 그 결과를 **빠른 진단(약 2분, 신뢰도 낮음)**과 **정밀 용량 테스트(수 시간, 신뢰도 높음)** 두 층으로 나눠 낸다.

---

## 1. ⚠️ 출력단 내부저항은 무의미하다 — 먼저 읽을 것

배터리 열화를 재는 고전적 방법은 내부저항이다. 부하를 걸었다 끊으며 `ΔV/ΔI`를 재면 셀이 늙은 만큼 값이 커진다. **모드 1(외부 셀)에서는 이게 통한다.** 셀 단자에 직접 붙기 때문이다.

**모드 2에서는 통하지 않는다.**

```
 [셀 3.0~4.2V] ── [보호회로] ── [DC-DC 부스트] ── [USB 출력 5V] ── 진단기 INA226
                                     ▲
                          여기가 전압을 5V로 붙잡는다
```

완제품 보조배터리는 셀과 USB 출력 사이에 **승압 컨버터**가 있다. 셀이 4.2V든 3.2V든 컨버터가 출력을 5V로 레귤레이션한다. 즉 진단기가 INA226으로 재는 `voltage_v`는 **셀 전압이 아니고 컨버터 출력 전압**이다.

따라서 출력단에서 `ΔV/ΔI`를 재면 나오는 값은:

- ❌ 셀의 내부저항이 **아니다**
- ✅ 컨버터의 출력 임피던스 + 케이블·커넥터 접촉저항이다

이 값은 셀이 얼마나 늙었는지와 거의 무관하다. **모드 2의 `internalResistanceMohm`은 `null`로 확정한다**(§5).

### 그래서 무엇을 보는가

컨버터는 전압은 붙잡지만 **에너지를 만들어내지는 못한다.** 셀이 열화하면 컨버터가 셀에서 끌어와야 하는 전류가 커지고, 그 결과가 출력 쪽에 세 가지 흔적으로 남는다.

| 흔적 | 물리 | 열화 시 방향 |
|---|---|---|
| **레귤레이션을 포기하는 지점** | 셀 전압이 처져 컨버터의 듀티 한계에 걸리면 출력 5V를 못 지킨다 | 더 **낮은** 전류에서 무너진다 |
| **같은 출력에 대한 발열** | 셀 내부저항 상승분이 `I²R` 손실로 열이 된다 | 더 **빨리** 뜨거워진다 |
| **광고 스펙 도달 여부** | 정격 2A를 못 내면 셀이나 컨버터가 그만큼 못 버틴다 | 도달률이 **떨어진다** |

이 셋이 §3 빠른 진단의 3지표다. 그리고 이 셋 전부보다 확실한 건 **실제로 몇 Wh가 나오는지 끝까지 빼 보는 것**이며(§4), 그게 정밀 테스트다.

## 2. 하드웨어 전제

### 2-1. 재사용하는 센서

모드 1과 모드 2는 **인터락으로 동시 활성이 불가**하므로(`CLAUDE.md`) 같은 소자를 물리적으로 옮겨 쓸 수 있다.

| 소자 | 주소 | 모드 2에서의 역할 | 필드 |
|---|---|---|---|
| INA226 | I2C `0x40` | **보조배터리 USB 출력단**의 전압·전류·전력 | `voltage_v`, `current_a`, `power_w` |
| MLX90614 ×2 | I2C `0x5A` / `0x5B` | 케이스 표면 IR 온도 2존 (중앙 / USB 포트쪽) | `temp_ir_surface` = 두 존의 최댓값 |
| MQ-2 → ADS1115 | I2C `0x48` `A0` | 오프가스 감지 — 모드 2의 사후 대응 안전계층 | `gas_raw` |
| 릴레이 | GPIO | 부하 경로 차단 + 마스터 차단 | — |

**모드 2에 없는 것**: DS18B20(케이스에 가려 셀 접촉 불가) → `temp_contact`는 `null`. FSR 406(외장 케이스에 부착 불가) → `pressure_raw`는 `null`. BQ27441(셀에 접근 불가) → `soc_pct`는 INA226 적산 상대값.

### 2-2. IR 부착 거리는 모드 1보다 여유롭다

MLX90614-DCC는 FOV 35°라 스팟 지름 = `0.63 × 거리`다. 모드 1은 18650 지름이 1.8cm라 **2cm 이내**여야 했지만, 보조배터리는 케이스 폭이 6~7cm이므로 **5cm 거리에서도 스팟 3.2cm**로 대상 안에 들어온다.

**두 존의 겨냥 지점**: `0x5A` = 케이스 중앙(셀 뭉치 위), `0x5B` = **USB 출력 포트쪽**. 포트쪽을 반드시 한 존으로 두는 이유는 부스트 컨버터와 출력 MOSFET이 그쪽에 몰려 있어 부하를 걸면 거기가 가장 먼저 뜨거워지기 때문이다.

### 2-3. ⚠️ 케이스 표면온도는 셀 온도가 아니다

모드 1의 온도 임계(55/60°C)를 모드 2에 그대로 쓰면 안 된다. 보조배터리는 플라스틱·알루미늄 외장이 열을 막아서 **셀이 70°C일 때 케이스 표면은 45°C밖에 안 될 수 있다.** 열시정수도 길어 케이스 온도는 셀보다 수십 초 늦게 따라온다.

그러므로 모드 2의 온도 판단은 **절대값보다 상승률(`dT/dt`)이 주 근거**다. 절대값 문턱은 보수적으로(§3-3) 잡고, 문턱 자체는 실측 후 확정한다(§8 H2).

### 2-4. ⚠️ 부하 수단 — `정의 필요`

§3의 계단 스윙은 **프로그램이 전류를 지정할 수 있는 부하**를 요구한다. 현재 BOM에는 그런 소자가 없다.

| 후보 | 장점 | 막히는 지점 |
|---|---|---|
| **(a) ATORCH BW150** | 이미 BOM에 있다(×1) | **데이터 경로가 아니라고 이미 확정됐다**(`CLAUDE.md`). 전류 설정이 수동 버튼이라 계단 스윙을 자동화할 수 없다 — 단계마다 사람이 손으로 바꿔야 하고, 그러면 §3의 40초 구간 타이밍이 무너진다 |
| **(b) 고정저항 뱅크 + 릴레이** | 부품값이 싸고 설계가 단순하다. 5V 기준 0.5A=10Ω/2.5W, 1.0A=5Ω/5W, 1.5A=3.3Ω/7.5W, 2.0A=2.5Ω/10W | 계단이 **이산적**이라 §3 P6의 0.1A 미세 스윕이 불가능하다. 4채널 릴레이를 부하에 다 쓰면 **안전 차단 채널이 남지 않아** 릴레이 모듈을 추가로 사야 한다. 저항의 자체 발열이 IR 측정을 오염시키지 않게 격리해야 한다 |
| **(c) MOSFET 정전류 부하 + MCP4725 I2C DAC** ← **권장** | 전류를 연속 제어해 계단 스윙과 미세 스윕을 그대로 구현한다. 릴레이는 안전 차단에만 쓴다 | 부품 추가 구매(파워 MOSFET·op-amp·전류감지 저항·MCP4725·방열판)와 아날로그 회로 설계가 늘어난다. MOSFET이 선형영역에서 10W를 열로 태우므로 **방열 설계가 필수**고, 그 발열을 IR 센서에서 멀리 둬야 한다 |

**이 항목이 닫히기 전에는 `hardware/mode2/` 회로도를 그릴 수 없다.** 계단 스윙의 전류값·타이밍(§3)은 부하 수단과 무관하게 확정된 것이므로, 수단이 정해지면 그대로 구현한다.

### 2-5. 릴레이 채널 매핑 — `정의 필요`

모드 1은 CH1 충전(GPIO5) / CH2 방전(GPIO6) / CH3 마스터(GPIO13) / CH4 예비(GPIO19)로 확정돼 있다. 모드 2 매핑은 §2-4가 닫혀야 정해진다. **확정된 제약 하나**: 부하 경로와 무관하게 끊을 수 있는 **마스터 차단 채널을 반드시 하나 확보**한다. 모드 1과 같이 **active-LOW**(`0`=도통, `1`=차단)이고 NO 접점을 쓴다 — 정전·부팅 중·크래시 시 자동 차단되어야 한다.

## 3. 빠른 진단 (Quick Scan)

**소요**: 100초(P6 생략 시) ~ 160초. **신뢰도**: `LOW`. **절대 SOH를 내지 않는다.**

### 3-1. 시퀀스

| 단계 | 시간 | 목표 전류 | 기록하는 것 |
|---|---|---|---|
| **P0** | 10s | 무부하 | 무부하 출력전압 `V_oc`, 시작 표면온도 `T0` |
| **P1** | 20s | 0.5A | 후반 10초의 V·I 중앙값, T |
| **P2** | 20s | 1.0A | 동일 |
| **P3** | **40s** | 1.5A | 동일 + **발열 기울기 산출 구간** |
| **P4** | 20s | 2.0A | 동일. 여기서 무너지면 이탈점이 P3~P4 사이 |
| **P5** | 10s | 무부하 | 부하 해제 후 회복 전압 |
| **P6** | ≤60s | 미세 스윕 | 무너진 두 단계 사이를 0.1A 간격으로 재스윕. 안 무너졌으면 **생략** |

각 단계의 **후반 절반만** 쓴다. 부하를 바꾼 직후에는 컨버터가 재정착하는 과도구간이라 값이 흔들린다.

**P3만 40초인 이유**: 케이스의 열시정수가 수십 초 단위라(§2-3) 20초 기울기는 노이즈에 묻힌다. 발열 기울기를 재는 구간만 두 배로 둔다.

### 3-2. 산지표

**① `regulationKneeA` — 레귤레이션 이탈 전류**

출력전압이 **`V_oc`의 94%** 아래로 떨어지는 최소 전류.

- 2.0A까지 버티면 값은 `2.0`에 `kneeIsUpperBound: true`를 붙인다. "2.0A 이상"이지 "정확히 2.0A"가 아니다.
- 절대값(4.7V)이 아니라 **`V_oc` 비율**을 쓰는 이유: 9V·12V PD 모드에서도 같은 산식이 성립해야 한다.
- 94%를 고른 근거: 5V에서 4.70V이며 USB 2.0 다운스트림 포트 하한 4.75V 바로 아래다. 이 선을 넘으면 그 보조배터리는 USB 규격 안에서 그 전류를 못 내고 있다는 뜻이다.

**② `thermalSlopeCPerMin` — 발열 기울기**

P3(1.5A) 40초 구간 `temp_ir_surface`의 최소자승 기울기를 분당으로 환산한다. 최소자승을 쓰는 이유는 두 점 차분이 IR 노이즈에 취약하기 때문이다.

**③ `specAttainmentPct` — 스펙 도달률**

```
specAttainmentPct = min(실제 지속 도달 전류, 광고 정격 전류) / 광고 정격 전류 × 100
```

"광고 정격 전류"는 사용자가 자산 등록 시 입력한 값이다. 입력이 없으면 이 지표는 `null`이고 등급 판정에서 제외한다.

### 3-3. 안전 중단 조건

아래 중 **하나라도** 걸리면 **부하를 먼저 0A로 내리고** 릴레이를 차단한다. 순서가 중요하다 — 부하가 걸린 상태에서 경로를 끊으면 인덕티브 킥과 아크가 생긴다.

| 조건 | 값 | 상태 |
|---|---|---|
| 표면온도 절대값 | 50°C | **`정의 필요`** — §2-3 때문에 셀 온도가 아니다. 실측 후 확정(§8 H2) |
| 표면온도 상승률 | `dT/dt` > 5°C/min | **`정의 필요`** — 주 판단 근거이므로 이쪽이 더 중요하다 |
| 가스 | `gas_raw` 임계 초과 | 모드 2 Fail-Safe 계층. 진단과 무관하게 항상 동작 |
| 출력전압 붕괴 | `V_oc`의 80% 미만 | 확정 — 컨버터가 완전히 무너진 상태 |

### 3-4. 등급 판정

문턱값 `S1`(발열 기울기 상한)은 **실측 전에는 정할 근거가 없다**(§8 H3). 판정의 **형태만** 확정한다.

| 등급 | 조건 |
|---|---|
| `양호` | 이탈점 ≥ 광고 정격 전류 **AND** 발열 기울기 < `S1` **AND** 도달률 ≥ 95% |
| `주의` | 위 세 조건 중 하나가 벗어남 |
| `열화 의심` | 둘 이상이 벗어남 **또는** 이탈점 < 광고 정격의 70% |

⚠️ 이 등급은 **`CLAUDE.md`의 4단계 이상등급(정상·주의·경고·위험)과 다른 축이다.** 열화는 수명 이야기이고 이상점수는 열폭주 위험 이야기다. 두 값을 같은 이름으로 부르거나 합산하지 않는다.

### 3-5. ⚠️ 빠른 진단이 절대 SOH를 못 내는 이유

**모드 2의 `soc_pct`는 측정 시작 시점을 100%로 가정한 INA226 적산 상대값이다**(`CLAUDE.md`, 2026-07-28 확정). 즉 **진단을 시작하는 순간의 실제 잔량을 우리는 모른다.**

잔량은 3지표 전부를 오염시킨다 — 잔량 20%인 새 배터리는 잔량 90%인 열화 배터리보다 이탈점이 낮게 나온다. 셀 전압이 낮으면 컨버터가 듀티 한계에 더 빨리 닿기 때문이다.

그래서 빠른 진단은:

- `confidence: "LOW"`를 **항상** 붙인다
- `socHintLevel`을 함께 기록한다 — 보조배터리 겉면의 잔량 표시(대개 LED 4단)를 사용자가 알려주면 `1`~`4`, 아니면 `null`. 이력을 비교할 때 **같은 힌트 단수끼리만** 비교한다
- 같은 자산의 빠른 진단 결과가 2회 미만이면 등급 대신 **"기준선 수집 중"**임이 드러나야 한다

## 4. 정밀 용량 테스트 (Capacity Test)

**소요**: 수 시간. **신뢰도**: `HIGH`. 열화의 유일한 신뢰 지표다.

### 4-1. 절차

1. **게이트 — 완충 확인.** 시작 SOC가 100%여야 결과가 SOH가 된다. 사용자에게 완충 상태임을 확인받는다
2. 소요 시간 추정을 알린다 — `ratedWh / (V_oc × 방전전류)`
3. 정전류 방전. 기본 **1.0A**(설정 가능). 컷오프까지
4. `deliveredWh = ∫ V·I dt` (INA226 100ms 적산)
5. 컷오프 판정 — 출력전압이 `V_oc`의 80% 아래로 무너져 **회복하지 않거나**, 보조배터리가 출력을 스스로 끊음
6. 결과 저장. 이 자산의 첫 테스트면 `baselineWh`로 기록

방전 전류 기본값을 1.0A로 둔 이유: 10000mAh급에서 약 0.2C에 해당해 표준 용량시험 관행에 맞고, 발열이 §3-3 중단 문턱을 건드리지 않을 만큼 낮다. 2.0A로 올리면 시간이 절반이 되지만 부스트 손실과 발열이 함께 커져 값이 낮게 나온다 — **방전 전류를 결과와 함께 기록해 다른 전류로 측정한 값끼리 비교하지 않게 한다.**

### 4-2. ⚠️ 부스트 효율을 보정하지 않으면 새 배터리도 SOH 85%가 된다

이 산식에서 가장 흔한 함정이다.

10000mAh 보조배터리의 정격은 `3.7V × 10Ah = 37Wh`인데, 이건 **셀 기준**이다. 출력단 5V에서 실제로 뽑히는 건 부스트 효율 η(85~90%)를 곱한 **31~33Wh**다.

```
잘못:  31.5Wh / 37Wh = 85.1%  →  방금 산 배터리가 "열화 15%"로 나온다
```

η는 제품마다 다르고 부하 전류에 따라서도 변해서 **가정할 수 없다.** 그래서 두 값을 나눠서 낸다.

| 필드 | 산식 | 성격 |
|---|---|---|
| `sohRelPct` | `deliveredWh / baselineWh × 100` | ✅ **신뢰값.** 같은 자산의 첫 테스트를 100%로 삼은 상대값이라 η가 분자·분모에서 약분된다 |
| `sohAbsPct` | `deliveredWh / (ratedWh × η) × 100` | ⚠️ **참고값.** η 가정에 전적으로 의존한다. `assumedEfficiency`를 응답에 반드시 동봉해 어떤 가정에서 나온 값인지 드러낸다 |

η 기본값 **0.88**은 `정의 필요`다(§8 H4) — 실측 여러 대의 첫 테스트값과 정격을 비교해 확정한다.

**첫 테스트에서는 `sohRelPct`가 정의되지 않는다.** `baselineWh`가 곧 그 측정값이므로 100%가 되는데, 그건 "열화 없음"이 아니라 "비교 대상 없음"이다. **첫 테스트는 `sohRelPct: null` + `isBaseline: true`로 낸다.**

### 4-3. 중단과 부분 결과

- 사용자는 언제든 중단할 수 있다. 릴레이 차단·세션 종료·전원 이탈도 중단이다
- **중단된 결과는 SOH로 쓰지 않는다.** `partial: true`로 기록만 하고 `sohRelPct`·`sohAbsPct`는 `null`이다. `baselineWh` 후보로도 쓰지 않는다
- §3-3의 안전 중단 조건은 정밀 테스트에도 그대로 적용된다

## 6. 데이터 스키마 확장

### 6-1. `battery-raw-metrics` — 필드 2개 추가

진단은 raw 스트림을 대체하지 않는다. 진단 중에도 100ms 프레임은 그대로 흐르고, 그 위에 **어느 단계에서 찍힌 프레임인지**를 태그로 얹는다.

```json
{
  "device_id": "string",
  "mode": 2,
  "timestamp": "ISO8601",
  "voltage_v": 5.02,
  "current_a": -1.50,
  "power_w": -7.53,
  "soc_pct": 74,
  "temp_contact": null,
  "temp_ir_surface": 38.1,
  "temp_points": { "contact": null, "ir": [38.1, 35.9] },
  "gas_raw": 812,
  "pressure_raw": null,
  "acoustic_raw": null,
  "diag_phase": "P3",
  "load_target_a": 1.5,
  "age_ms": { "soc_pct": 640, "temp_ir_surface": 40 }
}
```

| 필드 | 값 | 뜻 |
|---|---|---|
| `diag_phase` | `null` \| `"P0"`…`"P6"` \| `"CAPACITY"` | 진단 단계. `null`이면 진단 중이 아니다 |
| `load_target_a` | `null` \| 실수 | 그 프레임에서 **지시한** 목표 전류. 실측은 `current_a`이며 둘의 차이가 부하 제어 오차다 |

**기존 규약 준수** — `current_a`·`power_w`는 부호를 살린다(양수=충전, 음수=방전). 보조배터리를 방전시키는 진단이므로 음수다. 프론트는 표시할 때만 `abs()`하고 방향은 라벨로 낸다. `age_ms`는 그 프레임에서 실측되지 않은 필드에만 넣는다.

### 6-2. `battery-events` — 새 토픽을 만들지 않는다

진단 단계 전환·완료·중단은 **기존 `battery-events` 토픽**에 싣는다. 진단은 raw 스트림 위의 주석이므로 토픽을 늘릴 이유가 없다.

이벤트 종류: `DIAG_STARTED`, `DIAG_PHASE_CHANGED`, `DIAG_COMPLETED`, `DIAG_ABORTED`(사유 포함). 음성 안내 대상이므로 에지 스피커 카테고리에 매핑한다(§7-3).

### 6-3. ⚠️ 진단 구간은 AI가 특별 취급해야 한다

계단 스윙은 **사람이 의도적으로 만든 전류 계단**이다. 정상 사용 패턴이 아니다.

| 항목 | 처리 |
|---|---|
| AI 학습셋 | `diag_phase != null` 프레임은 **정상패턴 학습에서 제외**한다. 넣으면 계단 파형을 정상으로 배워 실제 이상을 놓친다 |
| 이상점수 산출 | 계속 산출한다. 끊으면 진단 중 진짜 사고를 놓친다 |
| 이상 **알림 발송** | 진단 구간에서는 **억제**한다. 의도한 부하 변동에 매번 알림이 가면 알림이 무의미해진다 |
| Fail-Safe | **억제하지 않는다.** 가스·온도 하드 임계는 진단이든 아니든 즉시 차단한다 |

태그가 프레임에 실려 있으므로 나중에 판단을 바꿀 수 있다. 태그를 안 남기면 되돌릴 수 없다.

## 7. 기능 계약 (F21의 근거)

`docs/product_contract.md` F21의 원본이다. 형태 어휘를 쓰지 않는다 — 화면 개수·경계·그릇의 형태는 자유다.

### 7-1. 반드시 제공하는 정보

**① 식별 — 등록값**
- 배터리 라벨, `battery_id`, 배터리 종류, 제조사·모델(입력된 경우), 자산에 고정된 측정 모드
- 정격 용량(`capacityWh` 또는 `capacityMah`), 광고 정격 출력 전류(입력된 경우)

**② 현재 출력량 — 실측값**
- 무부하 출력전압, 현재 전압·전류·전력. **전류·전력은 절댓값과 방향 라벨로 보인다**(원시 부호를 그대로 노출하지 않는다)
- 상대 SOC와 그것이 **측정 시작을 100%로 본 상대값**이라는 사실
- 표면온도(두 존의 최댓값)와 각 값이 몇 ms 전 실측인지

**③ 열화 — 진단 결과**
- 진단 종류(빠른 진단 / 정밀 테스트), 신뢰도, 측정 시각, 잔량 힌트 단수
- 빠른 진단 3지표 — 레귤레이션 이탈 전류(상한값인지 여부 포함), 발열 기울기, 스펙 도달률, 열화 등급
- 정밀 테스트 — 뽑아낸 Wh, 기준선 Wh, 상대 SOH, 참고 절대 SOH와 그때 쓴 효율 가정, 방전 전류, 부분 결과 여부
- **아직 진단하지 않았다는 사실**, 기준선 수집 중이라는 사실, 산출 불가 항목(누적 사이클·잔존수명·내부저항)이 왜 비어 있는지
- 진단 진행 중이면 현재 단계, 목표 전류, 경과·남은 시간 추정

**④ 안전**
- 가스 상태, 릴레이 회로 상태, 최종 이상점수와 4등급
- 진단 중 알림이 억제된다는 사실

**⑤ 이력**
- 이 자산의 과거 진단 목록 — 시각, 종류, 신뢰도, 핵심 결과값

### 7-2. 반드시 가능한 동작

- 빠른 진단 실행 → **게이트** 7-3①
- 정밀 용량 테스트 실행 → **게이트** 7-3②
- 진행 중인 진단 중단
- 잔량 힌트 단수 입력·수정
- 과거 진단 이력 확인, 개별 결과 상세 확인
- 실시간 관제로 이동 → F4
- 이 배터리의 상세·이력으로 이동 → F7
- 릴레이 차단으로 이동 → T7

### 7-3. 게이트

**① 빠른 진단 실행**
- 활성 측정 세션이 있고, 그 배터리의 측정 모드가 2이고, 진행 중인 진단이 없어야 한다
- **부하를 걸어 의도적으로 발열시킨다는 사실**과 소요 시간을 알리고 확인을 받는다. 확인 없이 실행하는 경로는 없다

**② 정밀 용량 테스트 실행**
- ①의 모든 조건에 더해, **정격 용량이 등록돼 있어야 한다**(없으면 Wh를 비교할 분모가 없다)
- **완충 상태임을 확인받아야 한다.** 시작 SOC가 100%가 아니면 결과는 SOH가 아니다
- 소요 시간 추정을 알리고 확인을 받는다

중단에는 재인증·사유를 요구하지 않는다. 중단은 언제나 더 안전한 방향이므로 막을 이유가 없다. (릴레이 차단·복구는 별개이며 T7의 재인증·사유 게이트를 그대로 받는다.)

### 7-4. 불변

- **Fail-Safe는 진단보다 우선한다.** 가스·온도 임계가 걸리면 진단 절차와 무관하게 즉시 개입하며, 그때 **부하를 0A로 내린 다음** 릴레이를 차단한다. 순서가 뒤바뀌는 경로는 존재할 수 없다
- **열화 등급과 이상점수 등급을 합산하거나 같은 이름으로 부르지 않는다.** 열화는 수명, 이상점수는 열폭주 위험이며 서로 다른 축이다
- **완충 확인을 거치지 않은 정밀 테스트 결과를 SOH로 쓰는 경로는 존재할 수 없다.** 중단된 부분 결과도 마찬가지다
- **모드 2에서 누적 사이클·잔존수명·내부저항에 값이 채워지는 경로는 존재할 수 없다**(§5)
- 진단 중이라도 `battery-raw-metrics` 발행은 멈추지 않는다

### 7-5. 상태·예외

- 정격 용량이 등록되지 않아 정밀 테스트를 시작할 수 없을 때
- 진단 이력이 하나도 없을 때 / 기준선이 1회뿐이라 상대 SOH를 낼 수 없을 때
- 진단 중 안전 조건이 걸려 중단됐을 때 — 어느 조건인지 드러나야 한다
- 진단 중 다른 배터리가 연결되거나 배터리가 운영 차단되어 세션이 끝났을 때 — 진단은 무효다
- 진단기가 오프라인일 때
- 부하 제어 오차가 커서(`load_target_a`와 `current_a`의 차이) 결과를 신뢰할 수 없을 때

### 7-6. 음성 안내 매핑

에지 스피커 카테고리(`CLAUDE.md`)에 붙인다 — 진단 시작·완료는 **연결/측정**, 안전 중단은 **Fail-Safe/릴레이**, 부하 제어 오차는 **센서/디바이스 오류**.

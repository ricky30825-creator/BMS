# AI 배터리 열폭주 관제 시스템 — 관리자 유저 플로우

> 관리자 기능은 일반 사용자 기능과 분리된 `ADMIN` 권한 전용 흐름으로 설계한다. 관리자는 전체 사용자, 배터리, 디바이스, 이상 상태, 시스템 헬스, 감사 로그를 통합 관제한다.
> MVP에서는 HTML 프로토타입에 표시된 조회·상태 관리·비밀번호 재설정·공지사항 관리·감사 추적을 우선하고, 데이터 삭제·원격 Kill-Switch 제어·권한 세분화는 제외한다.

- **기준 문서**: `PLAN.md`, `docs/admin_feature_definition.md`
- **HTML 프로토타입 반영**: `설계 산출물/셀가드 프로토타입_v3.html` 기준 관리자 기능정의서는 `docs/admin_feature_definition.md`
- **참조 요구사항**: `SRS-WEB-004`, `SRS-WEB-030`, `SRS-WEB-036~039`, `SRS-WEB-047`, `SRS-WEB-053`, `SRS-WEB-061`
- **참조 기능**: `REQ-WEB-005`, `REQ-WEB-030`, `REQ-WEB-036~041`, `REQ-WEB-049`, `REQ-WEB-055`, `REQ-WEB-063`
- **PLAN 기준**: 관리자 MVP 상세 범위, 관리자 데이터 모델/API, MVP 제외 항목
- **반응형 기준**: 데스크톱 사이드바 · 태블릿 접힘 메뉴 · 모바일 하단 내비게이션

## 관리자 MVP 원칙

- 관리자는 일반 사용자와 별도 권한(`ADMIN`)으로 식별하고, `/admin/*` 화면과 API 접근 전 권한을 확인한다.
- 관리자 대시보드는 전체 운영 현황을 빠르게 판단하는 허브이며, 유저·배터리·감사 로그 화면으로 이동한다. 디바이스 상세 라우트는 현재 도달 불가 범위다.
- 계정 정지/해제와 모든 배터리 운영 상태 전환은 사유 입력과 확인을 거친다. 관리자 메모는 상태와 별도 저장하고 독립 감사 기록을 남기되 상태 변경 사유는 요구하지 않는다.
- 관리자 조작과 접근 실패는 `audit_log`에 남기고, 감사 로그는 수정·삭제할 수 없다.
- MVP에서는 사용자/배터리/디바이스/헬스/감사 조회와 제한적 상태 변경만 제공한다.

## 범위 구분

| 구분 | MVP 포함 | MVP 이후 |
|---|---|---|
| 유저 관리 | 목록/검색/상세, 활성·정지 상태 변경, 비밀번호 재설정, 사유 기록 | 계정 삭제, 관리자 권한 세분화 |
| 배터리 관리 | 전체 목록/상세, `NORMAL`/`WATCH`/`BLOCKED`, 관리자 메모 | 배터리 삭제, 소유자 변경, 측정 데이터 수정 |
| 통계 | 등록/측정/상태/모드/제조사/이상 이벤트 집계 | CSV/PDF 내보내기, 고급 분석 리포트 |
| 디바이스/헬스 | — (현재 v3 도달 불가) | 온라인·지연·오프라인, Kafka·Consumer·DB·AI 단순 헬스 |
| 감사 로그 | 로그인, 접근 실패, 상태 변경, 메모 변경 조회 | 감사 로그 CSV 내보내기, 외부 SIEM 연동 |
| 공지사항 관리 | 작성, 수정, 게시, 임시 저장, 보관/삭제 확인, 웹푸시·카카오 알림 발송 선택 | 문의/고객지원 관리 |
| 운영 설정/제어 | 조회 중심 | 원격 Kill-Switch, 백업/복구 |

| ID | 노드 | 유형 |
|---|---|---|
| a1 | 시작 | start |
| a2 | 로그인 화면 | main_page |
| a3 | 일반/소셜 로그인 | action |
| a4 | 역할 확인(RBAC) | gate |

## 핵심 관리자 여정

1. 로그인 → 역할 확인(RBAC) → 관리자 대시보드 진입
2. 관리자 대시보드 → 위험 배터리 확인 → 배터리 상세 → `WATCH` 또는 `BLOCKED` 변경 → 사유 입력 → 감사 로그 기록
3. 관리자 대시보드 → 오프라인 디바이스 확인 → 디바이스 상세 → 최근 수신 시각과 연결 세션 확인
4. 유저 관리 → 유저 검색/필터 → 유저 상세 → 계정 정지/해제 → 사유 입력 → 감사 로그 기록
5. 공지사항 관리 → 새 공지 작성/수정 → 임시 저장 또는 게시 → 필요 시 웹푸시·카카오 알림 발송
6. 감사 로그 → 기간/행위/대상 필터 → 상태 변경 이력 확인
7. 시스템 헬스 → Kafka/Consumer/DB/AI 단순 상태 확인 → 장애 의심 시 원격 진단 번들 기능은 MVP 이후로 연결

## 반응형 표시

- 데스크톱: 사이드바와 다중 컬럼 대시보드를 사용해 요약 카드, 분포 차트, 위험 목록, 디바이스 목록, 감사 로그를 동시에 확인한다.
- 태블릿: 접힘 메뉴와 2컬럼 카드 배치를 사용하고, 목록 필터는 상단 접이식 영역으로 제공한다.
- 모바일: 하단 내비게이션과 단일 컬럼 카드 흐름을 사용한다. 위험 배터리, 오프라인 디바이스, 접근 실패 로그를 우선 노출하고 긴 표는 카드 목록/상세 화면으로 전환한다.

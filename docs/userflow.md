# AI 배터리 열폭주 관제 시스템 — 일반 사용자 유저 플로우

> 사용자가 제공한 HTML 프로토타입에서 실제 확인되는 일반 사용자 화면과 이동 흐름을 기준으로 정리한다.
> 사용자는 로그인 후 디바이스와 배터리 자산을 확인하고, 배터리 연결 확인 모달을 거쳐 측정 세션을 시작한다.
> 실시간 대시보드에서는 센서값, 이상점수, 상태 등급, 알림을 확인하고 위험 상황에서는 확인 절차를 거쳐 릴레이 차단/복구로 이동한다.
> 관리자 전용 흐름은 `docs/admin_userflow.md`에서 별도로 관리한다.

- **기준 문서**: `PLAN.md`, `docs/feature_definition.md`
- **HTML 프로토타입 반영**: `web/AI_배터리_열폭주_관제_시스템_v2.html` 기준 일반 사용자 기능정의서는 `docs/feature_definition.md`
- **참조 기능**: `docs/feature_definition.md`의 `REQ-WEB-001~072`
- **섹션**: 인증/계정 · 디바이스/배터리 · 실시간 관제 · 이상 분석 · 알림/릴레이 · 추세/이벤트 · 공지사항 · 설정
- **반응형 기준**: 데스크톱 사이드바 · 태블릿 접힘 메뉴 · 모바일 하단 내비게이션

## 공통 반응형 UI 원칙

- 데스크톱은 사이드바와 다중 컬럼 레이아웃으로 요약 카드, 게이지, 차트, 이벤트 목록, 제어 상태를 한 화면에 최대한 유지한다.
- 태블릿은 접힘 메뉴와 2컬럼 카드/차트 배치를 기본으로 하며, 필터·기간 선택·제어 버튼은 터치 조작 가능한 크기를 유지한다.
- 모바일은 하단 내비게이션과 단일 컬럼 흐름을 사용한다. 긴급 경고, 현재 이상점수, 알림 확인, Kill-Switch 진입을 우선 노출한다.
- 표 중심 화면은 모바일에서 카드 목록/상세 화면으로 전환한다.
- WebSocket 연결이 끊기면 자동 재연결 상태를 표시하고, 실시간 데이터 갱신 중에도 카드 높이·차트 영역·상태 배지가 흔들리지 않도록 유지한다.
- 다크모드, 명도 대비, 키보드 탐색, 스크린리더 라벨을 고려한다.

| ID | 노드 | 유형 | 참조 |
|---|---|---|---|

| n11 | 배터리 자산관리 | main_page | `REQ-WEB-008` |
| n12 | 새 배터리 등록 | action | `SRS-WEB-006` |
| n13 | 저장된 배터리 선택 | action | `SRS-WEB-007` |
| n14 | 배터리 연결 확인 | gate | `REQ-WEB-039` |
| n15 | 배터리 상세/이력 | page | `REQ-WEB-010` |

**전이**
- 디바이스 관리 → 디바이스 등록/선택 → 배터리 자산관리
- 배터리 자산관리 → 새 배터리 등록 → `battery_id` 발급 → 배터리 자산관리
- 배터리 자산관리 → 저장된 배터리 선택 → 배터리 연결 확인 → 측정 세션 준비
- 배터리 자산관리 → 배터리 상세/이력 → 과거 세션·점수 추세 확인
- 보조배터리 물리 연결 감지 → 에지 스피커에서 연결 완료 음성 안내

**배터리 선택 기준**
- 사용자는 저장된 배터리를 수동 선택한다. 보조배터리는 자동 고유 식별이 어렵기 때문에 `battery_id`와 사람이 확인하는 배터리 이름을 함께 사용한다.
- HTML 프로토타입 기준으로 저장된 배터리 선택 후 "이 배터리를 측정하시겠습니까?" 연결 확인 모달을 거치며, 사용자는 "연결하고 측정" 또는 "먼저 상세 · 이력 보기"를 선택한다.
- 배터리의 `target_mode`는 자산에 고정되어 있으므로 재연결 시 별도 모드 선택 화면을 요구하지 않는다.
- 디바이스 음성 안내가 켜져 있으면 연결/측정 카테고리 이벤트에서 사전 생성된 로컬 음성파일을 재생한다.

**안전 제어 원칙**
- 차단 해제, 위험 제어처럼 안전에 직접 영향을 주는 조작은 권한 확인과 2차 확인을 요구한다.
- 위험 제어 승인 모달은 사유 입력, 재인증, 승인자 기록을 남긴다.
- Fail-Safe 긴급 차단은 사용자 조작보다 우선하며, 결과는 이벤트 이력과 감사 추적에 남긴다.
- 스피커 음성 안내는 현장 운영 보조 기능이며, 릴레이/Kill-Switch 판단에는 영향을 주지 않는다.

## 핵심 사용자 여정

1. 시작 → 로그인 화면 → 일반/소셜 로그인 → Better Auth 세션 생성/검증
2. 디바이스 관리 → 디바이스 등록/선택 → 배터리 자산관리
3. 보조배터리 물리 연결 감지 → 스피커 연결 안내 → 저장된 배터리 선택 또는 새 배터리 등록 → 배터리 연결 확인
4. 배터리 연결 확인 → 연결하고 측정 → 스피커 측정 시작 안내 → 실시간 대시보드
5. 실시간 대시보드 → 센서값·이상점수·상태등급 확인
6. 경고/위험 발생 → 인앱/카카오/스피커 안내 → 알림 확인(Ack) → XAI/이벤트 상세 확인 → SOP 확인
7. 필요 시 위험 제어 승인 모달 → 릴레이 차단 또는 복구
8. 배터리 상세/이력 → 추세 차트·이벤트 이력·데이터 내보내기
9. 설정 화면 → 알림 수신, 디바이스 음성 안내, 테마, 캘리브레이션 이력 관리

> 모바일에서는 5~7번 흐름을 가장 짧게 접근할 수 있도록 하단 내비게이션과 위험 상태 카드에 알림 확인, SOP, Kill-Switch 진입을 우선 배치한다.

## HTML 프로토타입 확인 흐름

- 랜딩 화면은 제품, 실시간 관제, AI 이상탐지, 문의 메뉴와 로그인, 무료로 시작, 관제 시작하기, 데모 영상 버튼을 제공한다. 메뉴 앵커와 데모 영상의 실제 목적지는 HTML만으로 명확하지 않아 기능정의서 비고에 `정의 필요`로 표시한다.
- 로그인 모달은 일반 로그인, Google 로그인, 회원가입, 계정 찾기, 관리자 계정 진입을 제공한다. 계정 찾기 화면은 비밀번호 재설정과 이메일 찾기 탭으로 전환된다.
- 앱 셸은 사이드바 접기/펼치기, 한/영 언어 전환, 알림 패널, 로그아웃, 일반 사용자 메뉴 이동을 제공한다.
- 배터리 관리 화면은 저장된 배터리 목록, 모드 필터, 새 배터리 등록, 배터리 정보 수정, 배터리 연결 확인, 배터리 상세/이력 이동을 제공한다.
- 이벤트 이력 화면은 검색, 상태 필터, 정렬 메뉴, 페이지 이동, 이벤트 상세, CSV/PDF 내보내기 모달을 제공한다.
- 설정 화면은 알림 수신, 계정, 테마 탭으로 나뉘며 알림 채널 토글, 비밀번호 재설정, 테마 선택, 센서 캘리브레이션 이력 확인이 포함된다.
- 디바이스 음성 안내 설정은 전체 공통 정책으로 적용되며, 에지는 사전 생성된 한국어 로컬 음성파일을 재생한다.

## 일반 사용자 범위에서 제외

- 관리자 계정 관리, 권한 부여/회수, 계정 정지/해제
- 관리자 통합 대시보드, 전체 배터리 운영 상태 변경, 관리자 감사 로그 탐색
- 공지 관리, 백업/복구 관리
- 시스템 헬스 상세 운영, AI 모델/드리프트 관리자 모니터링

> 위 항목은 `docs/admin_userflow.md` 또는 운영자 설계 문서에서 관리한다.

# 셀가드 랜딩 페이지 라이트 글래스 리디자인 설계

## 목적

`설계 산출물/셀가드 프로토타입_v3.html`의 **랜딩 페이지**를 라이트 톤 글래스모피즘으로 전면 재디자인한다. 유저플로우와 버튼 동작은 그대로 두고 시각 레이어만 교체한다.

이 프로토타입의 용도는 **실제 React 구현(`frontend/`)이 따라갈 디자인 기준**이다. 따라서 일회성 리스킨이 아니라 CSS 변수 토큰 체계로 설계한다.

## 배경 — 무엇이 문제였나

v3는 `2026-07-16-cellguard-commercial-redesign-design.md`에서 "신뢰 중심 · 정돈된 엔터프라이즈" 방향으로 구현된 결과물이다. 사용자가 꼽은 불만은 네 가지다: 흔한 SaaS처럼 보임, 관제 제품 같지 않음, 정보 밀도·가독성 부족, 완성도가 떨어져 보임.

코드 분석으로 확인한 원인:

- **차가운 Tailwind 기본 팔레트를 그대로 사용** — `#6B7280` 163회, `#E5E7EB` 143회, `#2563EB` 143회, `#F9FAFB` 107회 하드코딩. 어디서 본 듯한 인상의 진짜 원인은 레이아웃이 아니라 이 색이다.
- **radius 난립** — 7·8·9·10·11·12·14·16·20px이 혼재해 디테일이 거칠다.
- **색 역할 혼선** — 파랑·초록·주황·빨강이 장식과 상태 표시에 섞여 쓰여 위험 신호가 묻힌다.
- 배경 도트 패턴과 과한 그라데이션·그림자가 데모 인상을 준다.

## 범위

### 포함

- 랜딩 페이지 전 섹션의 시각 재설계: `NAV`, `HERO`, `HOW IT WORKS`, `PRODUCT PREVIEW`, `CTA`, `FOOTER`
- `STATS` 섹션 제거 (아래 "제거 항목" 참조)
- 랜딩에 적용할 CSS 변수 토큰 체계 정의

### 제외

- 앱 화면(로그인 이후 20개 라우트), 인증 화면(`signup`, `find`), 관리자 화면 — 다음 작업으로 미룬다
- 라우팅·상태·예시 데이터·버튼 동작 변경
- 요금제/가격표 — 셀가드에 가격 모델이 없다(`PLAN.md`·`docs/` 전체에 정의 없음, CTA도 "무료로 시작")
- 트러스트 배지 — 실제 고객사·인증이 없어 허위 신뢰 신호가 된다
- 프레임워크 전환, 파일 분리, 외부 라이브러리 추가
- 카피 문구 수정

### 제거 항목

`STATS` 섹션("TRUSTED IN THE FIELD / 숫자로 증명하는 신뢰")을 통째로 제거한다. `모니터링 중 배터리`, `평균 조기 경고 리드타임`, `관제 가동률 · 무중단 운영` 수치는 실제 운영 배포가 없는 상태에서 지어낸 값이며, 트러스트 배지를 빼기로 한 결정과 같은 이유로 유지할 수 없다.

제거 후 섹션 흐름: `NAV → HERO → HOW IT WORKS → PRODUCT PREVIEW → CTA → FOOTER`

## 시각 체계

### 색 토큰

전부 CSS 변수로 정의해 이후 라이트/다크 확장과 React 이식이 가능하게 한다.

**뉴트럴 — 웜 슬레이트 (차별화의 핵심)**

Tailwind 기본 회색의 차가운 톤을 버리고 웜 뉴트럴로 전환한다. 사용자가 제시한 로고 이미지의 배경이 따뜻한 오프화이트인 것과도 맞는다. 같은 브랜드 파랑을 써도 인상이 달라지는 지점이다.

| 토큰 | 값 | 용도 |
|---|---|---|
| `--bg-base` | `#F7F6F4` | 페이지 배경 (기존 `#F9FAFB` 대체, 도트 패턴 제거) |
| `--surface` | `#FFFFFF` | 불투명 표면 |
| `--ink` | `#141719` | 본문·제목 |
| `--ink-2` | `#5A6068` | 보조 텍스트 |
| `--ink-3` | `#8B9099` | 메타·라벨 |
| `--border` | `rgba(20,23,25,.08)` | 구획선 |

**브랜드 — 로고에서 추출**

| 토큰 | 값 | 용도 |
|---|---|---|
| `--brand` | `#2563EB` | 주요 행동, 선택 상태 |
| `--brand-2` | `#3B82F6` | 그라데이션 종점 |
| `--brand-grad` | `linear-gradient(135deg,#3B82F6,#2563EB)` | CTA, 로고 마크 |

로고는 기존 자산을 유지한다: 파란 라운드 스퀘어(`#2563EB`, `rx=34`) + 흰 번개 볼트 + "셀가드" 워드마크. 번들 안에 이미 존재한다.

**상태 — 장식 재사용 금지**

`CLAUDE.md`의 4단계 위험 등급에 1:1 매핑한다. 이 색은 상태 표시 외 어디에도 쓰지 않는다.

| 등급 | 이상점수 | 토큰 | 값 |
|---|---|---|---|
| 정상 | 0.0–0.3 | `--ok` | `#16A34A` |
| 주의 | 0.3–0.6 | `--warn` | `#D97706` |
| 경고 | 0.6–0.8 | `--alert` | `#EA580C` |
| 위험 | 0.8–1.0 | `--danger` | `#DC2626` |

### 글래스

라이트 배경 위 글래스는 그냥 얹으면 탁해진다. 배경에 크게 블러된 브랜드 컬러 블룸을 깔고 그 위에서 유리가 굴절되게 한다.

- **배경 블룸**: `radial-gradient` 2~3개를 블루/인디고 계열 저채도로 배치. 섹션마다 위치를 달리해 스크롤 시 유리 표정이 바뀌게 한다.
- **글래스 카드**:
  - `background: rgba(255,255,255,.55)`
  - `backdrop-filter: blur(20px) saturate(1.4)` (+ `-webkit-` 접두사)
  - 안쪽 하이라이트: `border: 1px solid rgba(255,255,255,.7)`
  - 바깥 정의선: `box-shadow: 0 0 0 1px rgba(15,23,42,.06), 0 8px 32px rgba(15,23,42,.06)`
- **대비**: 글래스 위 모든 텍스트는 `--ink`(`#141719`)를 기본으로 4.5:1 이상을 확보한다. 블룸이 진한 영역 위에는 글래스 불투명도를 올린다.
- **폴백**: `backdrop-filter` 미지원 시 `@supports not (backdrop-filter: blur(1px))`로 불투명 흰색(`rgba(255,255,255,.92)`)을 준다.

### 형태와 간격

| 항목 | 규칙 |
|---|---|
| radius | `12px`(카드) / `20px`(대형 패널) / `999px`(필·배지) 3단계로 통일 |
| 간격 | 8px 배수 |
| 섹션 패딩 | 데스크톱 120px / 태블릿 88px / 모바일 64px |
| 그림자 | 글래스 정의용 외에는 사용하지 않음. 기존 `0 50px 90px -30px` 류의 과한 그림자 제거 |

기존 배경 도트 패턴(`radial-gradient(circle,#EEF0F3 1px,transparent 1px)`)은 제거한다.

### 타이포그래피

Pretendard를 유지한다(번들에 woff2/woff 내장). 5단계 위계로 좁힌다.

| 역할 | 크기/행간 | 자간 | 굵기 |
|---|---|---|---|
| Display (h1) | 56/1.05 | -0.03em | 800 |
| Section (h2) | 36/1.2 | -0.02em | 700 |
| Card (h3) | 20/1.4 | -0.01em | 700 |
| Body | 16/1.6 | 0 | 400–500 |
| Meta | 13/1.5 | 0 | 500 |
| Label | 11/1.4 | 0.12em | 700, uppercase |

모든 수치 표시에 `font-variant-numeric: tabular-nums`를 적용해 실시간 갱신 시 폭이 흔들리지 않게 한다.

## 섹션별 설계

기존 카피와 버튼 동작은 유지한다. 아래는 시각 처리만 기술한다.

**NAV** — 스티키 글래스 바. 로고 마크 + "셀가드" 워드마크, 중앙 메뉴(제품 / 실시간 관제 / AI 이상탐지 / 문의), 우측 `로그인`(고스트) + `무료로 시작`(브랜드 그라데이션 필). 스크롤 시 블러와 보더가 짙어진다.

**HERO** — 2컬럼. 좌측은 상태 배지("AI 열폭주 예측 · 실시간", 라이브 도트), h1 "먼저 알고, / 먼저 막는다.", 설명, CTA 2개(`무료로 시작하기` / `라이브 데모 보기`), 하단 센서 칩(온도·전압 등). 우측은 **실시간 데이터 시각화 글래스 카드** — 현재 이상점수 게이지(상태색), `PACK-001 · NCM-72Ah` 식별, 라이브 스파크라인. 배경 블룸이 카드 뒤에서 굴절된다.

**HOW IT WORKS** — 3단계 카드(1초 단위 실시간 수집 / AI 열폭주 조기 경고 / 위험 시 자동 릴레이 차단). 기존 다크 섹션이었으나 라이트 글래스로 전환한다. 각 카드에 Lucide 계열 SVG 아이콘을 쓴다. **이모지를 아이콘으로 쓰지 않는다.**

**PRODUCT PREVIEW** — 대시보드 미리보기를 글래스 프레임에 담는다. 실시간 온도 추세, AI 열폭주 예측 리스크(기여도 포함), 이상점수 24h 추세, 임계값 초과 → 릴레이 차단 흐름, 최근 이상 이벤트. 장식보다 실제 관제 정보 밀도를 보여준다.

**CTA** — 기존 다크 섹션이었으나 브랜드 그라데이션 블룸 위 글래스 패널로 전환한다. "방심하는 그 순간, 셀가드는 / 이 순간을 막습니다." + `무료로 시작하기`.

**FOOTER** — 웜 뉴트럴 배경, 최소 구성.

## 모션

- 지속 시간 150–300ms, 의미 전달용으로만 사용한다.
- 스크롤 리빌은 섹션 진입 시 opacity + y 이동 스태거(each 0.06s).
- 히어로 스파크라인과 라이브 도트는 상시 동작한다.
- `transform`/`opacity`만 애니메이션한다. `width`/`height`는 쓰지 않는다.
- `@media (prefers-reduced-motion: reduce)`에서 모든 장식 모션을 끈다.

## 반응형

기존 반응형 동작을 보존한다. 브레이크포인트 375 / 768 / 1024 / 1440에서 확인한다.

- 860px 이하: 히어로 2컬럼 → 1컬럼, 다중 컬럼 그리드 → 2컬럼
- 560px 이하: 전부 1컬럼
- 터치 대상 최소 44×44px, 간격 8px 이상
- 가로 스크롤이 생기지 않아야 한다

## 구현 방식

대상 파일은 `설계 산출물/셀가드 프로토타입_v3.html`이다. 구조상 주의할 점:

- 23MB 번들 파일이며 실제 마크업은 **210번 줄의 JSON 문자열**(327KB)에 들어 있다. 202번 줄은 base64 자산 매니페스트(22MB)다.
- 마크업은 `x-dc` 템플릿이고 스타일이 전부 인라인이다. 랜딩 구간은 디코딩 기준 약 118~345줄이다.
- 따라서 작업은 `210번 줄 디코딩 → 랜딩 구간 수정 → 재인코딩 → 원위치` 순으로 한다. JSON 이스케이프(`/` 등)가 깨지지 않아야 한다.
- 토큰은 `<helmet>` 안 `<style>` 블록에 CSS 변수로 정의하고, 인라인 스타일에서 `var(--token)`으로 참조한다. 랜딩 구간의 하드코딩 색상을 우선 교체한다.

수정 전 원본을 `설계 산출물/아카이브/` 아래에 백업한다.

## 검증

- 로컬 HTTP 서버로 파일을 열어(`file://`는 확장이 차단) 랜딩을 육안 확인한다.
- 기존 클릭 동작이 유지되는지 확인한다: `로그인`·`무료로 시작`·`무료로 시작하기`·`라이브 데모 보기` → `openLogin` 모달, 이후 앱 라우트 진입.
- 글래스 카드 위 텍스트 대비가 4.5:1 이상인지 확인한다.
- 375/768/1024/1440에서 가로 스크롤이 없는지 확인한다.
- HTML 구조와 JavaScript가 손상되지 않았는지 확인한다(디코딩 → 파싱 → 재인코딩 왕복 검증).

## 성공 기준

- 첫 화면이 Tailwind 기본 팔레트의 범용 SaaS가 아니라 셀가드 고유의 제품으로 읽힌다.
- 웜 뉴트럴 베이스 위에서 글래스가 탁하지 않고 선명하게 보인다.
- radius·간격·타이포가 정의된 토큰 안에서만 쓰여 디테일이 정돈돼 보인다.
- 상태색이 위험 표시에만 쓰여, 정상 화면은 차분하고 위험은 즉시 눈에 띈다.
- 지어낸 신뢰 수치나 존재하지 않는 요금제가 화면에 없다.
- 기존 유저플로우와 버튼 동작이 그대로 작동한다.

## 미결 사항

히어로 카피 "1초 단위 실시간 수집"과 `HOW IT WORKS` 1단계 설명이 `CLAUDE.md`의 실제 스펙(**100ms 수집 주기**)과 어긋난다. 이번 범위는 디자인이므로 건드리지 않는다. 카피 수정 여부는 별도로 결정한다.

# 셀가드 앱 화면 라이트 글래스 리디자인 설계

## 목적

`설계 산출물/셀가드 프로토타입_v3.html`의 **앱 화면 전체**(인증 2 + 일반 사용자 11 + 관리자 6 + 모달 17 + 공유 셸)를 랜딩에서 확립한 웜 뉴트럴 라이트 글래스 체계로 재디자인한다. 유저플로우·버튼 동작·라우팅은 유지하되, 관제 화면 특유의 정보 밀도와 상태 정확성을 반영한다.

이 프로토타입은 실제 React 구현(`frontend/`)이 따라갈 디자인 기준이다. 따라서 랜딩과 동일하게 CSS 변수 토큰 체계로 설계하고, 규칙을 린터로 기계 검증한다.

## 실행 모델 고려사항 (중요)

**이 설계의 구현은 Sonnet 5 모델이 수행한다.** Sonnet 5는 Opus보다 추론 여력이 작으므로, 플랜과 스펙은 **추측 여지를 남기지 않아야** 한다. 이 문서와 후속 플랜은 다음을 지킨다:

- **정확한 위치**: "게이지 근처"가 아니라 "디코딩 마크업 L1547–1549"처럼 줄 번호로 지정한다. 줄 번호는 편집 과정에서 바뀌므로, 플랜은 줄 번호와 함께 **고유한 앵커 문자열**(그 줄에만 있는 코드 조각)을 반드시 병기한다.
- **완전한 before/after**: 바꿀 코드의 전체 원문과 교체문을 그대로 싣는다. "적절히 토큰화" 같은 지시는 금지한다.
- **함정 명시**: 아래 "구현 함정" 절의 항목들을 플랜의 해당 태스크에 그대로 복사한다. 특히 SVG 속성의 `var()` 미작동, `</` 이스케이프, 번들 손 편집 금지는 매 태스크에서 반복 경고한다.
- **작은 단계**: 한 태스크는 한 화면(또는 한 컴포넌트)으로 제한한다. 그룹을 통째로 한 태스크에 넣지 않는다.
- **기계 검증 우선**: 각 태스크는 린터 통과 + 브라우저 렌더 확인으로 끝난다. 사람 판단(육안 디자인 취향)에 의존하는 합격 기준을 최소화한다.
- **판단 지점 사전 제거**: 레이아웃·색·간격에 선택지가 생기면 스펙/플랜이 미리 하나로 확정한다. 실행자가 결정하게 두지 않는다.

## 구현 함정 (플랜의 모든 관련 태스크에 복사할 것)

1. **SVG 속성에는 `var()`가 작동하지 않는다.** `stroke="{{ scoreColor }}"`, `fill="{{ x }}"`처럼 값이 SVG presentation **속성**에 직접 들어가는 경우, `var(--ok)` 같은 CSS 변수는 무시된다(색이 사라진다). 이 경로의 값은 **hex 문자열을 유지**하되 상태 토큰과 **동일한 값**으로 맞춘다(`--ok`=`#16A34A` 등). 토큰화가 꼭 필요하면 속성 대신 `style="stroke:var(--ok)"`로 옮겨야 하지만, 이번 범위에서는 hex 유지를 기본으로 한다.
2. **번들을 손으로 편집하지 않는다.** 실제 마크업은 23MB 파일의 210번 줄 JSON 문자열 안에 있다. 반드시 `python3 tools/bundle_io.py unpack/pack`으로만 편집한다. 202번 줄은 22MB base64 자산 매니페스트이므로 절대 건드리지 않는다.
3. **`</` 이스케이프는 `bundle_io.pack`이 처리한다.** pack은 마크업 내 `</`를 `<\/`로 이스케이프해 브라우저 HTML 파서가 템플릿 스크립트를 조기 종료하는 것을 막는다. 이 처리를 우회하거나 직접 파일에 쓰지 않는다.
4. **왕복 검증은 브라우저 렌더를 보장하지 않는다.** `unpack`은 readlines 기반이라 HTML 파서 경로를 타지 않는다. 그룹마다 로컬 HTTP 서버(`file://`는 확장이 차단)로 열어 육안 + 콘솔 에러를 확인해야 한다.
5. **대상 파일은 git 추적 대상이 아니다**(`.gitignore`의 `설계 산출물/`). 되돌리기가 불가능하므로 각 그룹 시작 전 백업한다. 커밋은 도구/문서만 이동하는 마커다.

## 배경 — 랜딩에서 이어받는 것

랜딩 리디자인(`2026-07-17-cellguard-landing-light-glass-design.md`, main에 병합됨)에서 다음이 완성됐다:

- **토큰 20개**: 뉴트럴(웜 슬레이트) 6 / 브랜드 3 / 상태 4 / 글래스 4 / 형태 3 — `<helmet>` `<style>` 블록에 정의됨.
- **편집 도구** `tools/bundle_io.py`: 23MB 번들의 210번 줄 JSON 마크업을 안전하게 unpack/pack/backup. `</` 이스케이프 버그 수정 완료(브라우저 HTML 파서 조기 종료 방지).
- **토큰 린터** `tools/landing_lint.py`: 차가운 Tailwind 색·비허용 radius·도트 패턴·이모지·지어낸 지표를 기계 검사. 현재 검사 범위는 랜딩 구간(`LANDING`~`SIGNUP` 마커)뿐이다.

앱 화면은 이 토큰과 도구를 **재사용**한다. 새 디자인 방향을 정하지 않는다.

## 시각 체계

### 크롬 vs 콘텐츠 — 절제적 글래스

관제 화면은 정보 밀도가 높고 운영자가 오래 응시한다. 글래스(반투명+블러)를 본문에 남발하면 가독성이 떨어지고 `backdrop-filter` 다수 중첩은 성능을 해친다. 따라서 **글래스는 강조 면(크롬)에만** 쓴다.

| 영역 | 처리 |
|---|---|
| 사이드바 | **라이트 웜 서피스** — 콘텐츠(`--bg-base`)보다 살짝 진한 웜 뉴트럴 + 얇은 보더. 선택 메뉴만 브랜드 강조. 글래스 아님. |
| 상단바 | **라이트 글래스 스티키** — 랜딩 NAV와 통일. `.cg-glass`. 스크롤 시 콘텐츠가 살짝 비침. |
| 모달 | 글래스 오버레이 + `.cg-glass` 패널. |
| 카드 헤더 | 필요 시 글래스 강조 가능. |
| 본문(카드·테이블·차트 콘텐츠) | **불투명 서피스** — 흰색 + 얇은 보더. 글래스 금지. |

### 사이드바 토큰 (신규 — 구체값)

콘텐츠와 구분되는 라이트 앵커. `CLAUDE.md`의 "네이비는 좌측 내비에 한정" 원칙을 라이트 방향으로 재해석한다(다크 네이비 대신 웜 서피스로 구분). `:root` 블록에 추가한다:

```css
--nav-bg:#EFEDE7;        /* --bg-base(#F7F6F4)보다 한 톤 진한 웜 뉴트럴 — 콘텐츠와 구분 */
--nav-border:rgba(20,23,25,.08);  /* = --border 와 동일 값. 콘텐츠 경계선 */
--nav-ink:#5A6068;       /* = --ink-2. 기본 메뉴 텍스트/아이콘 */
--nav-ink-active:#FFFFFF;/* 선택 메뉴(브랜드 배경 위) 텍스트 */
```

- **현재 사이드바(디코딩 마크업 L459)** 앵커: `background:linear-gradient(180deg,#161C2C,#11151F)` — 이 다크 네이비 그라데이션을 `background:var(--nav-bg)`로 교체하고, 우측 보더를 `--nav-border`로 준다.
- 워드마크(L462, `color:#fff`)와 메뉴 텍스트를 `--nav-ink` 계열로 바꾼다. 로고 마크(L461, 브랜드 그라데이션)는 유지한다.
- **선택 메뉴 상태**: `background:var(--brand-grad); color:var(--nav-ink-active);` + `--r-card`. 비선택은 `color:var(--nav-ink)`, hover 시 `background:rgba(20,23,25,.04)`.
- 배지(L470, `#EA580C`)는 상태 표시이므로 `--alert` 값 유지.

### 공통 서피스 클래스 (신규)

본문 카드용 불투명 서피스. `.cg-glass` 옆에 정의한다:

```css
.cg-surface{
  background:var(--surface);
  border:1px solid var(--border);
  border-radius:var(--r-card);
}
```

본문 카드·테이블 컨테이너·차트 패널은 `.cg-glass`가 아니라 `.cg-surface`를 쓴다(절제적 글래스 원칙).

### 밀도 (관제용, 랜딩보다 조밀)

- 간격 스케일을 축소한다: 8 / 12 / 16px 중심(랜딩은 큰 여백).
- 카드 패딩, 테이블 행 높이, 폼 필드 간격을 관제 밀도로 통일.
- radius는 랜딩과 동일한 3단계 유지: `--r-card 12px` / `--r-panel 20px` / `--r-pill 999px`.

### 공통 컴포넌트

먼저 확정하면 25화면이 재사용한다.

- **카드**: 불투명 흰 서피스(`--surface`) + `--border` + `--r-card`. `.cg-surface` 클래스로 표준화.
- **테이블**: 행 구분선(`--border`), 헤더 대비, 밀도 개선. **위험 행만** 낮은 채도 상태 배경(예: `rgba(220,38,38,.06)`). 모바일에서 카드 목록으로 전환(`CLAUDE.md` 원칙).
- **게이지·상태 배지**: 값에 따라 4단계 상태색. `tabular-nums`.
- **차트**: 추세선은 상태색, 면적은 저알파. 격자선 `--border`.
- **배지·필터·탭**: 기본/보조/위험 구분, 선택 상태는 브랜드로 한정.
- **모달 골격**: 배경 차단 + `.cg-glass` 패널 + 제목/영향 설명/행동 버튼 우선순위. 17개 모달이 공유.

### 타이포그래피

Pretendard 유지. 랜딩의 5단계 위계를 관제 밀도에 맞게 적용. 모든 수치에 `font-variant-numeric:tabular-nums`.

## 상태색 4단계 정합 (로직 수정)

### 근거

현재 게이지 계산 JS는 3단계만 구현한다: `score>=70`→위험, `score>=40`→주의, else 정상. 그런데 `CLAUDE.md`의 시스템 스펙은 4단계다:

| 등급 | 이상점수(0–1) | 0–100 환산 | 토큰 |
|---|---|---|---|
| 정상 | 0.0–0.3 | 0–30 | `--ok` |
| 주의 | 0.3–0.6 | 30–60 | `--warn` |
| 경고 | 0.6–0.8 | 60–80 | `--alert` |
| 위험 | 0.8–1.0 | 80–100 | `--danger` |

현재 로직은 "경고" 등급을 아예 생성하지 않고, "주의"에 경고색(`--alert`)을 잘못 물린다. 관제 화면은 상태 표시가 시스템 전반에 깔려 있어 이 불일치가 곳곳에 드러나므로, 리디자인에서 함께 바로잡는다(사용자 결정).

### 변경 대상 (정확한 위치 — 줄 번호 + 앵커 문자열)

줄 번호는 편집으로 이동하므로 앵커 문자열로 찾는다. score는 0–100 스케일이다(예시값 82/18/33/58 확인).

**(a) 게이지 계산 — 디코딩 마크업 L1547–1549**

앵커: `let scoreColor = '#16A34A', scoreLabel = '정상';`

원문(before):
```js
let scoreColor = '#16A34A', scoreLabel = '정상';
if (score >= 70) { scoreColor = '#DC2626'; scoreLabel = '위험'; }
else if (score >= 40) { scoreColor = '#EA580C'; scoreLabel = '주의'; }
```

교체(after):
```js
let scoreColor = '#16A34A', scoreLabel = '정상';
if (score >= 80) { scoreColor = '#DC2626'; scoreLabel = '위험'; }
else if (score >= 60) { scoreColor = '#EA580C'; scoreLabel = '경고'; }
else if (score >= 30) { scoreColor = '#D97706'; scoreLabel = '주의'; }
```

**(b) 예측 리스크 계산 — 디코딩 마크업 L1826**

앵커: `const riskColor = score >= 70 ? '#DC2626'`

원문(before):
```js
const riskColor = score >= 70 ? '#DC2626' : score >= 40 ? '#EA580C' : '#2563EB';
```

교체(after) — 4단계 등급색으로 정합. 정상은 브랜드 파랑이 아니라 상태 초록으로:
```js
const riskColor = score >= 80 ? '#DC2626' : score >= 60 ? '#EA580C' : score >= 30 ? '#D97706' : '#16A34A';
```

이 줄 근처의 `riskBg`/`riskLabel` 계산이 있으면 같은 4단계 임계값(30/60/80)과 라벨(정상/주의/경고/위험)으로 통일한다. 플랜은 해당 계산부의 원문을 확인해 before/after를 확정한다.

**(c) 이벤트 목록 tone 색 — 디코딩 마크업 L2113 (확인 + 정합)**

앵커: `scoreColor: e.tone === '정상' ? '#16A34A'`

이 계산은 이미 4개 tone(정상/주의/경고/위험)을 다루며 색이 `#16A34A`/`#D97706`/`#EA580C`/`#DC2626`로 상태 토큰과 이미 일치한다. 데이터 없음(`e.score === '—'`)일 때 쓰는 `#6B7280`은 금지색이므로 `#8B9099`(=`--ink-3` 값)로 교체한다. 그 외 tone 색은 변경 불필요 — 확인만 한다.

### 색 값 규칙 (구현 함정 1 재확인)

위 hex 값들은 상태 토큰과 **동일한 값**이다: `#16A34A`=`--ok`, `#D97706`=`--warn`, `#EA580C`=`--alert`, `#DC2626`=`--danger`. 이 값들은 `{{ scoreColor }}` 등으로 SVG의 `stroke`/`fill` **속성**에 직접 들어가므로 `var()`가 아니라 **hex 문자열을 유지**한다(구현 함정 1). 정합의 목적은 4단계 등급을 올바르게 산출하는 것이지 이 JS를 토큰화하는 것이 아니다.

- 이 변경은 카피(라벨 텍스트)가 아니라 등급 산출 로직이며, "경고" 라벨은 원래 시스템 스펙에 존재하는 등급이다.
- 검증: score를 25/45/70/90으로 바꿔가며 네 등급(정상/주의/경고/위험)이 각각 초록/주황/오렌지/빨강 + 올바른 라벨로 렌더되는지 브라우저에서 확인한다.

## 반응형

`CLAUDE.md` 원칙을 따른다.

- 데스크톱: 좌측 사이드바 + 다중 컬럼 관제.
- 태블릿: 사이드바 접힘 + 2컬럼.
- 모바일: **하단 탭바** + 단일 컬럼 카드 흐름. 긴급 경고·현재 이상점수·알림·Kill-Switch 진입을 우선 노출. 표는 카드 목록/상세로 전환.
- 브레이크포인트 375 / 768 / 1024 / 1440. 가로 스크롤 없음. 터치 대상 ≥44px.

## 도구·검증

### 린터 확장

`landing_lint.py`를 확장한다(테스트와 함께 TDD):

- **검사 범위 확대**: 현재 랜딩 구간(`LANDING`~`SIGNUP`)만 검사한다. 앱 구간(`SIGNUP`~문서 끝)까지 포함한다. 함수 분리로 구간별 검사가 가능하게 한다.
- **본문 글래스 오남용 규칙 추가**: 절제적 글래스 원칙을 기계 강제한다. `backdrop-filter`/`.cg-glass`가 허용 컨텍스트(사이드바·상단바·모달·카드 헤더) 밖의 본문 콘텐츠에 쓰이면 위반으로 보고한다. 구현 방식은 플랜에서 정한다(허용 목록 기반).
- 기존 규칙(차가운 색·radius·이모지·지어낸 지표)은 앱 구간에도 그대로 적용한다.

### 검증

- 번들 왕복은 `bundle_io`로만 한다(손 편집 금지). 편집 전 백업.
- 각 그룹 작업 후 린터 통과 확인.
- **브라우저 렌더 확인은 필수다.** 랜딩에서 `</` 이스케이프 버그가 브라우저에서만 드러났다 — 왕복 검증(readlines 기반)이 HTML 파서 경로를 안 타기 때문이다. 그룹마다 로컬 서버로 열어 육안 확인하고, 콘솔 에러가 없는지 본다.
- 상태색 4단계는 score 예시값을 바꿔가며 네 등급이 모두 올바른 색·라벨로 렌더되는지 확인한다.

## 구현 단계 (플랜 그룹 예고)

전체를 한 플랜에 넣으면 태스크가 40개를 넘어 거대해지므로, 플랜을 그룹으로 나눈다. 각 그룹은 독립적으로 린터 통과 + 브라우저 확인이 가능한 단위다.

1. **기반**: 사이드바·밀도 토큰 추가 + 린터 확장(범위 + 본문 글래스 규칙) + 상태색 4단계 로직 정합
2. **공유 셸**: 사이드바(라이트 웜 서피스) + 상단바(라이트 글래스 스티키)
3. **공통 컴포넌트**: 카드·테이블·게이지·차트·배지·필터·탭·모달 골격
4. **일반 사용자 화면** (11): 대시보드부터 설정까지
5. **관리자 화면** (6)
6. **모달** (17)
7. **인증**(2) + 반응형(모바일 하단 탭바 + 카드 전환) + 최종 리뷰

## 성공 기준

- 사이드바·상단바·본문·모달이 하나의 웜 라이트 체계로 읽히고, 랜딩과 일관된다.
- 글래스가 크롬(사이드바·상단바·모달·카드 헤더)에만 있고 본문은 불투명 서피스라 관제 가독성이 확보된다. 린터가 이를 강제한다.
- 정상 화면은 차분하고, 위험 상태만 상태색으로 눈에 띈다. 네 등급(정상/주의/경고/위험)이 모두 올바르게 노출된다.
- 표는 모바일에서 카드로 전환되고, 하단 탭바로 긴급 기능에 접근된다.
- 기존 유저플로우·버튼 동작·라우팅이 그대로 작동한다.
- 어느 화면을 브라우저에서 열어도 언패킹/콘솔 에러가 없다.
